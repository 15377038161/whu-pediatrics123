## 可复用命令

在仓库根目录使用已有Python环境及`pnpm`：

```powershell
# 文件级盘点：只读 knowledge/，输出路径必须被 Git 忽略。
python scripts/audit-case-library.py

# 复现旧分段、匹配原件指纹并生成私有候选：不写运行病例、不入库、不发布。
# 已应用病例保留原审核/应用日志，不用再次重生成替代历史审阅记录。
python scripts/audit-case-sections.py

# 预检候选；明确执行本地落版时加 --apply。先备份，逐例持久化日志，可断点重入。
pnpm exec tsx scripts/apply-case-section-candidates.ts

# 合成输入的章节边界回归：不使用患者材料。
python -m unittest discover -s scripts -p test_case_source_sections.py -v

# 相关既有领域回归。
pnpm exec tsx --test tests/teacher-case-source.test.ts tests/teacher-case-resources.test.ts tests/case-version-select.test.ts tests/patient-appearance.test.ts
```

盘点脚本输出`scope.json`、`materials.jsonl`、`inventory-summary.json`及`summary.md`。`scope.json`是本地盘点投影；现有病例就绪账本仍为`docs/case-readiness-register.json`。同一材料指纹不变时保留人工填写的用途与审核记录；事实文件变化时保留审阅历史并要求重新核对。Git基线在扫描中变化则不提交本轮最终账本。

分段工具输出`section-audit.json/.md`及`section-candidates/`。候选只覆盖能够复现旧字段、匹配源文件指纹且原文行不丢失的内容；旧生成器来源取自账本记录的Git基线，不执行历史文件的顶层逻辑。DOCX原文不一致时阻止该候选。候选文件按UTF-8原始字节写入，避免Windows自动CRLF转换造成内容与登记哈希不一致。使用受控应用工具，不直接复制候选或运行全量生成器；新版本必须区别于旧版。
