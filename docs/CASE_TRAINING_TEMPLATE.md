# 病例导入与接诊工作台通用约定

本轮首例是后续全部病例的导入、调用和验收模板。适用于独立来源、别名/亚型入口；目录以当前有效入口为准，已退役记录不重新上架凑数量。来源不足必须保留待办，不能复制另一例冒充。

## 本次反馈与实现

| 反馈 | 通用行为 |
|---|---|
| 器材直接指出正确部位 | 所有器材共用中性解剖部位，进行中学生响应不下发器材—正确部位答案映射 |
| 站立/仰卧未区分 | 前端传入实际选择，后台按既有规则及可选examRules.postures核验，错误体位不释放体征 |
| 下一步按钮突兀 | 工作台阶段操作条统一放置，删除查体/检查内容底部的重复跨阶段按钮 |
| 辅助检查页面单薄 | 申请区与逐项结果区分开，图片跟随实际检查事件 |
| 缺病历书写 | 顶部增加病历视图，复用note_drafts/note_submissions及原API，不新增业务阶段枚举或平行存储 |
| 无关人物占画面 | 接诊/交流/沟通/查体展示人物，检查/诊断/处置/书写使用更宽编辑区 |
| 提示不随进度 | 使用实际已采集话题、准备和提交记录，不读标准答案生成提示 |
| 内容过长 | 工作台固定视口高度，聊天、记录与编辑区独立滚动；保留完整证据而非只展示末8条 |

## 模板与版本

`docs/templates/case-runtime.template.json`是可解析的空白结构；需填写目录内真实来源ID及原材料后才能导入。老师按`docs/实施方案/老师填写版_儿科病例资料简明模板.md`提供事实、体位与对应来源，技术人员转换字段，不要求老师填写代码ID。

可选`examRules`用于教师确认的结构化查体项，每项包含toolId、bodyPartId、label、result、postures、sourceLocator；允许体位为standing/supine。方法和部位必须在固定枚举中，同一方法+部位不重复；requires仍由服务端保留手卫生前置。字段缺省沿用原始文字抽取及既有体位规则，不虚构额外结果。结构化规则结果及来源定位保存在私有binding_config，不进入学生facts载荷。规则、体位、结果或来源定位修订均换内容版本；未提供此字段的旧包版本保持不变。

现有testMedia、examMedia、testRelease继续按稳定项目ID绑定。共享来源通过既有teacher-case-links解析；活动版本按入口配置，旧会话保持绑定。标准病历仅服务端/教师可读，不传入书写编辑器、不自动填入学生病历。

## 参数化准备与验收

```powershell
# 全目录只读盘点：输出结构、绑定、来源及版本状态，不写库、不激活、不输出原文
pnpm exec tsx scripts/audit-case-training-template.ts --out output/template-audit-新批次.json
# 任一真实来源制作私有包（目录须为新目录，knowledge为受控原数据目录）
pnpm exec tsx scripts/build-pilot-case-bundle.ts teacher-已核实来源ID output/新病例包
# 同一包可以分别验证主入口和共享来源入口，仍需分别做真实页面验收
pnpm exec tsx scripts/verify-pilot-case-bundle.ts output/新病例包 --entry case-公开入口ID
# 既有教师身份导入任一已核实的单例包，凭据不得进入CLI参数值或聊天
pnpm exec tsx scripts/import-controlled-case.ts --cred-file output/受控凭据文件.json --bundle output/新病例包
```

调用过程：私有JSON校验→版本与附件核对→对象存储实际回读→服务端`controlled-case-registry.ts`登记sourceId/version/fileId/SHA256→真实教师配对导入回查→按入口活动版本启用→新会话绑定回查→实际问诊/查体/检查/诊断/处置/沟通/书写/报告/刷新。登记只是服务端数据清单，不需要为每个病例新增页面、接口或临床代码。导入本身不激活；不得覆盖同版本资料，不得连带切换其他入口。

`audit-case-training-template.ts`输出的是离线盘点，realFullFlowAccepted固定为0；独立真实验收回执另存，不合并冒充通过。无原件、无对应绑定、未登记对象、共享来源或未验体位均明确列出。当前数据不在输出中复制；输出只含版本、布尔值、计数与必要定位符。

## 书写和运行边界

书写数据契约仍为pediatric-general-v1，10个原有段键不变，只改变编辑布局。草稿写入串行、防抖；切换接诊阶段和生成报告前等待保存成功。自动保存失败显示重试，不能显示保存成功。提交继续使用原服务端归属、版本与幂等规则；草稿与正式提交均须在真实账号验证。AI审阅和医学评价不因本次UI改造而宣称已验。

本轮不批量导入或启用70例，不修改历史迁移、不新增账号/角色权限、不改已有临床评分。不把本地模板测试计入真实学生或医学验收。发布后按首例完成桌面与手机布局、错误操作不释放结果、书写草稿恢复/提交、旧会话与关联入口版本及完整报告复验。
