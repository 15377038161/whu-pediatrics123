# 教师病例资料工作室（2026-10-16）

## 使用与范围

入口 `/teacher/case-drafts`。Word 上传 → 中文表单核对 → 保存待审核。支持一份 `.docx` 或 UTF-8 `.txt`（10 MB），支持粘贴与手填。旧 `.doc` 先在 Word 另存为 `.docx`；扫描/PDF/图片/OCR/媒体提取不在本次范围。编辑前后均可切换草稿列表；切换病例及离开页面时提示未保存修改。

上传只提取纯文本，再按标准病例模板的标题分段，不调用模型，不推断医学事实；冲突的同名年龄、性别或主诉不自动选择。缺项保留空值，未匹配文字保存在来源正文。复杂文档须人工核对，不能把自动分段当作医学审核。来源正文也可编辑脱敏，临床表单修改不会改写来源。

已保存草稿支持搜索、详情与补充；保存修订为新版本，不覆盖、不删除旧记录。客户端生成一次病例 ID/版本用于双击锁和网络重试，数据库唯一约束最终兜底。新文件再次上传视为独立草稿，不以内容哈希合并不同患者。查看历史版本后仅编辑才允许另存；两个不同版本可同名，均显示保存时间。

## 架构与接口

- `case-document.ts`：原始文件限长、ZIP 元数据总解压体积/单项/条目数限制、Mammoth 纯文本提取、确定性分段。Word 排版、图片不进入浏览器 HTML；不访问文档链接，不将原文件保存到公共目录。
- `POST /api/teacher/case-drafts/document`：鉴权后读取 multipart `file`，返回 `{payload, sourceName, issues, fingerprint}`，不写数据库。文件 10 MB、解压总量 40 MB、单项 12 MB、最多 1500 条、正文 15 万字符。文本编码不识别即拒绝。此阶段图片引用不导入，媒体审核默认未确认。
- `GET /api/teacher/case-drafts`：最近 50 条元信息，按保存时间倒序。
- `GET /api/teacher/case-drafts?id=<uuid>`：教师详情（含来源正文）；非法 UUID 400、无记录 404，数据库故障不能伪装成空记录。
- 既有 POST `precheck/save` 继续使用既有字段；中文前端传递 sourceName，不要求教师理解 JSON 或手动管理版本。机器导入契约保持兼容。
- 所有接口保留应用教师角色 AND 数据库白名单；用户 JWT 查询与 RLS，不用 service role。学生库、随机池、事实快照、发布状态、角色授权均不改变。`source_kind=structured_json` 仍描述入库结构，而非老师操作格式。
- `authedFetch` 对 FormData 不设置 Content-Type，由浏览器生成 multipart boundary；仍附既有鉴权头。

## 部署与验证

新增依赖 mammoth / fflate，部署需 `pnpm install --frozen-lockfile`。无环境变量变化、无迁移。按现有 Next.js 构建启动流程；Windows 开发显式 `pnpm exec next dev -H 127.0.0.1 -p 8765`。

针对性测试 `pnpm exec tsx --test tests/case-document.test.ts`：标准字段与顺序、冲突留空、原文保真、隐私提示、旧 doc/无效编码/伪 ZIP/超大输入、真实最小 DOCX 表格顺序、解压限额。再执行 `pnpm validate`、`pnpm build`。

部署后需用真实教师查看已有草稿，预览 Word，检查资料；手机/桌面检查布局与保存栏。匿名上传/详情必须拒绝。真实学生越权和正式保存修订若没有可用测试条件，明确记录未验，不把单元测试等同正式多身份验收。

未实现：审核后自动生成运行时病例及发布、语音、扫描 OCR、媒体审核工具、草稿删除。不能把「已保存」表述为学生已可训练。
