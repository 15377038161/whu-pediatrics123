## 1. 产品定位与已经确定的边界

平台定位为学生自主使用的儿科临床训练与学习工具。学生通过完整病例、专项、OSCE 模拟、题库和学习资源提高能力；教师负责班级组织、了解学情、维护练习题及学习资源。系统不承担正式考试、行政成绩管理或真实诊疗。

### 1.2 必须区分的两类“完整”

1. **流程完整**：学生能进入、采集信息、完成适用操作、提交、查看报告，失败可恢复。
2. **医学内容完整**：教学目标需要的事实、证据、分支、解释和评价标准经过整理和专业审核。

文件字段不为空不等于医学内容完整；所有按钮能点击也不等于病例合理。目标是同时完成两类验收，而不是用模型临时回答填满所有空格。

对缺失信息允许使用 AI 辅助补全，但必须区分“原始病例事实”和“新增教学模拟事实”。真实材料不能被静默改写；关键临床事实未经专业审核不能进入正式开放训练。专业审核可以由项目侧指定儿科教师完成，不要求普通教师在平台里制作病例，也不需要新建教师病例编辑系统。

### 1.3 本方案中的推荐默认值

下文的接口名、数据库新增字段、模拟评分权重、超时值和实施批次是建议设计，不是已经存在或已经验收的功能。实施时以当前项目实际 schema 和平台最新接口为准。尚无凭据、文档或医学审核证据的项目明确记为待核验，不能写成已支持。

## 4. 报告中心与评价体系

### 4.1 记录分类与状态

| 记录 | 列表显示 | 完成后的评价 |
|---|---|---|
| 完整病例 | 病例、版本、模式、用时、提示使用情况 | 综合训练反馈或明确标注的过程完成度 |
| 专项 | 能力、专项场景、练习次数、状态 | 仅目标能力的专项反馈 |
| OSCE 模拟 | 考站、时限、用时、是否超时 | 固定版本考站量表的参考评分 |
| 题库批次 | 题集/版本、已答/总题数、正确率 | 错题、知识点及解析，不伪装为临床能力分 |
| 进行中/中断 | 已保存进度、最后活动时间 | 无总分，支持继续或明确结束 |
| 资源学习 | 最近播放/阅读及可选进度 | 学习记录，不生成临床成绩，不把观看完成当掌握 |

产品状态建议为 `in_progress / completed / generation_failed / pending_content_review / archived`；与现有 session/report 状态通过服务端明确映射。`pending_content_review` 表示内容评价依据尚待复核，不是要求教师逐份改分。网络失败不显示“无记录”，报告失败不显示零分。

筛选包括类型、专项、病例/题集、日期、状态。分页从服务端完成；列表展示“参考评分”“过程完成度”“题库正确率”等具体口径，不统一写成“成绩”。

统一记录使用 `recordType + sourceId` 作为稳定定位键，不能假设临床报告 ID 与题库 attempt ID 永不冲突。排序采用时间和稳定 ID 的组合游标；统计从同一权限与筛选口径计算，不能用当前页的十条记录冒充全部平均或总次数。

### 4.2 每份临床训练报告固定内容

1. 训练概况：病例/站点、类型、专项目标、病例版本、评分标准版本、提示/语音使用情况、有效活动时长与会话经过时长。
2. 学生原始提交：诊断、依据、鉴别思路、处置、沟通；未训练环节显示不适用，不制造空白扣分项。
3. 分项评价：满分、实得分或达成等级、是否适用、评价依据。
4. 问题分类：遗漏、操作不规范、信息整合不足、风险点；只有已审核规则才能给出临床正确性判断。
5. 证据回放：定位消息/操作/提交、时间、转写确认版本；仅展示说明文字不算回放。
6. 对照解释：已审核教学依据、病例适用范围；训练结束并满足答案释放条件后展示。
7. 下一步：最多 1—3 项具体补练，直接打开对应专项并带入允许的病例/目标参数。
8. 同类变化：仅同一能力、相同评价依据或明确可比版本之间比较；练习次数增加不等于能力提高。

### 4.3 不混算的成绩口径

新增/扩展 `evaluationBasis`：`clinical_rubric / process_completion / quiz_accuracy / unscored`，与已有 `scoreBasis` 有明确迁移映射。纯过程完成度不进入临床能力均分。题库正确率不与临床参考评分平均；专项之间不直接按分数排名。

趋势至少按类型、能力、量表版本、提示使用情况分组。小样本显示次数及“样本不足”，不要单次练习就给稳定掌握结论。有效时长沿用现有活跃区间口径，通话计时单独命名；挂机、静音空录、后台等待不能冒充有效练习。

### 4.4 评分从一份结构化量表生成

新增 `src/domain/training-rubric.ts` 保存已审核量表定义，`src/lib/scoring.ts` 只执行规则。每项至少包括：`itemId、dimension、label、maxScore、applicability、evidenceRule、partialCredit、feedback、reference、rubricVersion`。

评价项采用 `achieved / partial / missing / incorrect / not_applicable / not_assessable`，而不是只用达成/未达成。单个事件可以关联不同能力证据，但同一评分项不能重复累计。总分必须等于所有计分项之和；总满分必须等于适用计分项满分之和。

缺少病例事实或评价依据时使用 `not_assessable`，不能把“系统没提供”当学生没问；不适用项不记零分。确需归一到百分制时同时保留原始分子/分母，报告说明计算方式；重大安全错误可突出反馈，扣分或封顶必须来自事先审核且有版本的规则，不能由模型即兴决定。

同时修正现有弱规则：空处置不能因“没有出现不安全出院词语”而获得安全分；“不考虑某诊断”不能因包含诊断关键词而判正确；鉴别字数、事件数量和点击次数不能单独代表推理或职业素养。正反语义、实际提交与真实操作证据必须对应，相关回归列入验收。

### 4.5 各类量表的建议结构

以下权重是待教师审定的产品讨论稿，不是临床标准，也不要求所有病例完全相同。

| 类型 | 建议评价结构 | 使用条件 |
|---|---|---|
| 完整病例 | 病史 25、查体 25、推理 20、安全与处置 15、沟通 10、职业素养 5 | 所有相应环节均开放且有审核标准；否则按适用量表调整 |
| 问诊专项 | 主诉及现病史 35、病例重点追问 30、相关背景 20、提问组织 15 | 不因没做查体、没提交处置扣分 |
| 查体专项 | 准备与说明 20、方法/器材/部位 35、顺序与安全 25、结果识别 20 | 不能仅点击一次就代表掌握整个操作 |
| 推理专项 | 关键证据 30、诊断与依据 35、鉴别 25、不确定性表达 10 | 不能用“字数够”判断鉴别正确 |
| 处置专项 | 优先级 35、风险处理 30、复评/后续 25、解释 10 | 按具体病例已审核条目，不写通用处方模板 |
| 家长沟通专项 | 回应顾虑 25、通俗解释 25、核实理解 20、后续安排 20、尊重与表达 10 | 关键词只是候选证据，不是最终质量判断 |
| OSCE 模拟 | 按考站量表配置，展示适用范围和时限 | 只有完成量表审核的病例可进入 |
| 题库 | 正确数/已答数；整批完成率另列 | 多选部分得分规则先明确，首批可只做单选 |

首批对难以稳定自动评价的沟通质量采用“证据支持的反馈＋待核实项”，不硬凑精确分数。AI 可以辅助归纳原文并引用消息 ID；不得凭印象改写规则分、正式判定学生错误。使用提示后的成绩仍可见，但标为辅助练习；OSCE 和自主无提示表现不混算。

### 4.6 生成、幂等与历史

继续复用 `/api/sessions/[id]/finish`：服务端冻结提交与版本、生成报告、持久化、返回已有报告。相同 finish 请求重试不能产生多份；状态更新失败可重试恢复，不能留下“会话结束但永远没报告”。必要时用一个受控事务 RPC 承担完成态与报告写入，不依赖前端请求顺序保证一致。

新报告快照增加 `practiceFocus、rubricId/version、evaluationBasis、scoreItems、assistance、contentProvenance、studentSubmissions`。历史报告保持原分和原文，缺字段明确显示“历史记录未保存”，不得重算、补造成新评价。原始 `mode=immersive` 要正确标注，不能继续降级显示成引导训练。

题库增加 `quiz_attempt`/练习批次概念；统一报告列表在服务端合并临床报告、题库批次和进行中会话，保留各自存储与权限，不为统一 UI 强塞成同一种临床报告。资源学习记录可以作为列表独立分类，不纳入评分统计。

## 5. 专项训练的任务化改造

### 5.1 进入、训练、结束

专项流程：选择能力 → 选择适用场景/病例 → 阅读目标与必要背景 → 只完成本项任务 → 查看专项报告 → 再练/换场景。不能再次要求走完整接诊，也不能只换标题和横幅。

| 专项 | 开始时提供 | 开放操作 | 结束条件 |
|---|---|---|---|
| 病史采集 | 患儿基本信息、中性主诉、来诊情境 | 对患儿/家长提问、适用沟通干预、文字/语音 | 学生结束采集并提交简短病史摘要；不强制答中所有评分点才能结束 |
| 规范查体 | 已审核的必要病史 | 体位、器材、部位、结果识别 | 提交本项观察，不需要写完整诊断 |
| 危重识别 | 场景中已可获得的症状/体征 | 风险识别、优先行动选择及理由 | 提交识别与处理优先级 |
| 诊断推理 | 固定病史、查体和检查资料包 | 诊断、依据、鉴别 | 提交推理结果 |
| 处置决策 | 已知病情、病例限定条件 | 处置优先级、后续安排 | 提交计划 |
| 家长沟通 | 已知病情、告知范围、家长顾虑 | 模拟通话/文字沟通、解释与确认 | 结束会话，保留未覆盖目标的反馈 |

现有四项优先整改为真实单项任务；新增推理、处置按已有病例资料成熟度开放。筛选仅显示该专项可用的病例；从报告跳转时服务端验证病例与 focus 的组合，不适配时给出原因和其他可选场景，不默默换患者。

### 5.2 工作台与服务端同步限制

在 `src/domain/practice-scenarios.ts` 建立紧凑的专项配置：`focus、allowedStages、initialStage、requiredInputs、providedFacts、completionRule、rubricId、allowedCaseCapabilities、presentation`。本轮会话保存配置版本。

`training-workspace.tsx` 按配置显示阶段和表单；`agent-engine.ts` 同样验证事件。学生不能通过直接调 API 获取专项不应开放的阶段、答案或其他检查。允许的前置信息由服务端投影，不能把完整病例 JSON 放到客户端再靠 CSS 隐藏。

专项开始时由系统直接提供的事实标记为 `provided`，学生主动问到或操作获得的证据标记为 `elicited/observed`；不能把预先给出的资料算作学生完成问诊或查体。报告和评分共同使用该来源区分。

复用一个会话引擎、消息列表、鉴权、报告生成和语音组件；只为任务明显不同的区域拆子组件。不要复制第二套训练状态机，也不新增通用工作流引擎。

## 6. 全问诊语音与模拟通话专项

### 6.1 能力来源与实施前核验

用户已确认超星开发平台新增语音能力。当前本地 `speech-contract.ts` 的 unavailable 只是旧状态；旧接入 404、旧 SDK 未列语音能力都不能否定新服务。

目前未拿到新平台能力的正式接口契约，公开检索也未获得足以实施的当前官方语音文档。因此不虚构 SDK 类名、端点、音色或可用实时协议。实施第一步在用户当前项目内读取平台最新语音技能/官方文档，记录以下事项到 `docs/SPEECH_INTEGRATION.md`：

| 核验项 | 必须得到的证据 |
|---|---|
| ASR 输入 | 允许格式、时长、大小、采样率、上传方式；是否流式、是否返回片段与置信度 |
| TTS 输出 | 文本限制、格式、音色列表、角色适用范围；是否可流式、是否允许缓存 |
| 鉴权 | 服务端调用凭据与头透传规则；不把项目密钥发浏览器 |
| 网络 | 网关是否支持流式响应/WebSocket；鉴权头、超时与移动端行为 |
| 费用与并发 | 额度、速率、并发、错误码；有无项目级开通要求 |
| 数据 | 音频保留政策、处理方、可否禁用存储及删除方式 |
| 真实最小链路 | 麦克风 → ASR 文本 → 既有对话引擎 → TTS → 手机扬声器 |

若仅支持普通音频上传/合成，首批采用轮次式语音；若真实支持低延迟双向流，再增加自然轮替/打断。模拟通话的视觉样式不等于已经实现实时双工，不承诺尚未核验的接通延迟和声音表现。

### 6.2 语音覆盖范围

语音接入完整病例的问诊及家长沟通、所有包含交流的专项、OSCE 模拟问诊、现有 immersive 场景的交流。查体真实音效、教学视频与对话语音分开管理；非交流表单仍保留文字，不因为“全问诊语音”把所有按钮强制改成说话。

提供文字/语音切换，保留文字对话及可编辑转写。用户首次明确点击语音后请求麦克风权限，不在进入页面时自动录音。麦克风拒绝、设备不支持、ASR/TTS 失败时可以继续文字问诊，原病例进度和已提交内容保留。

首批轮次式交互：录音 → 结束/静音分段 → 识别 → 显示转写 → 确认发送 → 服务端处理 → 显示角色文字 → 按队列播音。后续可提供用户主动开启的自动发送，首版不默认把识别错误直接作为临床决策提交。

### 6.3 语音组件和状态

建议新增 `src/lib/speech.ts`、`src/components/voice-input.tsx`、`src/components/role-audio-player.tsx`、`src/components/communication-call.tsx`。保留现有 `speech-contract.ts` 并扩展真实状态，不复制另一个不兼容契约；状态来自服务端可用性探测，不能仅根据前端常量显示“已启用”。

最小状态：`idle、requesting_permission、recording、transcribing、awaiting_confirmation、processing_turn、speaking、recoverable_error、ended`。播放器维护当前消息 ID、排队消息、停止状态；对话引擎仍使用现有 `ASK_QUESTION` 或适用沟通事件，语音不另建一套临床逻辑。

每轮请求携带稳定 `clientEventId/turnId`，ASR 成功后网络重试不能重复发问。学生编辑转写时记录“ASR 原文/确认文本/是否编辑”，报告评价确认后的语义内容；默认不长期保存原始录音。需要回放原音时必须提供明确用途、保留期和用户同意，再设计受控存储，不默认收集全程音频。

停止录音、结束训练、切换页面后立即释放 MediaStream tracks、取消过期请求并回收 objectURL。音频播报使用本轮已校验的角色文本，TTS 不能自己生成新事实。家长/患儿队列顺序固定，不同时叠音；同一个角色同一病例使用稳定音色。不得克隆真实儿童或教师声音。

### 6.4 模拟通话界面

适用于家长沟通、部分病史采集、解释检查/后续安排等专项。页面包含：虚拟家长头像和身份、训练场景、连接/录音/思考/播报状态、模拟通话经过时长、静音、停止播报、文字转写、结束本轮。

进入前显示“AI 模拟家长沟通训练”；不显示真实电话号码，不调用系统电话，不假装真人在线。若实际是按轮录音，不显示虚假的“持续聆听”；只有正在采集时显示录音指示。提供结束确认和保存反馈，但不强制完成所有目标才能挂断。

与家长通话时不凭空插入患儿说话，除非场景明确孩子在旁且具备表达能力；电话场景不能声称已完成触诊、听诊、血氧测量等需要真实操作或既有资料的项目。若任务涉及必须现场评估的信息，只能按该场景已提供资料表达，不给模型虚构远程查体结果。

模拟通话不要求实时数字人、口型驱动、真人连麦或 WebRTC 服务器。上述均不作为首批依赖。

### 6.5 异常与评分公平性

| 情况 | 用户看到的行为 | 数据处理 |
|---|---|---|
| 麦克风拒绝/未接入 | 说明如何在浏览器站点权限中开启，同时可切文字 | 不记临床错误 |
| 无声/杂音/空识别 | 保留重录入口，不发送空问题 | 不产生重复轮次 |
| 医学词或数字识别不确定 | 展示转写，允许修正；平台若无置信度不伪造数值 | 保存确认文本及编辑标记 |
| TTS 失败 | 文字照常可见，可重播或停止 | 不重新运行临床引擎，不重复扣分 |
| 网络断开/取消 | 保留已确认文本，恢复后由学生决定重发 | 幂等，拒绝过期响应覆盖新轮次 |
| 手机切后台/来电 | 暂停录音与播报，恢复后明确继续 | 不偷偷持续收音 |
| OSCE 中平台异常 | 记录中断和技术原因；提供明确恢复/结束状态 | 技术故障不按沉默扣分；计时是否暂停采用站点规则并在开始前说明 |

语音速度、口音、ASR 错误、设备质量不直接转成能力分。要评价表达组织，只能基于已确认转写及审核标准；不在无证据时评价语气、音量、情绪识别。

## 7. 全病例资料补全与可运行性治理

### 7.1 先建立唯一病例账本

将公开目录、教师原始目录、别名/亚型映射、`knowledge/teaching-cases`、数据库快照、发布状态和既有会话引用进行对账。输出 `docs/case-readiness-register.json` 及便于人工查看的 Markdown 表。当前 53 份独立 JSON 不等于全部公开入口数量，也不能把多个别名当新增独立病例。

每个拟开放入口一行，字段至少为：`publicCaseId、sourceCaseId、relation、version、sourcePath、sourceHash、ageKnown、sexKnown、historyReady、examReady、testsReady、reasoningReady、planReady、communicationReady、avatarReady、speechRoleReady、rubricReady、supportedModes、blockers、reviewer、reviewedAt、publishedVersion、e2eResult`。

已有 `case-UUID` 和历史 `teacher-*` 的关系复用 `case-identity.ts`。别名可以引用同一个已审核病例；亚型不能因为名称相近就自动复用所有事实、诊断和处置，必须明确差异。去重不删除历史会话及其版本绑定。

### 7.2 每例需要完成的教学资料包

| 资料域 | 必须整理的内容 | 验收重点 |
|---|---|---|
| 基本身份 | 年龄及单位、性别来源、虚拟姓名、来诊时间线、陪诊者关系 | 天/月/岁不能误读；隐私脱敏；与图像一致 |
| 来诊情境 | 主诉、中性入口简介、家长最初顾虑 | 不在病例卡片提前公布最终诊断 |
| 现病史 | 起病、过程、相关症状、关键阴性、院前处理、一般状态 | 时间线、药物、症状不能互相矛盾 |
| 相关病史 | 与本病例目标有关的出生/喂养/发育、既往、过敏、接种、家族、接触等 | 不要求所有病种一套问法；未知与否认分开 |
| 查体 | 准备、体位、器材、部位、可返回结果、证据释放规则 | 不是点击任意部位都返回同一段原文 |
| 辅助检查 | 可申请项目、规范名称/同义词、结果、单位、时间、原始附件 | 不把旧检查当当前结果；不伪造正常值 |
| 诊断思路 | 参考诊断、证据链、需要区分的情况、允许的合理表述 | 只能使用该版本资料能支持的结论 |
| 处置与复评 | 病例适用的优先级、后续安排、复评条件 | 必须专业审核，不由聊天模型临时生成标准答案 |
| 家长沟通 | 家长已知信息、担忧、目标、可回答事实、理解确认点 | 不把家长写成医学专家，不能提前知道未告知结果 |
| 角色能力 | 患儿语言/意识/配合能力、代述人、非言语反馈 | 决定角色调度，不只作为提示词装饰 |
| 人物与媒体 | 对应年龄/性别的虚拟人物、适用体位、已有审核媒体 | 跨姿态同一人物；通用图不代表真实体征 |
| 评价标准 | 可评价项、不适用项、证据映射、量表版本 | 不因材料缺失扣学生分 |

“不适用”可以是合法、审核后的状态。例如某专项不训练辅助检查，不需要造一组检验值。完整体验要求关键训练路径有合理资料，不要求每个病例拥有所有检验、所有器械和所有症状。

### 7.3 缺失信息的分级补全

| 情况 | 允许操作 | 发布条件 |
|---|---|---|
| 原文有资料但提取失败 | 修正抽取、字段映射及同义词 | 与来源逐项核对 |
| 多份原文存在冲突 | 记录冲突及版本，人工确定适用记录 | 未解决前不得静默选一个并发布 |
| 非临床背景/口语表达不足 | AI 形成虚拟称呼、情绪表达、自然对话草稿 | 标注为教学设计；不影响临床事实；检查一致性 |
| 临床信息缺失，但希望形成完整模拟 | AI 根据明确教学目标生成一个独立“教学模拟病例”草稿 | 独立 ID/版本、合成标记、依据及专业审核；不冒充原真实病例 |
| 关键临床资料没有依据或尚未审核 | 保留未记录/待核实状态，列入补全任务 | 当前不开放依赖该事实的评分/模式；补齐审核后再开放 |

不能将“未记录过敏史”改成“无过敏”，不能将“没有检查结果”改成“结果正常”，不能为了流程顺畅补出确定剂量、检验数值、影像结论或急救反应并冒充原始事实。

用户希望“全部病例可完整体验”作为最终交付目标：每例都必须有闭环结论——原来源补齐且审核通过，或完成明确标记的完整教学模拟版本。暂时禁用不完整病例只是实施期间保护措施，不是最终完成方式。若专业审核或关键素材仍未取得，该例必须记为未完成，并列出具体欠项，不能宣称“全库已跑通”。

### 7.4 补全不是在每次问诊中即兴造事实

采用离线/受控制作流程：来源抽取 → 差距清单 → AI 辅助草稿 → 格式校验 → 一致性检查 → 专业审核 → 版本快照 → 发布 → 逐例流程验证。

建议新增 `scripts/audit-case-readiness.ts`、`scripts/prepare-case-enrichment.ts`、`scripts/verify-case-scenario.ts`。由项目侧受控脚本/工具运行，先产出可审阅文件，不自动写正式数据库、不覆盖原文、不让普通教师重新承担完整病例制作。

每项补充至少记录 `fieldPath、value、provenance、sourceRef、reason、reviewStatus、reviewer、reviewedAt`。`provenance` 为 `source / teaching_simulation / unknown`；文本模型输出只是草稿，不因 schema 通过就升级成临床真值。

运行时会话绑定已发布的病例与角色配置版本。相同问题在同一会话中保持事实一致；刷新、重启、换输入方式都不能换成另一份补全结果。更新病例只影响新会话，既有会话恢复原绑定版本，沿用现有快照恢复机制。

### 7.5 规则、矛盾与验收

检查至少包括：年龄单位与发育能力、性别与资源匹配、症状起止时间、院前处理、检查时间及单位、同一事实多处一致、资料能够支持参考推理、禁止泄露诊断的公开字段、来源与合成标记、媒体是否存在、量表引用的证据能否获得。

结构校验可自动化；临床合理性由专业审核；模型自检只能作为辅助，不能自审自通过。特别检查“家长不知道”与“系统没有资料”的差异：前者是可设计的真实交流情境，后者是制作缺项，两者不能用同一句话掩盖。

逐例端到端验证：目录可见 → 创建会话 → 问到关键事实 → 完成适用查体 → 申请适用检查 → 提交诊断与处置 → 完成沟通 → finish → 报告可见及证据可定位 → 刷新恢复 → 再练产生新记录。语音至少覆盖每种角色能力和每类场景的真实端到端测试，不能只测演示病例。

全库自动接口回归加分层人工临床抽查；新生儿、无法言语、不同年龄、不同性别、未知资料、别名和亚型必须纳入边界样本。全库覆盖率以唯一病例账本为分母，逐项记录通过/失败，避免换统计口径后宣称 100%。

## 8. 更拟人化且符合年龄与病情的双角色对话

### 8.1 角色能力是明确数据，不是让模型猜年龄

增加病例角色配置 `communicationProfile`：`ageValue、ageUnit、developmentNotes、speechCapability、consciousness、distress、primaryHistorian、caregiverRelation、caregiverKnowledge、childKnowledge、voiceProfile、nonverbalBehaviors`。

`speechCapability` 可为 `nonverbal / limited / conversational / impaired / unknown`。它由年龄、原资料和具体病情共同确定，并可由经审核的病情事件改变；不把单一生日阈值当医学发育诊断标准。原资料缺失或冲突时先核对，不把“3月”误读成“3岁”。

### 8.2 角色调度要求

| 情境 | 对话规则 | 界面与声音 |
|---|---|---|
| 新生儿、明确不能语言表达 | 病史由知情家长/照护者回答；患儿不输出语义台词 | 可展示“哭闹/安静”等已有或审核后的非言语反馈；不合成会说话的婴儿声音 |
| 表达能力有限 | 患儿仅回答自身能感知、能表达的问题；家长补时间线等 | 短句或词语按个体配置，不固定每轮都用儿语 |
| 能正常交流的儿童 | 能独立回答主观感受；不知道的病史由家长补充 | 不强迫学龄儿童使用幼儿化措辞 |
| 年龄较大/青少年 | 表达符合年龄与性格；按情境尊重自主表达和隐私 | 不总让家长抢答，不一律使用幼童音色 |
| 意识受损、严重不适或其他交流受限 | 优先照护者及已知资料，限制患儿语言输出 | 不因学生安抚一次就恢复正常交流能力 |
| 无家长在场/照护者不知情 | 按既定场景说明知情边界 | 不凭空切换出一个掌握全部病史的家长 |

表中是产品行为约束，不是临床年龄阈值指南。具体语料由专业教师审核。

“安抚”只能影响情绪和配合，不改变年龄、语言发育、意识状态或事实。“请家长先别说，让孩子回答”对不能说话的患儿不能机械执行；系统应给出合理的家长/场景回应并继续训练，不因按钮被点击就产出“嗯，我自己说”。

### 8.3 家长的自然表达

家长可以担心、重复确认、记不清某些细节、用生活化描述，也可以表达外行猜测，但外行猜测必须是角色观点，不能被引擎当成已证实诊断。不能每轮都以“我补充一下”开头，不能把病历原文一段段朗读给学生。

每次围绕问题回答适量信息，允许学生追问；记住之前已经说过的事实、已被解释的事项和未解决顾虑。模型可调整说法，不改变起病、用药、检查值、过敏等已固定事实。若问题宽泛，可自然请学生澄清；不要把所有未命中关键词的问题都拒绝。

不把“医生刚问过”当作家长已经知道检查结论。医生告知、病例初始知识和模型可见全量资料三者分开；角色只能使用其应知信息。学生的错误假设不能自动写入病例真值。

### 8.4 技术实现

在 `src/lib/agent-engine.ts` 的统一发言计划中先决定 `speakers、allowedFacts、disclosureLevel、nonverbalActions`，再调用 `renderRoleReply`。`role-agent.ts` 负责受限自然表达；输出 schema 显式允许 `childSpeech=null` 及独立非言语描述，不能把旁白混进患儿 TTS。

模型输出经过说话者能力、事实引用与长度校验，再写消息和播放队列。模型未命中规则、结构解析失败或超时，确定性降级也读取同一份角色能力配置。检查范围必须包括普通问答、来源病例问答、医生干预、宽泛问题、沟通阶段、系统默认消息，不能只修主提示词。

检索从宽泛正则匹配原文逐步改成“结构化病例事实＋主题同义词＋受控语义识别”。保留现有确定性事实授权，不允许模型检索跨病例事实填空；每条获知事实写入事实 ID 和来源证据，不用问答轮次猜得分。

新增 `src/domain/communication-profile.ts`、`src/lib/role-orchestrator.ts`（确有多处调用需要复用时），扩展 `RoleReplyInput` 与统一 schema。避免把年龄解析、权限、事实过滤散落在 UI、提示词和降级函数里各写一遍。

增加测试：不能说话患儿在模型成功/失败时都无语义台词；暂停家长不导致婴儿开口；多轮追问一致；学生诱导改年龄/诊断无效；同义提问能获得同一事实；长对话不串病例；情绪变化不改变临床事实。

## 9. 人物形象、音色与病例绑定

### 9.1 人物资产清单

建立 `src/domain/patient-assets.ts` 或扩展现有 `patient-appearance.ts`，每项包含 `assetId、ageBand、sexPresentation、postures、caregiverAssets、style、license、isSynthetic、reviewStatus、version`。病例发布版本绑定 `patientAssetId` 和必要家长头像；不再按病例哈希随机挑一个明显年龄不符的通用孩子。

年龄段可按产品素材管理划分为新生儿/婴儿、幼儿、学龄前、学龄、青少年；实际匹配依据病例年龄与审核，不声称图片可精确体现医学发育年龄。对于缺少明确性别或年龄的来源，使用中性示意/先补核，不擅自给真实病例增加性别与出生日期。

### 9.2 制作与复用原则

优先复用现有合法、适龄资产；不足的用合成插画/虚拟人物补充，标注“教学虚拟角色”。同一患儿的正面、仰卧及其他必要姿态使用一致人物，不因切换查体而换脸、换性别或变大变小。婴儿不使用站立儿童图；体位只在适用病例中提供。

图像只表达外观和场景，不能替代真实体征。若图片中没有可靠呈现某个体征，不让学生凭通用人物图判断阳性/阴性；症状图片使用经过审核、授权、脱敏且确实对应本例或明确的示教附件。

家长头像符合该场景的母亲/父亲/其他照护者配置，不默认所有病例都是妈妈。TTS 使用合法可用的稳定音色；没有适当儿童音色时保留文字或用明确旁白，不能用成人声冒充已经准确模拟儿童。

### 9.3 失败与验收

资源不存在或加载失败时显示中性占位与“示意图暂不可用”，不随机换为另一个性别或年龄。核对所有病例的资产存在性、元数据、体位及身份一致；在手机和桌面真实打开检查裁剪，重要部位不被遮挡。素材及许可写入资源清单，原图不含患者个人信息。

## 10. 班级创建、名单匹配、首次选班与一次换班

### 10.1 首次登录优先级

1. 服务端完成超星官方 OAuth 及身份验证，读取本项目获准获取的可信身份字段。
2. 已有当前班级：保持不变，不在每次登录重新跑默认分班覆盖它。
3. 尚未完成入班且名单唯一可靠匹配：自动进入对应启用班级，显示归属结果，不弹无意义选班页。
4. 无匹配：显示可选班级，按院校/年级等非敏感字段筛选；学生自主选择即可加入，不需要邀请码或教师审批。
5. 跳过：进入系统“游客班级”，可立即训练、看题库和资源、保存报告；仍是本人登录账号，不是匿名游客登录。
6. 首次选择/跳过/自动匹配完成后记录 onboarding 状态，避免每次登录重复弹窗。

游客班级是无正式归属的逻辑分组，不向所有教师开放该组学生数据，不生成虚假授课教师，不清空历史学习记录。

### 10.2 一次自主修改机会

建议明确规则：初次选班、初次跳过、首次名单自动入班都不扣次数；之后主动从当前班级换到其他班级（含游客转正式）消耗一次。学生在“我的班级”看到当前归属、剩余次数、更换说明和确认。

服务端事务锁定该学生当前归属记录，检查 `selfChangeCount<1`、目标班级启用且可选择、目标不等于当前，再变更当前成员关系、写审计并增加次数。重复提交同一幂等请求不多扣；两台设备并发最多成功一次。不能依赖 localStorage 或隐藏按钮限制。

推荐首批一个学生只有一个“当前主班级”；历史班级通过变更记录保留，不能为兼容现有多成员关系把所有旧班级都当当前。历史多班学生迁移时生成冲突清单，按真实归属核对，不武断挑第一个。

换班成功不删除个人训练记录，也不追溯改写旧会话 `cohort_id`。班级被归档属于系统修复场景，项目管理员可受控纠正并记审计，不计学生主动换班次数；普通教师不能借此任意调整学生历史成绩或访问范围。

### 10.3 名单导入字段与匹配

继续支持现有 Excel 复制粘贴及 UTF-8 CSV，首批不必为“Excel 导入”增加复杂二进制解析。模板包含：姓名、超星标识类型/值、学号、手机号、院校标识；至少一项可用于核对，姓名单独一列的名单可保存但可能只形成候选。建议班级详情内导入，避免每行反复填写班级。

UID、cxid、puid 等名称必须以平台实际语义为准：不同命名空间分别保存，不未经核实全部当同一个 uid。学号和手机号按字符串保存，保留前导零；手机号规范化区号和格式，界面脱敏，不把完整手机号写日志。

| 匹配依据 | 自动归班要求 | 不满足时 |
|---|---|---|
| 超星可信标识 | 来自官方已验证声明，类型与名单一致，唯一命中 | 候选/待核实 |
| 手机号 | 官方返回或经平台验证绑定，唯一命中；不能使用学生自由编辑资料冒充验证 | 没有获准字段就不宣称支持自动手机号匹配 |
| 学号 | 可信声明＋同一非空院校/机构范围，唯一命中 | 不跨校按裸学号匹配 |
| 姓名 | 仅在同院校范围、来源可信且唯一无冲突时才可作为自动依据 | 普通显示名只用于候选，不强制自动归班 |

任意可信标识相互矛盾、多班同时命中、同名多条或已绑定其他账号，都不能采用“优先字段覆盖其他冲突”；展示待核对状态，学生仍可按首次选班路径训练。姓名是否允许单独自动匹配及其可信来源在实施前确认，不能凭重名概率低就放宽身份边界。

教师看到导入预览、重复、冲突、已匹配、待学生登录、缺少可靠标识的计数和必要明细，不获得学生密码或 token。同一文件重复导入幂等，出现矛盾保留原名单与绑定，不静默覆盖。

学生已自行选班或已经换过班后，晚导入名单不自动改其当前班级；列入候选提示和受控核对。匹配不提升教师角色，也不把学生自填手机号/学号升级为全局可信身份。

### 10.4 现有机制怎样替换

复用 `cohorts、cohort_members、class_roster、class_account_identities` 和当前鉴权。新增当前归属/次数和变更审计，不另建第二套班级系统。修订 `/api/classes` 的 action schema：保留 create/import，新增初次选择、跳过、一次更换、归档；删除学生申请和教师批准的活动入口。

数据库同步更新 `class_workspace`、身份同步/匹配函数、RLS 和统计 RPC。旧 `class_join_requests` 可保留历史只读记录，但停止新建/审批；不为了兼容保留两个并行入班流程。旧接口在新前端切换后返回明确废弃响应，按发布计划移除旧 action；历史 SQL 文件仍不改。

### 10.5 教师查看范围与换班历史

推荐默认：教师查看自己管理班级成员在授权归属期间产生的训练；加入前的个人记录可由学生主动分享，原班教师不自动获得转班后的新记录。此规则尚需产品确认，但必须在实施前写成明确的会话/报告时间范围策略。

当前 `app_can_view_student(user_id)` 主要限制“能看谁”，还不足以表达“能看这个人的哪段记录”。新增/扩展 `app_can_view_training(user_id, cohort_id, created_at)` 一类受控判断，并统一用于会话、消息、操作、报告、题库、语音资产、统计和导出。禁止只在前端过滤，也禁止换班后所有教师看到全部历史。

## 11. 教师工作台的具体重设计

### 11.1 学情首页

首屏：班级选择、日期范围、参与学生数/班级人数、完成训练次数、待继续人数、训练类型分布；提供学生列表和常见遗漏入口。没有任务发布，不出现任务完成率、逾期作业、未交名单或正式考试排名。

第二屏：按临床能力/专项的反馈分布、题库知识点错误情况、近期训练记录。不同评价依据分开展示，过程完成度不能进临床均分；用时只表示参与，不代表水平。

学生表列：姓名/必要编号、当前班级、最近训练类型和时间、已完成次数、可比训练表现、查看档案。不能只按最近一次低于 80 分决定“风险学生”，尤其不能把未训练、缺资料和实际低表现混成一类。

空状态分开显示：教师尚无班级、班级无人、有人但未训练、日期内无记录、接口读取失败。权限异常不能伪装成“没有数据”。

### 11.2 学生档案与报告查看

展示授权范围内的病例、专项、OSCE 模拟、题库历史；支持按类型和能力筛选、进入单次报告、查看问答/操作证据、同类进步。可提供教学备注作为后续可选项，但不是强制评阅流程，更不要求教师对每份记录确认才能让学生看到。

教师只读学生原始提交、系统评价和已确认转写。无改分按钮、无隐藏评分写接口、无改分数据库策略；不把“AI 点评”生成成教师本人评语。

### 11.3 班级管理

班级列表提供创建、搜索、启用/归档；详情分成员、名单、导入结果。取消邀请码、加入审批卡和待审批数量。名单数据仅本班管理者及项目管理员可读；学生选班页不返回全体学生名单、手机号和匹配详情。

归档不删除成员历史和学习记录；停止新选班后，现有学生如何迁移有明确提示和管理员修复流程。若首批不支持教师直接移除成员，按钮不出现；不得为了复用旧 UI 留一个点击无效的管理入口。

### 11.4 病例资源页面

替换 `/teacher/case-drafts` 中“上传已有资料，完善病例”的产品流程。保留名称/学科、资料状态、适用训练、审核版本、病例说明、资源查看、问题反馈和已有上下架。

删除普通教师创建/导入完整病例的组件入口和业务 API 权限；不能只移除菜单却仍允许老师直接访问旧 URL/API 上传。旧草稿记录保留只读，技术导入仅项目侧受控工具可用，与教师角色分离。上架不等于审核通过：只能对已达所选模式就绪标准的版本上架。

新增问题反馈内容：病例 ID/版本、环节、问题描述、可选消息/操作定位，不要求老师重新编辑整份病例。反馈由项目侧修订新版本，不直接覆盖正在训练的病例。

### 11.5 内容发布权限

教师可维护自己题集和学习资源；默认只对其管理班级发布。全平台资源/题库由项目管理员审核后开放，避免某教师的草稿或不适用内容直接影响全体学生。游客班级可以使用全平台公开内容，不能因没有正式班级而不能练习。

病例核心事实、模型调用配置、全局教师授权和评分算法不开放给普通教师随意修改。内容审核、资源发布不等于修改学生训练得分。

## 12. 教师 AI 出题与学生题库

### 12.1 教师使用流程

新建题集 → 填主题、教学目标、适用年级、题量、难度 → 可选择允许使用的教学材料/已结束公开病例资料 → AI 生成草稿 → 自动格式检查与重复提示 → 教师逐题审核、编辑或重新生成 → 预览学生视图 → 选择班级范围发布。

首批优先单选题，复用当前题目、答案和判分机制；多选、判断、问答在数据契约和判分标准就绪后分批开放，不生成平台无法作答的题型。教师界面只显示已支持的题型。

题目草稿包含：题型、题干、选项及稳定 ID、正确答案、解析、知识点、难度、教学目标、参考材料定位、适用条件、生成模型/时间、审核状态。材料无明确出处时写“未提供来源，需人工核实”，禁止模型编造教材页码、指南版本或参考文献。

教师上传出题材料与上传病例是两种用途：前者只是生成练习题的参考，不创建病例、不进入学生问诊事实库。来源材料仍按隐私和授权要求处理，含个人信息的原始病历不能直接发给模型或题库学生端。

### 12.2 生成与发布约束

所有文本 AI 调用经现有 `invokeCozeAI`；新增专用 `question-generation.ts` 负责 prompt、Zod schema 和解析，不在 API 里另建 LLMClient。材料内容和用户输入视为不可信数据，不能改变权限、泄露答案或调用其他工具。

生成前检查数量、输入长度、适用范围和教师配额；长任务按可恢复批次返回，保存 job 状态和 requestId，防止超时后重复计费/重复插入。先做简单受控批次，不引入通用任务平台。若无法在请求时限内完成，用现有平台可用机制实现持久任务，不能依赖响应结束后的进程内 Promise 保证落库。

自动校验：必填字段、选项唯一、答案在选项内、单选恰好一个正确答案、解析存在、重复/近重复、事实与参考材料冲突提示、题干不夹带答案。自动校验通过不等于医学内容审核通过。状态为 `draft → ready_for_review → published → retired`；老师确认审核后才进入学生取题范围。

编辑已发布题目生成新版本，题集固定题目版本清单；已有练习仍按原版判分。下架阻止新练习选入，但不删除历史作答与解析。学生已分发未作答的题目遇到下架/错误纠正，需明确继续原版或替换的策略，首批建议提示退出该题并记录原因，不把它算错。

### 12.3 学生使用流程

题集列表展示标题、主题、适用范围、题数和已练情况；详情可开始、继续、重练或只练错题。重新练习必须创建新的 attempt，不能沿用“该学生该题一生只能首次提交”的去重键；同一次 attempt 的重复提交仍然幂等，以首次已确认答案为准。

取题只返回题干、选项、难度、知识点等允许投影。正确答案/解析不进入初次 HTML、前端 bundle、网络响应或可猜测的资源路径。判分在受控 RPC 完成，学生只能访问自己已分配/已开始 attempt 的题目；提交后按规则释放本题答案及解析。

练习批次结束生成题库报告：题集及题目版本、正确率/完成率、逐题提交、解析、知识点错误分布、下一步建议。中断后可继续；用户主动结束只统计已答数并标明未答，不把“已答正确率”冒充整套完成率。

### 12.4 改造现有题库安全链

继续复用 `src/lib/quiz-pool.ts` 和 `/api/quiz/questions、answer、review`，扩展题集、版本、attempt 参数；需要新版 RPC 时采用新签名或明确新函数，禁止修改参数却让旧客户端误判。

现有 `quiz_assignments` 是内部题目分发记录，不是教师布置作业，产品界面不把它显示成“任务”。先核对线上实际题表和约束，再添加题集/版本/attempt 表。旧练习标记 `legacy`，不伪造题集名称或历史批次。

修订目前宽泛的教师题库写策略：普通教师只改自己的草稿/题集，发布范围受其班级管理权限制；全平台发布由管理员控制。学生使用范围约束必须在取题 RPC 与 RLS 生效，不仅靠题集列表隐藏。

## 13. 独立学习资源中心

### 13.1 学生端

列表按教学视频、图文资料分类，支持主题、关键词和最近学习。卡片含标题、类型、简介、视频时长、适用主题；详情展示播放器/阅读区、来源与发布信息、相关专项入口。

八个已盘点视频可作为首批资源登记清单：儿童胃管置入、经鼻/口腔吸痰法、动脉采血、静脉采血、儿童胫骨穿刺、穿脱隔离衣、心肺复苏、简易呼吸器的使用。名称需核对原文件后展示，不凭标题自动生成操作标准或医学解析。

用户已解决上传方式，本方案不再安排压缩、分段、云盘迁移或存储服务采购。现有资源取得什么形式的访问标识，就按核验后的方式接入；发布资源前检查其对应文件、播放权限、移动端兼容和教学适用性。

### 13.2 教师端

资源管理提供标题、简介、类型、学科/知识点、适用年龄或年级、封面、视频/文件标识、来源、授权说明、可见范围、排序和状态。支持草稿、预览、发布、下架；上传入口只调用已经选定、验证过的文件上传方式，不在网页内重建第二套大文件上传器。

相关病例/专项通过显式关联保存，不能通过标题包含“肺炎”就自动认定适用于所有呼吸病例。资源与病例事实分开：一个视频可供多个专项学习，但不能因此被当作每个患者的检查结果。

### 13.3 播放与访问契约

平台对象存储资源保存 `fileId`，播放前由服务端校验可见范围后获取当前有效链接；不要把临时签名 URL 当永久数据库值。若用户最终提供永久视频地址，则核对 HTTPS、视频响应类型、访问权限、防盗链、拖动进度及浏览器可播放性；永久页面分享链接不自动等于可用视频地址。

嵌入播放、跳转播放分别显示；只支持跳转时明确“前往平台观看”，不假装应用内已取得播放进度。需要跨域脚本请求的流媒体再核验 CORS；普通 video 能否播放需实际测试，不能仅按是否支持跨域 fetch 推断。

对任意外部链接不在服务端无条件下载/转发，避免开放 URL 代理；需要探测时限制协议、来源和内网地址。资源下架后学生新请求被拒，历史学习记录仍在。临时链接失效后可续取，但已发出的签名链接能否提前撤销以存储能力为准，不能承诺下架即刻撤销所有既有 URL。

观看进度保存本人资源 ID、版本、位置和更新时间，可做断点续播；进度不能当掌握程度，不加入临床评分。资源学习时长如纳入参与统计，沿用可见且活跃口径，并与病例训练、语音交流分项展示。

### 14.4 历史数据迁移与发布顺序

1. 备份当前数据库结构、策略、关键表计数和发布配置；盘点已有未提交改动，不覆盖用户文件。
2. 生成现有班级归属冲突、题库约束、病例版本和历史报告字段差异清单。
3. 先新增可向前兼容的字段/表/读接口，部署后端和授权策略；旧数据使用明确 legacy 标记。
4. 回填可验证字段；无法可靠回填的保留未知，不重新计算历史分、不伪造音频和来源。
5. 切换新页面和事件契约，验证后停用旧入班审批、旧教师病例写入口及宽泛题库写策略。
6. 以代码回退＋保留新字段/版本数据为优先回退方式；涉及权限策略的回退不能恢复已知越权能力。
7. 每批发布记录 Git 版本、迁移、病例/量表版本、真实验收结果。线上配置与本地构建成功分别记载。

生产新功能只在对应后端、迁移和真实能力就绪后开放；未接入语音不展示可点击的空麦克风，缺量表不伪装可评分。技术发布阶段控制不能长期变成两个并行产品入口，完成切换后移除临时分支和废弃文档。

## 15. OSCE 模拟站的保留与调整

保留独立入口及限时、无提示的综合自测体验。页面和报告统一使用“模拟站/参考评分”，不出现正式考试成绩、教师排考、考试任务、改分和成绩发布流程。

学生流程：选择已就绪站点 → 查看能力目标、时限、语音/文字方式、技术故障规则 → 开始 → 独立完成站点要求 → 手动结束或时间到冻结已确认提交 → 查看报告与补练建议。

站点定义包括 `stationId、version、caseVersion、timeLimit、allowedActions、requiredStages、rubricId/version、technicalInterruptionPolicy`。时限以站点配置为准，不把页面固定文案与服务端实际计时写成两个来源；服务器保存开始和截止时间，刷新不能重置计时。

无教学提示不代表隐藏设备/权限/网络错误；技术状态正常显示。训练期间不返回评分点、参考诊断和答案；时间到后服务端拒绝新增临床操作，不只禁用按钮。已录但尚未确认的转写是否纳入以开始前公布的规则为准，不能结束后悄悄代学生补写。

学生主动结束或时间到都能得到反映实际过程的报告；未覆盖项按量表说明呈现，不伪造完成。模型或语音故障保留过程并显示技术影响，不用重复调用模型重新生成一段“像已经完成”的对话。只有标准、资料和技术链都通过的站点才能作为可用站点发布。

## 16. 实施阶段、优先级与每批交付

不以一次大改上线。每批有明确完成条件，后一批复用前一批能力；全部范围仍属于整体目标，分批不等于长期放弃全库补齐。工期需在语音接口核验和病例差距清单形成后按实际工作量估算，不在未知条件下承诺全部病例几天完成。

| 阶段 | 优先级与依赖 | 具体工作 | 可交付结果与放行条件 |
|---|---|---|---|

先做 B 的代表样板，是为验证同一套契约是否适合不同年龄及病种，不是只交付两三个样板。A/G 的病例账本持续更新，任何未审核的关键临床补全都不因产品进度而跳过审核。

## 17. 验收矩阵：什么叫完成

### 17.1 学生与报告

| 编号 | 场景 | 必须通过 |
|---|---|---|
| R01 | 日常病例完成 | finish 后出现在报告中心，刷新/重新登录仍可见 |
| R02 | 专项完成 | 只评目标能力，未训练环节不扣分；不要求完整接诊 |
| R03 | OSCE 手动/到时结束 | 仅生成一份报告；时限服务端有效；报告名为模拟参考评分 |
| R04 | 题库中断与结束 | 继续同一 attempt；新重练独立；正确率和完成率分开 |
| R05 | 进行中或报告失败 | 显示真实状态，无零分冒充；能继续或重试 |
| R06 | 得分核对 | 所有计分项之和等于总分；不适用/不可评价正确处理 |
| R07 | 负向语义/空提交 | 否定诊断不因关键词得正确分；空处置不自动得安全分 |
| R08 | 证据与补练 | 点击定位真实原文/操作；带正确病例与目标进入兼容专项 |
| R09 | 旧数据 | 历史分不重算；缺字段如实标记；immersive 显示准确 |
| R10 | 趋势 | 过程完成度、题库正确率、临床分不混平均，版本和提示有标记 |

### 17.2 语音、角色与人物

| 编号 | 场景 | 必须通过 |
|---|---|---|
| V01 | 全部交流入口 | 完整病例、交流专项、OSCE、immersive 的适用环节使用同一套语音链 |
| V02 | 真实设备 | 桌面浏览器和至少一台实际手机录音、转写、确认、回复、播报成功 |
| V03 | 权限/无声/断网 | 明确提示且能文字继续；不重复消息、不误扣分 |
| V04 | 取消/离开/后台 | 麦克风确实停止，旧响应不会追加到新会话，不泄漏 objectURL |
| V05 | 家长通话 | 状态与实际一致；纯模拟标识；语音与文字互通、结束后有报告 |
| V06 | 不能言语患儿 | 普通问答、干预、沟通、宽泛提问、模型成功及失败都不输出患儿语义台词 |
| V07 | 正常儿童/青少年 | 表达符合个体能力，不统一幼儿语气；家长不机械抢答 |
| V08 | 事实一致 | 换问法、追问、刷新、长对话均不改变固定病史，不跨病例取资料 |
| V09 | 人物匹配 | 每例年龄/性别/体位符合配置；跨体位人物一致；未知不猜 |
| V10 | 技术故障 | OSCE 技术异常可识别；ASR 错误可修正；TTS 失败不重跑问诊 |

### 17.3 班级、教师与内容

| 编号 | 场景 | 必须通过 |

| L01 | 视频发布播放 | 使用已有上传成果，授权账号桌面/手机真实播放；不以文件已上传替代播放验收 |

| L03 | 进度 | 本人可续播，不能覆盖他人进度；观看不等于能力得分 |
| T01 | 教师首页 | 真实班级、空态、异常态与权限态准确，所有入口可用 |
