# 儿童骨骼模型接入说明

## 2026-10-20 逐结构核查后的纠正

当前状态以 [逐结构核查报告](anatomy-audit.md) 和 [机器证据](anatomy-audit.json) 为准。模型不是逐骨齐全、已医学审定的儿童教学图谱。下面较早的“完整骨架”仅指动画复原状态，现已改为“原位骨架”，不得理解为解剖结构齐全。

源部件及 GLB 核查覆盖 133 个骨材料部件定义；保留的 73 组源表面到 101 个导出网格逐三角面一致，没有发现这些保留源组在拆分中新增/丢失三角面。35 对 2D/3D 表示的去重中有 18 对三角面表达不同，虽然省略表示的顶点全部存在于保留表示中，仍不能未经复核声称表面完全相同。另有 23 个参考/连接片及 2 个空源部件分别记账，不当作遗漏骨头。没有独立标识的结构不能从名称搜索直接断言整体几何完全不存在。

桡骨使用原始 `landmarks_ISB.k` 的左右茎突节点确认，现转换脚本直接用源地标识别，替代横向坐标推测；生成的 GLB 与之前 SHA-256 相同，未变形或添骨。骨盆命名仍为空间规则推断，界面明确提示待复核。手足合并、颅骨材料层、仅第1—11肋的覆盖范围均已显示。

`python -X utf8 scripts/audit-anatomy-completeness.py --source outputs/piper-child` 可复查并生成报告/摘要，不执行转换、不写模型资产。重新执行转换时源码包会包含当前转换脚本；源码包改变不代表骨骼几何改变。新模型摘要必须与 GLB 指纹一致且技术核查通过，界面才显示已有核查证据。

下一阶段优先取得有年龄、许可、专业标注依据的儿童逐骨资产，对缺项和待分割结构逐项复核；AI 输出仅作未发布草稿，不自动写入教学真值。本轮不补造第12肋、手足小骨或其他缺项，也不把成人模型缩小冒充儿童。

本轮技术验证：核查脚本可复现；`pnpm validate` 288 项通过、4 项真实 AI 测试按条件跳过；`pnpm build` 通过；构建产物在本地 `node dist/server.js` 运行后，390/768/1440 浏览器回归通过，确认“原位骨架”和覆盖不完整说明正常显示，平铺/复原/选取及异常恢复仍有效。没有新增骨骼几何、医学审定或线上发布。

## 2026-10-20 当前交互更新

本轮将原来的径向散开替换为“完整骨架 ↔ 分区平铺”的平滑动画，参考本机汽车实验室的逐部件目标位置和逐帧插值思路。新增一键平铺、完整骨架、适配全景；滑杆仍可观察中间状态。按实际包围盒排版，八区域分别排列，自动适配手机/桌面的相机；选择区域后重新排版并放大，选中结构可高亮、聚焦和隔离。

本轮开始前工作区已有 schemaVersion=2 的模型、清单、转换脚本和源码 ZIP 改动（101 个网格）。这些资产作为输入保留，本轮没有重新生成、替换或改写它们。下文 2026-10-14 的 131 网格描述属于初版记录，不作为当前计数。当前 UI 将 101 个网格组织为 79 个展示结构：同一长骨骨干/骨骺等一起移动，保持内部相对位置；颅骨材料层单独注明不是独立骨头，手足合并结构如实保留。

渲染在源场景副本上仅做全局等比单位归一和结构平移，不修改共享几何顶点、不逐骨缩放、不补造骨骼。完全平铺后各展示结构的正面包围盒无交叠，结构中心位于同一展示平面；原有三维厚度保留，平铺不代表解剖位置或生理运动。复原返回原始布局。尊重 `prefers-reduced-motion`；动画期间按需请求帧，结束不持续播放。

当前 v2 清单中已有的源连通分量拆分和自动命名不等同于专业医学审核。技术测试只能验证资产指纹、分组、几何保持和交互，不能证明每个骨的医学标签、覆盖完整性及教学适用性零错误。正式教学前需由儿科/解剖专业人员复核，尤其源模型分组、拆分命名和未逐骨细分部分。

代码：`src/domain/anatomy-structures.ts`（来源分组与范围说明）、`src/lib/anatomy-layout.ts`（包围盒平铺与镜头距离）、`src/components/anatomy-scene.tsx`（逐帧动画、选取和相机）、`src/components/anatomy-lab.tsx`（操作与结构导航）。

验证：`pnpm validate`、`pnpm build`；布局专项 `tests/anatomy-layout.test.ts` 使用真实 GLB 包围盒验证全部/单区域/单结构、不同宽高比下的非重叠、尺寸保持和镜头包含范围。真实浏览器脚本 `python scripts/verify-anatomy-ui.py --base http://127.0.0.1:8772` 使用本地合成身份，检查 390/768/1440 宽度、WebGL 展开/复原像素、点选/隔离/聚焦/搜索/缩放、404 重试、上下文丢失恢复及无 WebGL 明确失败。执行结果以 `outputs/anatomy-verification.json` 为准，不能由本段命令清单推断已通过；不涉及线上授权、发布或医学验收。

## 2026-10-14 初版来源与筛选

用户明确要求儿童骨骼，不接受成人模型替代。GitHub 检索找到 React Three Fiber 项目 [3D-Human-Skeleton](https://github.com/vincentgg6886/3D-Human-Skeleton)，参考提交 `2ff63803e768a2b67b283944b3a317c574fd5d88`，其成人骨骼资产不纳入本项目。参考其 Three.js 交互路线，复用本项目现有 React Three Fiber/Drei 依赖进行最小接入，没有复制整套成人病例、病理模拟或全站架构。

最终资产来自 [PIPER Child](https://www.piper-project.org/child) 官方开放研究项目：[源码](https://gitlab.com/piper-project.org/child)，固定提交 `6aeee0cec84570e1455f797ac49e4721eb89fdee`，`PIPER_ChildModel_6YO` 原始年龄字段为6。该模型面向生物力学研究，并非逐块完整儿童解剖教学图谱。我们仅提取其骨骼表面，没有进行年龄变形、比例缩放冒充不同年龄、患者建模或碰撞模拟。

另一个名为 Child Skeleton 的 Sketchfab 候选自述为首次雕刻作品，没有医学审核和年龄证据，因此未采用。现有页面不加载 Sketchfab iframe、成人资产或第三方热链。

## 转换与范围

`scripts/convert-piper-child.py` 从上游 part 名称中的 `_BO_` 选择骨骼材料，按定义自动收集相应网格文件，包括 `mesh_PIPER_Body.k`、`main_Head_Skull.k`、`main_Neck.k` 及 `main_Head_Brain.k` 中的颅骨内板。此前手工列三个文件会遗漏内板，本次改为按骨骼定义收集，记录各源文件SHA256。转换前验证原始年龄为6、拒绝重复部件及冲突节点坐标。壳单元三角化；无壳表面的实体提取外边界；转换毫米/Z-up到米/Y-up。仅对相邻面抵消形成的零法线选择有效面法线，不更改顶点或骨骼比例。源模型中的骨骺、骨干等网格仍分开，部分前臂、手足等结构原本合并。原始姿势保持，无成人网格和人工补骨。

产物：`public/models/anatomy/piper-child-6yo.glb`（约4.7MB），131个网格部件、221978个三角形；`manifest.json` 记录年龄、部件原名、区域、网格来源类别、三角数、源文件指纹及GLB SHA256。131不是人体骨头计数，不宣传“完整206骨”。肋骨按原始编号显示，肩胛骨/锁骨归对应上肢区域；同名骨骼的壳单元/实体表面在列表和选中说明中区分。部件标签对应源网格，骨骺等不作为新的独立骨头。骨缝、软骨、肌肉等未一并提取，不能用于骨龄判读、患者诊断或生理运动模拟。教学命名及适用范围还需要儿科教师审核。

复现：

```powershell
git clone https://gitlab.com/piper-project.org/child.git outputs/piper-child
git -C outputs/piper-child checkout 6aeee0cec84570e1455f797ac49e4721eb89fdee
python scripts/convert-piper-child.py outputs/piper-child
```

转换需要 Python + NumPy，仅用于离线资产制作，生产运行不新增 Python 依赖。不执行外部仓库脚本。

## 界面与架构

原 `anatomy-lab.tsx` 的二维色块和对应CSS已移除。现使用 `anatomy-scene.tsx` 动态加载 Canvas，浏览器加载带清单SHA版本参数的本地GLB，减少更新后旧缓存问题；旋转、平移、双指缩放使用 OrbitControls。支持正/背/侧视角、重置、八区域显示、名称/编号搜索、单部件高亮及隔离、聚焦所选、显式缩放按钮和0–100%结构分离。聚焦根据选中部件包围球及当前视口比例设置相机；重置恢复完整视图及搜索。单部件模式点空白会恢复区域显示，不会陷入全空且无恢复按钮的状态。结构分离只是显示位移，不改变骨骼几何，不表示医学上的关节活动。加载错误、WebGL不可用与上下文丢失都有明确错误状态；网络重试及上下文重建可恢复，不生成虚假占位骨骼。

按需渲染，DPR上限1.5，无新运行库（仅补显式 `@types/three` 开发依赖）。模型缓存共享几何，交互副本材质退出时释放。身份门控和API未变。
