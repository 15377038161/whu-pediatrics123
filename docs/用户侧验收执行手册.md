## 〇、凭据安全注入约定（所有节通用，先读）

1. **绝不在聊天/文档中粘贴密码、token、验证码**。凭据只存在于您本地。
2. 受控凭据文件方式（推荐）：在您本地终端创建 0600 权限 JSON 文件，例如：

   ```bash
   # 仅示例路径；文件内容 {"email":"...","password":"..."}，用后删除
   chmod 600 /tmp/.student-a.json
   ```

   脚本以 `--cred-file <文件>` 读取；权限非 0600 时脚本直接拒绝（fail-closed）。
3. 环境变量方式（部分脚本支持）：`PEDIATRICS_TEACHER_EMAIL` / `PEDIATRICS_TEACHER_PWD`。
4. **只使用既有且经授权的账号**：脚本与流程一律不新建账号、不改密码、不 signup。
5. 验收完成后删除本地凭据文件；如涉及探针账号临时会话，可用工程侧撤销脚本收尾（`scripts/revoke-speech-browser-probe-session.ts` 同模式）。

**证据回传统一格式**（每项验收按此填写回传）：

| 字段 | 说明 |
|---|---|
| 验收项编号 | 如 V02 |
| 执行步骤 | 手册中的步骤号 |
| 设备与环境 | 设备型号 / 浏览器及版本 / 网络（如：iPhone 12，Safari 17，Wi-Fi） |
| 时间 | 精确到分钟 |
| 证据 | 截图（含地址栏 URL 与页面状态）、录屏、或终端输出/退出码 |
| 结果 | 通过 / 不通过 / 异常说明（异常时描述现象与复现步骤） |

## 一、V02 真实设备语音（桌面 + 真实手机）

**通过标准**：桌面浏览器和至少一台实际手机上，录音、转写、确认、回复、播报五个环节成功。

**前置**：部署站点在线；受控学生账号一枚；设备麦克风可用。

### 桌面浏览器步骤
1. 登录学生端 → 进入训练 → 选择病例建立会话。
2. 确认语音入口可见（服务端 `/api/speech/capabilities` 三段探测通过时才显示；看不到语音按钮请先截图并记录，这是有效证据而非失败）。
3. 点击语音输入 → 授权麦克风 → 说一句话（如「哪里不舒服？什么时候开始的？」）→ 结束录音。
4. 查看转写文本 → 确认或编辑 → 发送。
5. 等角色文字回复 → 确认播报（角色语音按队列播放）。
6. 每步截图（含地址栏与状态提示）。

### 真实手机步骤（至少一台实际手机）
1. 手机浏览器打开站点 → 登录同一受控学生账号。
2. 重复桌面步骤 2-5。
3. 另检查 390px 窄屏下语音 UI 不溢出、按钮可点（截图竖屏全页）。

**工程侧已就绪**：语音链实现（录音→ASR→确认→发送→TTS→队列播报）、音色映射、能力探测路由；沙箱内合成身份路由测试与 SDK 真实调用链路已验证，仅缺真实麦克风与手机。

## 二、V03 权限/无声/断网异常路径

**通过标准**：三种异常下明确提示且能文字继续；不重复消息、不误扣分。

1. **拒绝麦克风权限**：浏览器弹权限框选「阻止」→ 页面出现明确提示 → 仍可用文字输入继续问诊。
2. **无声录音**：静音环境下录音并结束 → 出现「未识别到语音」类明确提示 → 可重试或改文字。
3. **断网**：发送语音/文字瞬间断网（可开飞行模式模拟）→ 明确失败提示 → 恢复网络后继续，消息列表**无重复消息**。
4. 核对最终报告：异常轮次不进入能力评分扣分项（报告只评价确认后的语义内容，语音速度/口音/ASR 错误不扣分为设计约定）。

**证据**：每场景截图 + 异常前后消息列表对比截图 + 报告截图。

## 三、V04 取消/离开/后台

**通过标准**：麦克风确实停止；旧响应不会追加到新会话；不泄漏 objectURL。

1. **录音中取消**：录音进行中点取消 → 浏览器标签页麦克风指示灯熄灭（截图含指示灯）。
2. **切后台/离开页面**：录音或播放中切后台或离开 → 返回后麦克风已停止；播放队列不自动续播旧音频到新会话。
3. **换会话**：结束当前会话后新建另一病例会话 → 旧会话的角色音频不追加进来。
4. **objectURL 检查（可选，技术向）**：DevTools Console 中确认临时 blob URL 在播放结束后被 revoke（无累积的 blob: 残留）。

**证据**：指示灯截图、跨会话消息列表截图、（可选）Console 检查截图。

## 四、V05 家长通话

**通过标准**：状态与实际一致；纯模拟标识可见；语音与文字互通；结束后有报告。

1. 选择含家长沟通专项的病例 → 进入模拟通话界面。
2. 确认界面显示「AI 模拟通话」徽标（不伪装成真人来电）。
3. 确认按轮录音的如实状态提示（界面不显示虚假的「持续聆听」）。
4. 用语音完成一轮解释沟通（录音→转写确认→发送），再用文字完成一轮（语音与文字互通）。
5. 点「结束通话」→ 确认弹窗文案（已完成有效沟通轮与未完成时文案不同）→ 生成专项报告。
6. 截图：徽标、按轮状态、两种输入方式的消息记录、结束确认、专项报告。

## 六、E03 真实多身份

**通过标准**：管理员、教师 A/B、学生 A/B 的允许/拒绝路径全部走通；使用既有账号，凭据受控。

### 身份与允许路径
| 身份 | 允许路径 | 验证方式 |
|---|---|---|
| 管理员 | 平台管理通道（教师授权维护） | 按平台管理通道既有流程 |
| 教师 A / 教师 B | 登录 → 教师端工作台、病例工作室、班级管理、督导只读 | 登录后截图 + 访问 `/teacher` 正常渲染 |
| 学生 A / 学生 B | 登录 → 学生端训练、资源、报告 | 登录后截图 + 访问 `/student` 正常渲染 |

### 拒绝路径（负例必测）
1. 学生 B 以学生 A 的会话 id 请求 `POST /api/speech/tts`（{sessionId, messageId}）→ 预期 403（归属拒绝）。
2. 学生 A/B 访问教师端路由（如 `/api/teacher/case-publication`）→ 预期 401 或 307 回跳学生端。
3. 教师 A 读取教师 B 班级学生明细（跨教师范围，若已配班级边界）→ 预期拒绝。
4. 评委预览链路（可选回归）：教师预览→退出→学生预览登录、反向链身份稳定（此前已验收过的域名链路，回归确认即可）。

**凭据注入**：各身份分别用本地 0600 凭据文件或平台正规登录通道；**不新建账号、不改密**。

**证据**：每身份登录成功截图（含姓名/角色标识）；每拒绝路径的响应截图或状态码记录。
