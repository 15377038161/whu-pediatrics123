# 报告与标准病历的读取边界

2026-10-28，本地实现，尚未部署。依据当前接诊闭环及后续病历书写验收要求。

此前来源病例把整段来源诊断、诊疗经过作为零分对照项写入报告，学生结束、报告列表和详情均能收到。标准底稿虽然没有公开下载，报告仍暴露了其中的答案章节。这与后续病历书写训练的答案门控不一致。

现在保留原报告存储、成绩、提交和教师受控读取；学生响应通过 `projectReportForRole` 移除 `SOURCE_DIAGNOSIS_REFERENCE`、`SOURCE_PLAN_REFERENCE`，保留实际操作证据、采集复盘和教学图。finish 首次返回、幂等重取、报告详情及本人列表均执行相同边界。缺项反馈不能因此改为整篇标准答案，也没有把过程分改为临床能力分。

直接调用数据库 RPC 也必须遵守此边界。CLI生成的新迁移 `20261027181036_student_report_answer_projection.sql` 只限定本项目tenant：

- 读取时过滤历史答案，不更新或删除旧报告行。
- `report_get_mine`、`report_list_mine` 继续校验本人；已有函数ACL保持，不增加角色权限或改RLS。
- 使用受控私有投影函数，匿名及authenticated均不能直接执行该辅助函数。
- 教师继续走既有RLS范围直读，不通过学生RPC获得扩大权限。

迁移已在隔离PGlite通过本人、非本人、匿名、列表/详情一致、原行不变及ACL不变检查；这是合成工程验证，不是实际OAuth/RLS多身份验收。生产数据库未执行。最终同步前先只读核对目标tenant和现行两RPC定义/ACL，出现云端差异则保留差异并适配；不得盲目替换或绕平台护栏。

完整标准病例仍在服务端/教师范围保留。独立书写模块及AI完整性检查尚未交付；当前修复不代表全部逐例临床反馈已完成。
