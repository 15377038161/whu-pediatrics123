# 病例知识库最小教师审核结构化导入方案

更新时间：2026-10-09（核验阶段）

## 背景与现状

- SDK 召回（`recall`/`list`）无文档 ID、无全文获取能力（2026-10-08 实测），多查询变体召回是唯一获取途径，快照存在漂移/截断风险。
- 72 项病例入口覆盖状态：**53 独立来源 / 42 知识库直接召回匹配 / 14 别名亚型映射 / 3 无独立来源**（新生儿脑梗死、支气管肺炎、格林巴利综合征，docs/case-knowledge-map.md）。
- 现有基础设施已具备教师审核导入的全部前提：
  - `case_snapshot_facts`/`case_snapshot_answers` 双表持久缓存，教师可写（insert/update 策略，`app_is_teacher()`）；
  - 会话已绑定快照版本号（`sourceSnapshotVersion`），`restoreCaseSnapshotFacts` 按固定版本恢复——教师写入的固定版本天然免疫召回漂移；
  - `case_snapshot_get_reference` 完成态门控已就位（诊断答案不提前泄漏）。

## 最小方案（不新增表、不新增权限）

**原则：教师审核结果以固定版本号写入既有快照表，学生会话绑定该版本后按版本恢复，绕过召回不确定性。**

1. **教师审核写入**（复用既有教师 INSERT/UPDATE 策略）：
   - 教师通过召回多查询取回分片，人工校对五段事实（history/exam/tests/diagnosis/plan）与媒体列表；
   - 以人工固定版本号（如 `teacher-approved-v1`）写入 `case_snapshot_facts` + `case_snapshot_answers`；
   - 版本号不随召回内容变化（与 sha256 内容版本区分），教师修订时升 `v2` 并保留旧版本。
2. **会话绑定审核版本**：
   - 建会话时优先查找 `teacher-approved-*` 固定版本，命中即绑定；未命中再走现有召回+内容版本链路；
   - 已绑定会话不受后续召回漂移影响（现有机制，无需改动）。
3. **运行时行为不变**：
   - 学生侧仍走 `case_snapshot_get_facts`（阶段门控投影），诊断答案走 `case_snapshot_get_reference`（完成态门控）；
   - 无来源病例（D 类 3 项）保持「资料不足」空事实，不编造。

## 覆盖目标与工作量

| 分类 | 数量 | 导入动作 |
|---|---|---|
| A/B 类（有独立来源） | 53 | 逐病例教师审核后写固定版本（每例约一次人工校对） |
| C 类（别名/亚型） | 14 | 复用映射目标病例的审核版本（alias 解析已存在 teacher-case-links.ts） |
| D 类（无来源） | 3 | 明确标注「无独立来源」，仅目录条目，不进训练池 |

本阶段仅输出方案与表结构就绪证明，**未实施批量导入**（需要真实教师逐例审核，非脚本可替代）；3 个无来源病例建议由教师补充原始病例后入库。

## 语音能力核查结论（2026-10-09）

- 平台插件清单（list_plugin）：**空**——无 TTS/ASR 插件；
- 平台任务流清单（list_task_flow）：**空**——无可复用业务任务流；
- 结论与既有记录一致：TTS/ASR 为平台能力缺口，浏览器 `speechSynthesis` 降级不等于内置 TTS 通过。等待平台在官方 SDK（coder-coding-dev-sdk）或插件层面补齐；届时 `/api/tts` 切回服务端统一调用即可。
