> 文档版本：v1.0 ｜ 日期：2026-08-27

> 方法：动线建模 → 最短路径分析 → 模拟用户走查（可用性验证）

## 1. 动线总览

全系统收敛为 **5 条动线**，全部标注于「全局用户动线图」：

| 编号 | 动线 | 起点 → 终点 | 主色 |
|------|------|------------|------|
| F1 | 登录分流 | 落地页 → OAuth → 学生首页 / 教师台 | 蓝 + 绿 |
| F2 | 学生学习主流程 | 首页 → 病例库 → 训练台(8阶段) → 报告 → 补练 ↺ | 蓝 |
| F3 | OSCE 考核流程 | 首页 → 考站 → 训练台(osce) → 时间到/提交 → 报告 | 蓝 |
| F4 | 教师学情流程 | 教师台 → 会话详情 → 返回 | 绿 |
| F5 | 异常分支流程 | 登录失败 / 训练中断 / 时间到 / 空状态 → 回归主线 | 红 |

**设计原则**：每条动线单向无环路（除 F2 的「补练回归」是刻意设计的学习闭环）；任何页面距「返回主线」≤1 步。

## 2. 动线详述（逐步：页面 / 操作 / 触发条件 / 去向）

### F1 · 登录分流（3 步）
| 步 | 页面 | 操作 | 触发条件 | 去向 |
|----|------|------|----------|------|
| 1 | 登录落地页 `3:172` | 点击「进入守护营」 | CTA | 超星 OAuth |
| 2 | 超星授权页（外部） | 确认授权 | 授权成功 | 按角色分流 |
| 3a | — | — | `role=student` | 学生首页 `3:170` |
| 3b | — | — | `role=teacher`（白名单） | 教师学情台 `3:618` |
| 异常 | — | — | 授权失败/超时 | 登录错误页 `3:881` →「返回首页」回落地页 |

### F2 · 学生学习主流程（核心闭环，5 步 + 8 阶段）
| 步 | 页面 | 操作 | 触发条件 | 去向 |
|----|------|------|----------|------|
| 1 | 学生首页 `3:170` | 点击旗舰病例卡 / 病例入口 | 病例已解锁 | 病例库 `3:436` |
| 2 | 病例库 | 点击病例卡「进入病例」 | 选定病例 | 训练台 `3:171` |
| 3 | 训练台 | 完成 8 阶段：问诊(自由输入+AI提示)→查体(热区)→辅助检查(开单)→诊断→处置→沟通 | `FINISH_SESSION` | 报告详情 `3:535` |
| 4 | 报告详情 | 查看六维能力/证据 → 点击「补练」 | `weak=<维度>` 参数 | 专项练习 `3:829` |
| 5 | 专项练习 | 点击任务卡「开始」 | 单阶段短闭环 | 训练台（对应阶段）|

**闭环说明**：F2 的 4→5→3 构成「报告→补练→再训练」学习闭环，这是刻意设计的正向循环，非死循环（每次循环能力分提升）。

**F2 关键修订（V1.1）· 问诊与查体的自由往返**：

真实临床中「问诊」与「查体」是**交织**而非串行的（听诊发现异常 → 回头追问病史）。原「问诊完成才能查体」的阶段锁设计被修订为**自由工作台模型**（画布屏 `3:1409` 训练台·自由往返）：

| 机制 | 设计 | 对应实现 |
|------|------|----------|
| 双工具并行 | 「问诊」「查体」为同屏两个页签，随时互切，无解锁条件 | 智能体容忍乱序（`NAVIGATE_STAGE` 自由跳转） |
| 采集清单替代线性进度 | 「主诉✓ / 肺部听诊✗」清单 + 就绪度百分比 | `askedIntents` / `preparationActions` / `unlockedEvidence` 累积集合 |
| 学生自主推进 | 自认信息足够即可进入诊断；采集不足体现在评分证据 | `ScoreEvidence` 归因，不硬性阻断 |
| 防迷失护栏 | 切换提示条「进度不丢失」+ AI 提示给方向 | 系统提示类消息 |

就绪度 60% 为示例态：清单未满仍可推进诊断（真实临床风险），但报告会标注「信息采集不完整」扣分项——**把约束从交互层移到评分层**，这是复杂动线的通用解法。

### F5 · 异常分支流程（4 条）
| 分支 | 触发 | 界面 | 出路（回归主线） |
|------|------|------|------------------|
| 登录失败 | OAuth 拒绝/超时 | 登录错误页 `3:881` | 重新登录 / 返回首页 → 回 F1 |

| 报告为空 | 新生无报告 | 报告空状态（本轮新增） | 「去训练」直达病例库 → 回 F2 |

## 3. 最短路径分析

| 核心任务 | 优化前步骤（原系统） | 优化后步骤 | 优化点 |
|----------|---------------------|-----------|--------|
| 开始一次训练 | 首页→病例→训练（3 步） | 同 3 步（路径已最短） | 旗舰卡情境化降低选择成本 |
| 看最新报告 | 首页→报告列表→详情（3 步） | 训练完成**直达**详情（1 步） | FINISH 后自动跳转 |
| 针对弱项补练 | 报告→返回→首页→练习→选题（5 步） | 详情「补练」直链（**1 步**） | `weak=` 参数直达对应维度 |
| 教师查看学生 | 登录→学情台→详情（3 步） | 同 3 步 | 顶部搜索直达 |
| 从错误中恢复 | 无明确出路 | 任何异常态 ≤1 步回主线 | 四类异常态全配置出路 |

## 4. 动线可用性验证（模拟真实用户走查）

### 4.1 Persona A · 新生「小李」首次使用
```
落地页(读主张5s) → 点击进入守护营 → 超星授权 → 学生首页
→ 底部导航点「报告」→ 空状态页（无报告）→ 点击「去训练」→ 病例库
→ 选「小宇」病例 → 训练台 → 问诊不知问什么 → 点「AI 提示」→ 获得方向 → 继续问诊
→ 完成 8 阶段 → 报告详情（86 分）→ 点击「补练·沟通」→ 专项练习
```
**走查结论**：
- ✅ 无死路：空状态给了出路；AI 提示解决了「不知问什么」的冷启动困惑。
- ✅ 无阻塞：全程每步均有明确唯一主操作。
- ⚠️ 发现 1：新生首屏的「病例库」与「旗舰卡」双入口略重复 → 已通过旗舰卡情境化弱化冲突（保留双入口但层级分明）。

### 4.2 Persona B · 备考学生「小张」模拟 OSCE
```
首页 → 考核入口 → 考站阅读 4 条规则 → 开始考核
→ 作答至 7:50 时被电话打断 → 返回 App → 训练中断确认弹层
→ 点「继续训练」（考核不中断，计时持续）→ 倒计时归零
→ 时间到页（自动交卷说明）→ 查看报告
```
**走查结论**：
- ✅ 逻辑一致性：OSCE 模式中断弹层**不暂停计时**（与真实考试一致），弹层文案已注明。
- ✅ 无矛盾：时间到自动交卷不可逆，但时间到页明确说明「已自动提交」消除困惑。
- ⚠️ 发现 2：中断弹层若在 OSCE 模式出现「保存进度」文案会产生误导 → 规范：OSCE 模式弹层文案改为「离开将不会暂停计时」。

### 4.3 Persona C · 教师每周巡检
```
登录（role=teacher 分流）→ 教师学情台 → 浏览班级统计
→ 搜索「小李」→ 点学生卡 → 会话详情（轨迹+证据）
→ 复核争议评分 → 返回学情台
```
**走查结论**：
- ✅ 闭环：查看→复核→返回，单向动线无绕路。
- ⚠️ 发现 3：会话详情为源码模块、画布未出独立屏 → 列入后续补屏（不影响动线逻辑验证）。

### 4.4 阻塞/矛盾/困惑检查表
| 检查项 | 结果 |
|--------|------|
| 每页均有 ≥1 个明确出路 | ✅ 18/18 屏通过 |
| 异常态均有回归主线出口 | ✅ 4/4 异常态通过 |
| 无「点了没反应」的死角按钮 | ✅ 动线图上所有节点均有出边 |
| 角色权限边界（学生不见教师功能，反之亦然） | ✅ 分流唯一入口 |
| 数据状态衔接（训练完成→报告就绪） | ✅ FINISH_SESSION → 报告直达 |
| OSCE 计时与中断逻辑 | ⚠️ 文案需按发现 2 调整 |
| 补练闭环 vs 死循环 | ✅ 有分数提升预期，非死循环 |

## 5. 验证结论

1. **功能链路闭环完整**：学生学习（训练→报告→补练→再训练）、OSCE 考核、教师巡检三大链路均为闭环，无断链。
2. **最短路径达成**：核心任务全部 ≤3 步；补练从 5 步压缩至 1 步。
3. **异常态全覆盖**：登录失败/训练中断/OSCE 超时/报告为空四类异常均有明确出路，且 ≤1 步回归主线。
4. **整改项**（2 项，均为文案级）：
   - OSCE 中断弹层文案改为「离开将不会暂停计时」；
   - 首页保持旗舰卡唯一 L0，病例库入口降为 L2 层级。
5. **遗留项**（1 项）：教师会话详情独立屏待补绘（动线逻辑已验证无碍）。
