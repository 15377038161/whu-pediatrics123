# 病例接诊闭环与后续病历书写验收补充

日期：2026-10-27。依据：本聊天用户最新确认。本文记录目标和新增验收要求，不代表功能或全库验收已经完成。

## 1. 每个病例要交付的接诊体验

从资料卡进入同一个固定版本病例，经历问诊、查体、辅助检查、诊断鉴别、处置沟通、结束及复盘。所有实际展示的按钮、部位、面板及训练模式逐项核对：有对应操作、真实状态和与本病例一致的信息，不能只有能点击的空壳。原件确有材料却未绑定/未显示，按系统缺陷处理，不能写成“病例没提供”。

每例登记全部资料与适用检查。检查结果应区分项目、数值或文字所见、单位、时间点及原图；年龄适用参考范围有依据才填写，不套成人范围、不凭空补正常。未做、不适用、未知、待回报与系统加载失败分别呈现。不能为了让每个按钮“有值”虚构结果；关键资料仍缺时保持未完成并继续补齐。

资料卡的年龄、性别、主诉、形象与会话中一致。不能言语患儿由照护者提供病史，不输出患儿语义台词。全部70入口（独立病例、别名、亚型、无原件入口）分别覆盖，不拿一套通用病例的流程代替逐例内容。

## 2. 学生得到的反馈必须具体

结束后告诉学生：漏问了什么、漏做或误做什么、哪些已有指标没有识别或解释、诊断依据哪里不足、鉴别缺哪条依据、处置及沟通有哪些待补。反馈关联学生真实问答、操作、检查及提交的事件，不仅给总分或“已经完成”。

逐病例建立必要信息/操作/证据与评价项的对应关系，区分未采集、已采集未写、写错、证据不足及不适用。学生无法获得的信息不能成为要求其猜答案的计分点。没有充分判据的质量结论记无法评价/待复核，不用按钮次数、关键词命中或提交非空冒充能力评价。

当前源码中的来源病例报告主要仍按六环节记录是否完成；这不足以证明已实现上述逐例漏洞分析。补充评价规则与专业判据是待办，不能宣布全库反馈已经完整。

## 3. 服务端标准病历与答案边界

每例要有一份服务端/教师可读取的完整标准病历或明确标识的教学模拟标准，覆盖主诉、现病史、相关既往/个人/家族等病史、查体、辅助检查、诊断依据/鉴别、处置及时间线；字段按教师模板及病例适用性配置。原始事实、未知和教学设定分开标记。

学生通过接诊逐步获得可以释放的信息，不能直接打开、下载或从接口/资源/页面源代码获得完整标准病历。完整病历也不能在结束报告中直接整篇泄露。反馈应给出缺项和依据，不以整份标准答案代替训练；现有诊断/处置对照与未来写病历任务的答案释放时点须一并核对，避免学生在书写前直接照抄。

标准病历、公开资料卡、角色事实、图像/检查结果、评价依据与学生会话绑定同一来源版本。修订产生新版本，旧会话及旧提交不换成新病历。

## 4. 后续独立病历书写模块（新增规划，尚未实现）

这是用户明确提出的后续模块，不声称本轮已经交付：

1. 学生从指定病例接诊后，进入独立的病历书写入口，依据本次获得的信息填写病历；保存草稿、恢复及提交版本。
2. 学生病历绑定本人、病例入口、会话与标准病历版本，保留提交原文；教师只能在既有授权教学范围内查看。
3. AI辅助检查完整性、事实一致性、时间线及逻辑、遗漏和表达不足；建议必须引用学生已写内容或本例可获得的证据，区分漏采与漏写，不编造检查结果或临床结论。
4. AI审阅作为独立辅助反馈，保留所用标准/提示词版本与依据。规则检查与AI不可评价/失败明确区分，不因服务异常给零分或全缺。
5. 教师可查看学生提交与AI意见，不恢复已取消的任务发布/教师改分流程。AI完整性审阅不自动冒充医学审核，也不据此改写既有历史临床成绩。
6. 教师病历模板及具体完整性量表在进入模块实施前确认；当前不猜一个院校模板并据此给学生扣分。

## 5. 完成的证据

逐例保存资料卡、每个可见入口和操作、适用指标/图片、结束反馈、标准病历不泄露、报告及刷新恢复的证据。工程fixture、隔离Postgres或合成浏览器只是工程层；实际学生入口和真实材料流程另验。
