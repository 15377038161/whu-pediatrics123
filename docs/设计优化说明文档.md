## 2. 设计系统规范（Design Tokens）

> 画布中对应「设计系统规范」屏（`3:670`），含颜色 / 字体 / 组件 / 响应式四块看板。

### 2.1 色彩
| 角色 | 色值 | 用途 |
|------|------|------|
| Primary（主色） | `#4EB7E8` | 主按钮、步骤激活、链接、品牌 |
| Secondary（辅色） | `#80D88C` | 成功态、进度、正向反馈 |
| Accent（强调） | `#FFD66B` | 徽章、提示高亮、装饰 |
| Warm（暖色） | `#F2A93B` | 告警、限时、重要强调 |
| Ink（墨色） | `#2A2F3A` | 正文、标题 |
| BG（背景） | `#F5FAFF` | 页面底色、卡片留白 |
| 危险/低分 | `#E26D6D` | 失分、错误、告警 |

**规则**：主色用于「前进/确认」；暖色仅用于「告警/限时」等高张力场景，避免滥用；同屏主色+辅色不超过 2 个高饱和色。

### 2.2 字体
- 字体族：**Inter**（英文/数字）+ 系统中文（PingFang / 思源黑体回退）。
- 字号阶梯：Display 28 / H1 22 / H2 18 / Body 15 / Sub 13 / Caption 11。
- 字重：Regular 400 / Medium 500 / Bold 700。
- 行高：标题 1.3，正文 1.5。

### 2.3 圆角与间距
- 圆角：卡片 16、按钮 12、标签 8、头像全圆。
- 间距：4 基准栅格（4/8/12/16/24/32）。
- 阴影：卡片 `0 4px 16px rgba(42,47,58,0.06)`；浮层 `0 8px 32px rgba(42,47,58,0.12)`。

### 2.4 组件库（核心）
| 组件 | 规范要点 |
|------|----------|
| 顶部栏 | 左返回/标题，右等级徽章；高度 56，安全区适配 |
| 病例卡 | 左患儿头像 + 右 meta（难度/时长/模式标签）+ 进度条 + 主操作 |
| 步骤指示器 | 6–8 段，已完成✓ / 进行中(主色脉冲) / 未达(灰) |
| 对话气泡 | 学生右(主色)、患儿/家长左(灰)、系统提示居中(浅色条) |
| 主按钮 | 主色实底白字；次按钮描边；禁用态降透明度 |
| 标签 Badge | 圆角 8，浅底深字，用于难度/模式/状态 |
| 评分条 | 六维横向条，达标绿 / 未达红，配分值 |
| 底部导航 | 学生 4 项 / 教师 3 项，图标 + 文字，激活主色 |

### 2.5 响应式断点

## 4. 关键交互优化（对应测试痛点）

### 4.1 训练台问诊区：选择题 → 自由输入 + AI 提示（高优先级）
- **优化前**（测试痛点 🔴）：问诊以预设选项为主，学生无法自主组织语言。
- **优化后**：
  - 学生以**自由文本输入框**发起询问，气泡右侧上屏（主色）。
  - 输入框内嵌 **「AI 提示」按钮**（浅蓝底），点击在对话区插入 scaffolding 提示（如「可从发热时长、峰值体温、伴随症状切入」），**不替学生作答**，仅给方向。
  - 家长/患儿以真实对话风格回应（含情绪 `Emotion`），训练共情与追问。
- **画布体现**：`3:171` 问诊区已改为自由问诊文本 + `3:434`「AI 提示」按钮。

### 4.2 首页旗舰关卡卡：情境化（中优先级）
- **优化前**：旗舰卡信息堆砌显「突兀」。
- **优化后**：改为**情境化病例卡**——患儿 SVG 头像 + 渐变蓝绿底色 + 进度条 + meta 标签（时长/难度/模式）+ 白色底蓝字「进入病例」主操作，与整体童趣风融合。
- **画布体现**：`3:170` 中 `3:406` 旗舰关卡卡。

### 4.3 报告详情 → 专项练习闭环
- 报告详情「补练」按钮直链 `/student/practice?weak=<能力维度>`，把建议转化为可执行任务（对应测试痛点 🟠）。

### 4.4 教师学情台：群体洞察
- 顶部统计下新增「班级共性短板」洞察卡（如「本班沟通均分偏低」），让教师快速定位干预点。

### 4.5 OSCE 考站：规则强化 + 演练缓冲
- 4 条规则以**图标卡**呈现（限时自动提交 / 全程无提示 / 可解释评分 / 异常不丢记录）；开始前增加「模拟演练 / 确认规则」缓冲页。

### 4.6 登录态引导
- 落地页增加「登录态感知」：已登录显欢迎、未登录高亮登录入口，避免受保护路由重定向造成的「页面坏了」错觉。

### 4.7 问诊与查体自由往返（`3:1409` 训练台·自由往返屏）
- **问题**：真实临床问诊与查体是交织的（查到体征→回头追问病史），线性阶段锁不成立。
- **方案**：双工具页签并行互切 + 采集清单/就绪度替代线性进度 + 学生自主推进（约束移到评分层：采集不足在报告证据中扣分，不硬阻断）。
- **依据**：`SessionState` 的 `askedIntents`/`preparationActions`/`unlockedEvidence` 为累积集合，数据模型天然支持非顺序采集。

## 5. 设计标注说明（开发落地约定）

### 5.1 标注维度
- **间距/尺寸**：以 4 基准栅格标注，组件间用 8/12/16/24。
- **颜色**：所有色值引用 §2.1 设计 Token，禁止硬编码非规范色。
- **字体**：引用 §2.2 字号阶梯与字重，移动端正文不小于 15。
- **状态**：每个可交互组件标注 normal / hover / active / disabled / empty 五态。
- **文案**：所有中文文案以设计稿为准，开发不擅自改写。

### 5.2 图标与插画
- 患儿头像、守护精灵、ECG 等使用 **SVG 矢量**（已在画布内联），导出时单独切片。
- 禁止在画布使用 emoji（部分渲染环境不显示），统一以矢量或文字替代。

### 5.3 动效约定
- 步骤切换：200ms 缓动；AI 提示插入：120ms 淡入；限时倒计时：最后 30s 暖色脉冲告警。

## 7. 响应式适配方案

- **Mobile（<700）**：单列 App 流，底部导航常驻，390 基准；对话/表单全宽，避免横向滚动。
- **Tablet（700–1023）**：病例库/报告列表转双列网格；训练台保留单列对话但加宽留白；侧边可收起。
- **Desktop（≥1024）**：左侧固定导航（图标+文字），右侧主工作区；首页采用「病例网格 + 能力卡」双栏；训练台可扩展为「左患儿/右对话」双面板，提升信息密度。
- **统一约束**：所有断点下主色/字体/圆角/间距严格引用 §2 Token；断点切换不出现布局错位或文字截断。

## 8. 开发落地建议

1. **先落地设计系统**：把 §2 Token 写入 `globals.css` 的 CSS 变量与 Tailwind 主题，组件统一引用，杜绝散落硬编码。
2. **组件优先**：按钮、病例卡、步骤条、对话气泡先做成共享组件，再拼页面。
3. **交互难点前置**：训练台「自由输入 + AI 提示」与 OSCE 限时交卷是交互最复杂处，建议先做原型联调。
4. **数据驱动可视化**：六维能力、证据卡、教师群体洞察均直接消费 `TrainingReport` / `SessionState`，无需另建数据层。
5. **分阶段交付**：移动端 13 屏 → 分支/异常态与动线图 → 桌面适配 → 动效打磨。
