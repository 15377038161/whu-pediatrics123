## 未完成 / 未验证项（如实声明）


1. **53 来源/67 项完整覆盖未验证**：召回验证只证明「库可检索」，42/70 直接匹配 + 14 别名映射 ≠ 全量病例正文可取。尚需按 72 项清单逐项核验「正文可取 / 媒体可取 / 训练可用」三态并记录证据。
2. **快照持久化未实现**：当前为进程内 Map 缓存，TTL 10 分钟，服务重启后病例事实需重新召回——召回结果可能因 topK/排序变化而与上一次不同。会话未绑定固定快照版本，存在「同一会话前后患者事实漂移」风险。计划：内置数据库持久缓存表 + 会话绑定快照版本号。
3. **多患者混拍风险未消除**：召回按「病例名」匹配，同名病种多个住院记录可能混合；当前无「精确来源文档 ID + 同一患者记录匹配」校验。缺失必填事实时保持「资料不足」，未默认年龄/性别/体征（已实现）但完整性与出处逐项校验未实现。
4. **SDK 全文/文件获取能力——已核验，不支持**（2026-10-08 实测）：`KnowledgeClient` 仅暴露 `recall`（返回分片的 `title`/`content` 两字段，**无文档 ID**）与 `list`（仅知识库元数据：id/baseName/description/creator 等）。SDK 无按文档 ID 获取全文、无文件下载接口。因此 topK 多查询召回是唯一获取途径，**这不等于全文导出**：影像册分片可能被截断、正文分片顺序不保证。当前缓解：多查询变体（4 个）+ sha256 去重 + 分段解析；根治需平台侧提供「按文档 ID 取全文」能力。召回阈值当前 0.2，不再通过继续调低阈值宣称提升覆盖率。
5. **3 系统完整训练流程未验收**：启动→问诊→查体→检查→诊断→报告 的完整链路仅做过单点验证（问诊/查体/辅检各一次 200），未做 3 个不同系统病例的全流程记录。
6. **正式 A/B JWT 验收未完成**：此前安全验收已用真实邮箱用户完成，但本轮新增的 resources 收紧、快照链路尚未用真实用户 JWT 做数据库持久化与 RLS 业务复测（当前用 preview 会话验证了路由层）。
7. **题库未移植**：43 题在 main 分支（ff9ae74），当前分支无 quiz 代码。数据库 quiz 表存在且本租户策略干净（4 条合理策略）。
8. **平台内置超星 OAuth 主入口未实现**：平台代理 exchange 契约已读（/v1/api/coder/proxy/auth/chaoxing-oauth/exchange），代码未实现。邮箱登录仅为安全测试通路。
9. **TTS/ASR 未实测**：/api/tts 未配置凭据时返回 TTS_UNAVAILABLE，内置语音能力未验证。
10. **移动端 390px 交互验收未做**。
