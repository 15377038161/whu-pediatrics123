# 教师学生使用统计——现状定位与下一阶段实施清单

定位时间：2026-10-11
性质：只读定位（不实施）。用户已授权使用统计需求，按单一任务原则，待病例任务结束后再按本清单实施。

## 一、现有实现定位（真实代码位置）

### 数据表（supabase/migrations/202608230001_pediatrics_agent.sql 及后续迁移）

| 表 | 关键列 | 与统计的关系 |
|---|---|---|
| `training_sessions` | user_id/cohort_id/case_id/case_version/mode/stage/status/state(jsonb)/started_at/updated_at/expires_at | 训练明细主表：访问/训练时间、病例、模式、阶段、完成状态 |
| `training_messages` | session_id/actor/content/message_kind/created_at | 轮次（对话轮）计数来源 |
| `clinical_operations` | session_id/client_event_id/event_type/stage/payload/result/created_at + **unique(session_id, client_event_id)** | 事件表；唯一约束已天然提供**幂等去重** |
| `agent_call_records` | session_id/client_event_id/execution/duration_ms/created_at + unique | 调用耗时，可做错误/降级（model_fallback）统计 |
| `training_reports` | session_id/user_id/case_id/mode/total_score/status/created_at；data 含 rubricId/rubricVersion、逐项 evidence(status/score) 与原始提交快照 | 完成率、题库记录、练习成绩（**非可信正式成绩，须标识**）；总分=计分项之和、适用满分=可评价计分项满分之和（`not_assessable`/`not_applicable` 不进分母）；量表 v4（2026-10-21）起旗舰「家长沟通」项与沟通专项全部项、查体专项「结果识别」恒记无法评价——命中表述仅记候选/过程反馈，原文冻结在提交快照待教师复核 |
| `profiles`/`cohorts`/`cohort_members` | display_name/student_no/角色 | 学生去重、教师数据范围 |

### 教师权限（复用，不新增）

- RLS：`app.is_teacher_for_user()`（teacher_emails 白名单 + 同 cohort 教师），`sessions_owner_or_teacher_read` 等 policy 放行教师读学生数据（migrations L199-247）
- 应用层同源判定：`src/lib/case-draft-import.ts` 的 `isTeacherByWhitelist()`（RPC `app_is_teacher`，fail-closed）
- 路由守卫：`src/lib/request-auth.ts` 的 `requireAuth(request, 'teacher')`（服务端身份，不信任客户端声明）

### API 与仓库层

- 学生：`/api/sessions`、`/api/sessions/[id]`、`/api/reports`、`/api/reports/[id]`（`AgentRepository.listOwnSessions/listOwnReports`）
- 教师：`/api/teacher/students`（`listTeacherStudents`，RLS 放行范围）、`/api/teacher/sessions/[id]`（`getTeacherSession`）、`/api/teacher/case-drafts`
- 时间戳全部为服务端 timestamptz（started_at/created_at/updated_at），满足"服务端身份和时间"要求

## 二、缺口分析（现状 vs 需求）

| 需求 | 现状 | 缺口 |
|---|---|---|
| 学生明细：访问/训练时间、病例、模式、轮次、阶段、完成/退出 | 表已有原始列；轮次需 count(training_messages)；退出需 status 枚举区分 | 需聚合查询/RPC，无现成明细视图 |
| 有效时长（多标签/离开闲置不算） | 无 active/last-heartbeat 列 | **需新增有效时长口径**：基于 state 或新增列记录活跃区间，不能直接用 updated_at-started_at |
| 题库记录 | training_reports.data 含 quiz 维度；quiz_pool 已有表 | 需在明细中展开 quiz 记录 |
| 整体：去重/日周活跃/完成率/模式分布/趋势/错误 | 无统计聚合接口 | 需新增教师统计 RPC（RLS 内聚合） |
| 教师筛选：日期/病例/学生 | listTeacherStudents 无筛选参数 | 需扩展查询参数 |
| 匿名汇总导出 | 无 | 需导出端点（匿名化：仅 student_no/显示名脱敏 + 聚合） |
| 测试/演示与真实分开 | 2 个内置演示 fixture（peds-respiratory-001/002）与 teacher- 前缀分离；探针用户 rls-probe-* | 统计查询需**排除 fixture 与探针账号**（口径文档明示） |
| 练习分标识 | TrainingReport 有 scoreBasis（clinical/process）与 rubricId/rubricVersion 快照（v4 起沟通类项与查体专项「结果识别」恒无法评价、不进适用满分） | 统计输出需显式"练习成绩非正式成绩"标识；无法评价项不计入得分率/达成率等派生指标的分母 |
| 事件幂等 | clinical_operations/agent_call_records 已有 unique 约束 | 复用即可，无需新表 |
| 重启持久化 | 全部入库 | 复用既有 verify-restart-persistence.ts 模式 |

## 三、下一阶段实施清单（单一任务，按序）

1. **口径文档先行**（docs/使用统计口径.md）：有效时长定义（活跃心跳区间、闲置阈值、多标签去重）、活跃定义（日/周、去重口径）、完成率分母（有效 session vs 全部）、排除清单（演示 fixture、探针账号）、练习成绩标识文案
2. **有效时长支撑**：评估在 `training_sessions` 新增列（如 active_intervals jsonb 或 last_active_at）+ 新迁移（不改历史迁移），或从 state 投影（参考既有 facts_stage_projection 迁移模式）；前端埋点仅发送事件（复用 clinical_operations 的 client_event_id 幂等），不写时长结论
3. **教师统计 RPC**（新迁移）：`teacher_usage_stats(filters)` 返回学生明细 + 整体聚合，RLS 内用 `app.is_teacher_for_user` 限定范围，服务端时间过滤（日期参数）、case_id/学生筛选；最小 GRANT（仅 authenticated 教师白名单可调用）
4. **API 路由**：`/api/teacher/usage-stats`（requireAuth 'teacher'，只读），导出走同路由 `?format=csv` 匿名化输出（不含 user_id 明文、不含患者正文）
5. **前端教师页**：日期/病例/学生筛选、明细表 + 趋势图（复用现有教师页组件风格），空数据显式"暂无数据"（诚实空态）
6. **负测与验收**：权限负测（学生调教师接口 403、跨 cohort 教师 0 行）、幂等去重测试（重复 client_event_id 不双计）、重启持久化测试、390px 桌面实测、`pnpm ts-check`/`lint`、既有 verify-rls-e2e 模式扩展

## 四、边界（与用户授权一致）

- 复用内置 DB 与原教师数据范围（RLS teacher 白名单），**不新增第三方埋点**
- 不存患者原文/密码/token；统计输出不含病例正文
- 服务端身份与时间；客户端只上报事件
- 不用客户端可写记录作为防篡改证据；现有练习分非可信正式成绩，全部输出带标识
- 新迁移不改历史迁移；pnpm；不推送 GitHub/正式部署
