# 接诊摘要部署修复

根因：`knowledge/` 私有原始资料不进入 Git，部署环境读取不到文件时，`admissionProfile` 将全部教师目录覆盖成“待补充接诊信息”。此前只验证本地资料可读和合成演示病例，未覆盖这个部署边界。

修复：单独提交经原始资料核对的 `src/domain/admission-summaries.json`，仅包含公开 UUID、年龄、性别、主诉。客户端目录和服务端目录使用相同摘要；服务端没有完整资料时保留摘要，不抹除已知接诊信息。标题统一“年龄＋男童／女童＋主诉”，原始姓名、诊断、检查结果和全文不公开。67 个目录条目已有摘要（包括复用同源资料的关联条目），另 3 个缺独立资料保留中性名称；1 个原始性别未记录的摘要使用“患儿”，不补造性别。

摘要仅用于展示，不替代原始事实，不改变随机资格、版本绑定、媒体审核或身份权限。资料更新后运行 `pnpm exec tsx scripts/gen-admission-summaries.ts` 并审阅、提交摘要变更；生成器在读取不足 67 条时拒绝覆盖，避免在没有私有资料的部署机器上清空摘要。

验证：新增模拟 `PEDIATRICS_KNOWLEDGE_ROOT` 不存在的回归测试；浏览器用合成学生身份和实际公开目录检查 390、768、1440px，接诊主诉可见，无“待补充”覆盖及整页横向溢出。此浏览器验证不等于已验收线上身份和数据库。本次更新需要 Coder 拉取开发分支后重新构建发布才能改变当前线上页面。
