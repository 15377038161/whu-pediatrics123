# 首页病例库全流程审核与完善任务书（交给 Claude）

日期：2026-10-21。修订：v1.1（根据外部审核意见修订，不代表医学审核）。项目：珞珈儿科智训。工作目录：`D:\coze\儿科学`。

## 1. 用户要得到什么

请审核首页病例库中的全部病例，判断并完善每例从首页进入到复盘的完整教学体验。重点不是 JSON 是否有值、接口是否成功，而是学生能否接诊一个年龄、外观、病史、体征、检查和诊疗逻辑相互一致的模拟患者。

用户已授权：缺材料时可以自行联网查找，或结合上下文设计教学模拟内容；先完成整批病例，再发布给老师。老师使用学生实际入口体验并反馈，之后再修改。**不要求老师预审通过后才允许此次教师试用发布。此次不面向真实学生开放。**

必须分别报告四件事：内容已整理、运行已验证、教师试用已发布、医学已审核。它们不能互相代替。

本任务书是本项目制定的验收要求，不是国家标准或医学学会认证文件。具体病例的医学依据需要逐例检索核实。本次编写任务书未逐例完成内容审核，也未执行发布。

### 统一术语与状态

- **材料**：原件、外部参考、派生文件和生成示意的总称；**媒体**仅指图片、音频、视频；“资源”用于既有资源接口名称。
- **内容完整性验收**：检查本例所声明的训练目标、事实与材料是否闭环，医学正确性尚待老师确认。
- **运行验收**：真实入口和流程是否可执行；与内容完整性分别记录。
- **教师试用发布**：老师在受控范围内使用学生相同流程。允许带明确遗留项发布，不要求所有内容标准或医学审核先通过；存在隐私泄露、越权或无法限制真实学生接触等问题则先解决这些实际问题。
- **医学审核确认**：老师对指定版本作出的明确确认；不从试用次数、发布时间或无反馈推断。
- **老师预审**：此次不设置为教师试用的强制前置步骤。

上述四种状态分别记录时间、版本、证据和未通过项，不使用单个递进状态枚举隐含“已发布=已医学审核”。

8. 在已明确授权的内容整理、查找、生成、可逆修复范围内持续完成，不反复询问是否继续。实际部署目标不明确、存在原件冲突且无合理模拟方案，或无法限定教师试用访问范围时，只问影响该步骤的关键问题，继续处理独立工作。

## 3. 先确定真实审核范围

不能只按历史“53 个病例”交差。需要同时核对：

- 首页实际返回的病例、分页和各分类条目。
- 教师目录、原始材料目录、当前运行病例、别名/亚型关联。
- 导入的新材料、未绑定文件、内置演示病例。
- 当前本地与目标部署环境的版本、材料是否一致。

启动参考：本地存在 53 份 `knowledge/teaching-cases/*.json`；教师目录有独立来源、关联来源和资料不足条目。所有数量执行时重新统计，首页条目数不等于独立患者数。

输出范围表，每一行至少包括：公开病例 ID、内部来源 ID、名称（教师可见）、学科、来源目录、是否首页展示、关联类型、运行版本、材料数、审核状态。别名关联不是独立病例，亚型关联不代表两个疾病可以直接共用同一套患者结论。

审核单位分为两级：

- **病例级**：每一个首页可选条目都走完整训练链。
- **材料级**：每一份原始材料均被登记并决定用途，不能只挑几张图片宣称整例已处理。

## 4. 病例必须形成的完整链条

`首页主诉与形象 → 接诊开场 → 患儿/家长问诊 → 查体操作与证据 → 开检查与结果 → 诊断及鉴别 → 处置与沟通 → 反馈及复盘`

普通训练允许回到前面追问或检查；不为了凑流程强行增加无意义的阶段。已核对 `src/lib/agent-engine.ts` 的 `validateStageNavigation`、`validateEventStage` 和 `NAVIGATE_STAGE` 分支：普通训练回看使用 `viewStage`、不回退业务 `stage`；OSCE 使用事件及阶段门控。状态字段见 `src/domain/agent.ts`。修改前再次对照工作树，不把本次静态阅读当作运行验收。

每例先列出学习目标，再确定学生必须获得的证据。**每个评分点都必须能追溯到学生有机会获得的信息或可执行操作。** 不允许答案库要求学生猜出隐藏且无法获取的事实。

## 5. 逐项审核标准

以下编号用于逐例报告。标记为“关键”的项目失败时，该例不能记为内容验收通过；这不等于阻止用户已授权的教师试用发布。教师试用中必须可定位问题，不能伪造已通过状态。

### A. 来源、身份与时间线

| 编号 | 要求 | 验收证据 |
|---|---|---|
| A01 关键 | 首页条目能定位到明确的患者事实集合；别名、亚型和演示病例分清 | 公开 ID → 来源 ID → 运行版本对应表 |
| A02 关键 | 年龄、性别、主诉、病程、就诊时间点一致；婴儿月龄、新生儿日龄表达明确 | 原文位置或模拟补充记录，与实际页面对照 |
| A03 关键 | 病史、体征和检查区分入院前、初诊、治疗后、出院等时点 | 本例时间线；不能把治疗后正常结果作为入院结果 |
| A04 | 有明确学习对象、训练模式、学习目标和完成条件；时间为设计预估 | 病例说明与实际任务对应 |
| A05 关键 | 材料读取失败、抽取遗漏、字段归错、原文缺失、系统未接入分别记录 | 问题分类及可复查证据，禁止统一写“资料不足” |

### B. 首页卡片与患者形象

| 编号 | 要求 | 验收证据 |
|---|---|---|
| B01 | 完整主诉、年龄、性别与进入后的患者一致；首页遵守三列、每页九例既有约定 | 手机与桌面截图，卡片和接诊页对照 |
| B02 关键 | 形象适配年龄阶段及性别；新生儿、婴幼儿、学龄儿童、青少年不能共用明显错龄形象 | 形象适用年龄记录及人工视觉复核 |
| B03 | 同一患者在卡片、问诊、站立/仰卧查体中保持可识别的一致形象 | 刷新、恢复、姿势切换截图 |
| B04 关键 | 外观、体位、设备、精神状态不与已设定病情冲突；中性示意不暗示额外体征 | 外观与患者设定对照；无表现能力时使用合适中性形象 |
| B05 | 非患者本人形象有清楚的教学示意说明；不能在文件名、替代文字、标签提前泄题 | 学生页面、无障碍文本、资源响应核查 |

精确年龄不必通过一张插画准确到月份，但发育阶段、身体比例和可执行动作必须合理。病例缺年龄时可建立有依据的模拟年龄，老师视图必须看到这是新增设定。

### C. 问诊事实与信息释放

| 编号 | 要求 | 验收证据 |
|---|---|---|
| C01 关键 | 有固定开场、主诉及本病必要的现病史，学生能逐步问出有效信息 | 问题—事实—来源—释放条件表 |
| C02 | 按本例目标覆盖症状特点、起病演变、伴随表现、已做检查/用药、生活影响 | 目标所需问题清单，不要求所有疾病机械使用同一套问题 |
| C03 | 按年龄和疾病关联覆盖必要的围产、生长发育、喂养、接种、既往、过敏、家族等信息 | 每类标适用/不适用及原因；关键缺口已补充或标明 |
| C04 关键 | “未问”“未知/记不清”“否认”“未做”“未提供”“结果暂不可取”语义分开 | 边界问句与界面反馈，不把网络失败说成无材料 |
| C05 | 开场不倾倒完整病历；开放提问可得到合理概括，具体追问获得细节 | 开放、具体、重复、模糊、连续追问的对话记录 |
| C06 关键 | 同义问法答案一致；重复问不换年龄、病程、数值；不将当前医生尚未完成的诊断当成患者已知 | 同例不同表达回归与会话恢复记录 |

既往外院诊断如属于原病史，可以由家长表述；不能为“防泄题”删掉真实就诊经过。需由教学设计决定何时释放。

### D. AI 患儿与家长扮演

| 编号 | 要求 | 验收证据 |
|---|---|---|
| D01 关键 | 明确本轮由谁回答；语言和理解能力与年龄相符，新生儿不得口头讲病史 | 患儿/家长职责表与实际对话 |
| D02 | 家长以观察和回忆表达，患儿以感受表达，不照读医生病历或教科书 | 同一事实的家长口语/患儿表达示例 |
| D03 | 具备本例情绪、顾虑、配合度、安抚后的变化；不能所有病例同一人设 | 固定角色设定和安抚前后对话 |
| D04 关键 | 模型只自然表达已保存事实；新增模拟事实先入本例固定版本，不能边问边生成患者事实 | 运行输入、补充登记及多次问诊一致性 |
| D05 | 未覆盖问题能自然说明记不清、不知道或需查证；不连续机械重复“未记录” | 越界问句记录；不能用反问替代本来应能回答的问题 |
| D06 关键 | 不因学生诱导、错误断言或提示词注入而改变事实、透露评分答案 | 注入、诱导和模型失败降级结果 |

每例至少提供：开场、角色职责、事实表、释放时机、情绪变化、已知/未知边界和典型问法。AI 扮演说明不是一段通用系统提示词就算完成。

### E. 查体操作与体征证据

| 编号 | 要求 | 验收证据 |
|---|---|---|
| E01 | 从本例目标列出必要查体，明确方法、器材、部位、体位、侧别及准备动作 | 操作—条件—结果表；只设置实际能表达的动作 |
| E02 关键 | 每条异常体征及用于排除的关键阴性均有依据或明确模拟设定；未记录不默认正常 | 体征—事实 ID—材料 ID 对照 |
| E03 关键 | 正确操作解锁相应结果，错误部位/方法不返回同一段通用病理结果 | 正确与错误操作实测；双侧结果分别核对 |
| E04 关键 | 图片、声音、视频确实支持所述体征；听诊音不能来自不匹配部位或病情而宣称本例原始音 | 素材人工查看/播放、区段定位和文字说明 |
| E05 | 适合直接观察的表现可初见提供；需操作获得的结果按动作出现 | 初见与操作后展示对照，不人为隐藏肉眼可见事实 |
| E06 | 操作产生的证据及时入记录，重复操作不重复加分，回看仍可播放或放大 | 证据时间线、重复操作、恢复验证 |

不是每个体征都必须配图片。视诊优先图片/视频，听诊优先适配音频，触诊可用准确文字或交互反馈。不能用一张无关图片凑“多模态”。

### F. 辅助检查与报告

| 编号 | 要求 | 验收证据 |
|---|---|---|
| F01 关键 | 每项检查的名称、适应的教学目标、结果、单位、时点和来源清楚 | 检查目录与结果记录 |
| F02 关键 | 检验数值、报告、影像及文字解读彼此一致；年龄相关参考范围有出处，不能套成人范围 | 数值逐项核对；参考文献版本/日期 |
| F03 | 合理同义检查名可识别，歧义需澄清；无结果与请求失败分别处理 | 同义、歧义、未提供、暂时失败测试 |
| F04 关键 | 初次查看符合下单规则；已获得结果允许回看；未开检查不能从资源列表或网络响应获得隐藏结果 | 下单前后接口和页面验证 |
| F05 | 多页报告、影像序列和视频有合理导航，关键页可读，有需要时提供定位 | 手机缩放/翻页/播放记录，关键帧与上下文 |
| F06 关键 | 外部病例素材、示例报告和生成示意不能冒充本患者实测结果 | 可见说明及材料来源记录；模拟病例版本内保持一致 |

生成示意图不能凭视觉外观认定其有诊断价值。缺少可靠影像时，可以先给有依据的模拟文字报告并明确图像能力边界，不伪造“真实 CT”。

### G. 诊断与鉴别诊断

| 编号 | 要求 | 验收证据 |
|---|---|---|
| G01 关键 | 标准诊断、分型/严重程度与当前患者全部事实一致 | 诊断—支持/反对证据表 |
| G02 关键 | 必需诊断依据在本轮实际可获得，不能用诊断标签反推补造一套伪装原始的证据 | 诊断要点逐条回溯问诊/查体/检查 |
| G03 | 鉴别诊断围绕本例，说明为何考虑、如何区分、仍需何种证据；不机械凑数量 | 鉴别表和对应检查/问诊路径 |
| G04 | 同义诊断、允许的上位诊断和不充分答案有清楚规则；模糊证据允许合理不确定性 | 答案边界与得分示例，规则保持确定性 |
| G05 | 非相关检查不成为唯一解锁答案的暗门；可接受的替代路径有记录 | 至少一条合理替代路径验收或不适用说明 |

### H. 处置、解释与病程变化

| 编号 | 要求 | 验收证据 |
|---|---|---|
| H01 关键 | 处置目标与年龄、体重、严重程度、过敏和已知检查一致 | 方案—事实—参考依据表 |
| H02 关键 | 涉及药物剂量时明确体重、计量单位、途径、频次、最大量等必要条件及来源；未具备条件不强评精确剂量 | 剂量与单位核对；按第16节重点标注，允许先供老师试用，不将医学预审设为发布前提 |
| H03 | 区分紧急处理、进一步评估、治疗、复查、转诊/住院、随访；内容按本例目标适用 | 本例可执行处置清单，非所有病例强行要求全部 |
| H04 | 家长能提出本例合理顾虑；学生解释病情、风险、检查目的和后续安排后有对应反馈 | 沟通脚本、学生解释证据与角色反馈 |
| H05 关键 | 病情演变仅在已设计的时间/事件条件下发生；不能操作一下就无依据痊愈或恶化 | 条件—时间—新事实表；无动态演变则固定当前场景 |

| I03 关键 | 报告区分“未询问/未执行”和“系统未提供/请求失败”，不归责学生 | 缺材料与失败注入后的报告 |
| I04 | 每条反馈能指出具体行为、缺失证据、改进建议；必要时回看材料 | 报告中的证据引用可点开、版本一致 |
| I05 | 复盘把关键图片、结果、诊断推理和处置理由串起来；答案标注图适合在此展示 | 完整复盘记录，避免只给分数和通用评语 |

### J. 每份材料的标准

| 编号 | 要求 | 验收证据 |
|---|---|---|
| J01 关键 | 每份文件登记唯一 ID、路径、哈希、格式、所属病例、来源类型、阅读状态 | 材料总账；失败也登记，不把失败文件丢掉 |
| J02 | 每份材料决定用途：本例证据/教学参考/复盘讲解/同源重复/不适用/无法读取待处理 | 用途和理由；有效材料安置率达到 100% |
| J03 关键 | 使用材料记录时点、部位/侧别、支持事实、展示阶段、触发动作、是否泄题 | 材料使用卡和实际触发记录 |
| J04 | 图片清晰且可缩放，音视频可播放，有必要的裁剪、转码、字幕/说明；保留原件 | 原件和派生物关联；可访问性与移动端验证 |
| J05 关键 | 隐私、来源、使用条件明确；外部图不能因可搜索就当成可再分发 | 来源页、许可/授权记录及核查日期；不明权利的只保留链接或另找素材；事后发现问题按第20节撤换 |
| J06 | 大批连续图像按真实序列分组，审阅关键段并记录覆盖范围，不能按张数当作不同检查 | 文件级总账＋序列级说明＋关键帧，未审段落明确记录 |

“有效材料安置率”分母为全部登记文件，重复/不适用有明确理由也算完成安置；不是要求所有文件都展示给学生。**语义已核验覆盖率另算**，仅登记或自动分类不算看过内容。

### K. 补充内容与来源管理

| 编号 | 要求 | 验收证据 |
|---|---|---|
| K01 关键 | 补充类型明确：表达润色、一般角色设计、医学事实/数值模拟、外部临床参考、生成形象/示意 | 补充登记表，不把所有内容统称“AI 优化” |
| K02 关键 | 医学补充可回到可访问的专业依据；具体患者数值属于教学设定，引用指南不使其变成真实实测值 | 依据页、适用人群/版本、设定理由 |
| K03 关键 | 补充后全例自洽，所有派生脚本、图片、结果、评分同步；与原件冲突不得静默覆盖 | 冲突记录、取舍理由、版本变更记录 |
| K04 | 老师能集中看到全部新增项、来源、风险和修改位置；原始内容与补充内容可对照 | 老师审核清单；学生页面只需简洁说明模拟性质 |
| K05 关键 | 发布和审核独立；教师试用可以未医学审核，但不能标“老师已确认” | 实际版本状态和发布日期 |

### L. 运行、访问与整批验收

| 编号 | 要求 | 验收证据 |
|---|---|---|
| L01 关键 | 每个首页条目都验证能进入、完成、生成报告、退出和恢复，不只抽测代表病例 | 每例测试结果；失败列真实状态 |
| L02 | 手机优先，材料加载、放大、音频/视频播放和返回不丢进度；资源失败可重试 | 390/768/1440px 代表页面；所有特殊媒体类型覆盖；失败按第19节降级 |
| L03 关键 | 问诊、查体、检查和报告使用同一事实版本；修订不改变既有会话的患者事实 | 新旧会话、刷新、重启后的版本实证 |
| L04 关键 | 仅老师试用此次发布；老师走学生相同页面及业务流程，但不会改变账号实际权限 | 按第17节验证受控入口、API和媒体的访问范围，而非只隐藏按钮 |
| L05 关键 | 部署端实际拥有材料和派生文件，不能本地可读就声称线上可用 | 目标环境文件/资源状态及真实页面验证 |
| L06 | 类型、静态检查、相关测试和构建通过；不把构建成功当成内容或医学验收 | 命令真实退出码、接口/浏览器记录、未验证项；执行预算按第22节 |

## 6. 缺失内容的处理规则（已获用户授权）

按下列顺序处理，每一项落实到具体内容，不停留在建议：

1. **先找已有材料**：正文、表格、附件、补充目录、既有抽取结果和绑定快照，防止已有内容被错判缺失。
2. **修复抽取/映射**：内容存在但被漏读或放错字段，先修真实原因。不用新生成内容盖住损坏的来源链。
3. **联网补充**：优先专业学会/官方指南、权威医院教学资源、同行评议原始论文和有明确使用条件的教育素材。记录直接来源、版本、访问日期、适用年龄及采用内容，不以搜索摘要作为唯一依据。
4. **固定模拟设计**：缺年龄、生活细节、阴性病史、体征、检查结果时，可在不覆盖原件事实的前提下设计完整模拟设定。医学项目写清依据和设定理由，组合成同一患者版本；高风险剂量、关键诊断阈值逐项核实。
5. **补形象及示意**：可生成适龄患者外观、体位、操作示意、一般解释图。生成内容保存提示词、版本、用途和视觉核查。病理性图像只能按真实验证能力使用；未经验证不能成为诊断评分的决定性证据。
6. **仍不可靠的内容**：先提供可用的明确模拟文字结果或缩小相应问题，记录老师重点反馈项。不能为了“全部完成”编出证据齐全的结论。教师试用仍可列出该例并反馈，报告不得把缺口算作学生能力缺陷。

当原件无法形成一个自洽患者时，可以另建明确的“基于该教学主题设计的模拟版本”，保留原件；不能把拼接不同患者后的版本标成单一原患者记录。

### 必填的补充记录

`补充 ID / 病例 ID / 字段或素材 / 原始状态 / 新增内容 / 来源类别 / URL与版本或生成方式 / 设计理由 / 影响环节 / 是否影响诊断与评分 / 教师审核状态 / 运行版本`

同一来源支持多个设定时逐项解释，不能用一条参考文献为整例所有数值背书。

## 7. 每一份材料如何进入流程

| 材料 | 优先使用位置 | 主要检查点 |
|---|---|---|
| 病史 Word/TXT、表格 | 问诊事实表、时间线 | 表格/脚注/修订内容是否读取，身份信息是否脱敏 |

| 血常规、生化等检验单 | 开出相应检查后 | 单位、年龄参考、时点、隐私及数字一致 |

## 8. 每例必须交付的标准病例包

每例至少具备下列内容；可复用现有文件并建立索引，不要求为每项新建一个模块。

1. **病例概况**：身份、年龄、性别、主诉、时间线、学习目标、训练模式、版本。
2. **首页与形象说明**：可公开摘要、形象及适龄依据、初见表现。
3. **问诊事实表**：事实 ID、问题类别、固定事实、患儿/家长表达、主动/追问释放、依据。
4. **角色扮演说明**：开场、角色分工、情绪、顾虑、配合变化、未知边界。
5. **查体表**：操作、方法、部位、体位、结果、证据材料、记录和评分关系。
6. **检查表**：检查名及同义词、下单条件、结果与单位、报告/媒体、时点。
7. **诊疗表**：诊断与鉴别、支持/反对证据、处置与沟通、允许的替代答案。
8. **复盘与评分表**：目标、行为、可获得证据、得分规则、针对性反馈及材料回看。
9. **材料及补充总账**：所有原件安置、外部来源、模拟设定、生成内容、冲突与取舍。
10. **验收与教师反馈单**：逐项标准结果、实际运行证据、未解决问题、教师修改记录。

## 9. 实施顺序与每阶段交付

### 第一阶段：范围与材料盘点

建立全部首页条目、独立患者、关联条目和全部材料的总账。核对新材料和本地/云端差异，读取失败文件单列。只报告实际盘点结果，不将旧报告计数照抄为当前事实。

交付：病例范围表、材料总账、版本基线、待解决读取问题。盘点完成不等于语义已审核。

### 第二阶段：完成一例端到端样板，立即继续整批

选择原件和媒体较丰富的一例，把第 8 节的全部内容做完整，并实际走通训练与复盘。用它校准字段、证据引用和验收方式。样板完成后无需再等用户逐次批准，继续处理全部病例，不能以样板代替全量交付。

交付：一例真实完整样板、必要的共用实现修正、最终填写格式。

### 第三阶段：逐例审核、补充和接入

按学科或材料共性分批，但每例独立闭环。建议先解决共用缺陷：适龄形象、材料展示触发、原文分段、未知状态、版本一致性。对每例完成“原件阅读 → 缺口确认 → 补充设计 → 来源记录 → 实际接入 → 内容复核”。

不同病例可共用合适的中性形象或教学解释资源，但不能共用不属于本例的患者事实和异常检查结果。每批交付更新总账和可复查问题清单，不只报百分比。

### 第四阶段：全量运行与质量验收

对每个首页条目运行一条完整路径；对所有共享交互执行有意义的负面/边界测试。媒体做真实查看、播放和缩放，不用“文件存在”代替。失败修复后重跑受影响路径。

交付：逐例内容验收表、运行结果、截图/接口证据、相关测试与构建结果、真实未验证项。

### 第五阶段：全部发布教师试用版

用户已授权整批发布给老师，不以医学预审作为阻断条件。复用既有部署和病例发布方式，老师使用学生相同入口、页面及业务流程，不授予新的身份权限。

发布前确定：目标地址、版本、全部病例可访问性、材料已部署、老师如何进入、真实学生为何不会提前接触。优先使用现有受控试用环境；若目标是现有学生共用环境，必须先核实已有访问范围，不能仅靠“老师先用”口头约定推定学生不可达。

有遗留项的病例仍纳入整批教师试用清单，清楚列出问题和反馈入口；不篡改通过状态、不绕过认证/资源隔离、不把受损运行强行称为可用。遇到共用环境暴露或阻断流程的真实故障，修复或明确列出发布阻断原因。

交付：教师试用地址、批次/版本、病例清单、已验证访问范围、已知问题及老师使用说明。发布成功必须有真实访问结果。

### 第六阶段：老师反馈后的修订

将反馈定位到病例、材料、事实或规则，修订后检查所有受影响环节和评分；保留已完成训练的旧版本。反馈闭环后再更新医学审核状态，不因老师暂时没反馈而自动标已通过。

## 10. 运行验收脚本必须覆盖什么

| 类别 | 必验情形 |
|---|---|
| 全量入口 | 每例默认接诊、关联来源、各分页、无重复遗漏、全部试用条目可进入 |
| 问诊 | 开放提问、追问、同义问、重复问、混合问题、未覆盖问题、诱导/注入、角色切换 |
| 查体 | 正确/错误部位、方法、器材、侧别、重复、初见信息、媒体失败重试 |
| 检查 | 同义名、歧义名、先下单后结果、重复下单、未提供、临时失败、回看 |
| 诊疗 | 标准答案、合理替代、证据不足、错误诊断、缺条件剂量、沟通后继续追问 |
| 复盘 | 无学生错误却材料缺失、漏问/漏查、重复操作、证据引用、答案图释放 |
| 恢复 | 刷新、退出后继续、不同会话、版本升级、必要的重启恢复 |
| 环境 | 本地与部署差异、真实身份访问、手机/桌面、所有媒体类型真实渲染 |

内容事实可自动核对的项目做自动核对；图像语义、角色自然性、临床连贯性须人工或模型辅助审阅并留记录。模型自评不等于老师医学审核。

真实 AI 检查必须区分实际模型回复与确定性降级；纯内存测试、真实数据库、真实浏览器结果分别报告。医学规则/评分不改成由大模型临时判定。

## 11. 验收口径与整批完成条件

每项使用：`通过 / 失败 / 未验证 / 不适用`，不适用必须写理由。不要自拟一个总分掩盖关键缺陷。

- 范围覆盖率：已登记首页条目 / 实际首页条目，目标 100%。
- 材料登记率：已登记文件 / 范围内实际文件，目标 100%。
- 材料安置率：已决定用途并有理由的文件 / 已登记文件，目标 100%。
- 语义核验覆盖率：已实际阅读、查看、播放或按说明审查的材料 / 应审材料；部分审阅不能计为全部。
- 关键证据闭环：每个诊断/评分关键点均有学生可获得的证据；缺口单列，不能用平均率冲抵。
- 全量流程完成率：真实完成训练并生成报告的条目 / 本批试用条目，目标 100%，失败列明原因。
- 教师试用发布覆盖率：目标环境可实际访问的条目 / 本批条目，目标 100%。
- 医学审核率：老师明确确认的版本 / 待审核版本；试用发布时可以为 0，不能因此冒称已医学审核。

整批交付必须能回答：共有多少首页条目和独立患者、每例用了哪些材料、补了什么、还有哪些问题、哪些运行已实测、老师从哪里进入、真实学生访问范围是什么。

## 16. 医学补充风险分级与教师试用处理

分级用于决定核查力度和老师关注点，不另建一套拦截全部教师试用的医学审批流程。同一内容若影响临床判断，按较高风险处理。

| 类型 | 例子 | 进入教师试用前要求 | 老师看到什么 |
|---|---|---|---|
| 一般设计 | 语气、普通顾虑、中性形象、非临床生活细节 | 与年龄、固定事实相容，记录生成/设计来源 | 新增项及用途 |
| 医学模拟 | 一般体征、必要阴性史、常规检验、年龄参考范围 | 逐项有专业依据；数值写明是设计值；核对时间线、单位及跨环节一致性 | “教学模拟补充，待医学审核”及具体依据 |
| 重点医学核查 | 剂量、关键诊断阈值、急救处置、罕见体征 | 对适用人群、条件、单位、依据版本做独立核对；可计算项确定性复核；不得仅相信模型自检 | 在相关内容附近显示“教学示例，待老师医学审核，不用于实际诊疗”，并列待确认项 |

所有教师试用页面在开始和复盘有简洁的模拟性质说明；重点项在实际出现处提示，不能仅藏在总说明里。提示不是准确性核查的替代。

找不到可核实依据、必要条件不齐或出现互相矛盾依据时，不输出一个自信的精确结论：改为原则性教学内容、明确暂缺的细项，并从精确数值评分中剔除。病例仍可参加老师试用并反馈，不因单个细项而整例锁死，也不把“暂缺”冒称内容验收通过。

## 17. 教师试用的具体访问验收

先检查现有环境，优先采用已存在的受控试用部署和身份控制；没有必要时不新增 feature flag、`trial_batch` 数据库列或独立权限体系。

1. 记录试用 URL、部署版本、实际访问控制、允许的老师身份和真实学生当前入口。
2. 若用独立环境，确认服务器/网关或应用身份校验覆盖整个试用环境；独立域名、未公开链接或环境变量本身均不等于访问隔离。
3. 若用共用环境，复用服务端身份及受控试用版本选择，核对病例目录、新会话、历史恢复、报告、材料和直接资源 URL。仅前端隐藏、客户端 `trial=true` 或单独一个批次标签不构成访问控制。
4. 老师仍用真实身份进入学生页面及相同业务流程。若使用已有学生测试身份，记录其治理方式，不将老师的整个角色改成学生，不扩张白名单，不为此默认新建账号。
5. 至少验证允许老师可达、未登录被拒、真实学生身份不可达本次未审版本、直接请求 API/媒体不能绕过。只用断言或接口模拟不足以证明目标环境隔离。
6. 记录现有正式入口、旧训练和其他病例是否受影响。所有病例只在本次教师试用范围内整批可用，不能用全局 `published=true` 推断已安全完成该要求。

当前 `src/lib/case-publication.ts` 的规则是无行默认发布、教师豁免；`src/lib/case-admission.ts` 另有主诉/年龄/各节完整度筛选。它们不是已实现的“试用批次隔离”。执行者须验证真实路径，有缺口时做必要的最小改动并同步文档。

## 18. 版本、变更、反馈定位及回退

### 三种定位符分工

- `caseVersion`：现有会话实际绑定的不可变事实版本。继续兼容现有绑定字段和恢复链。
- `contentDigest`：覆盖本例实际使用内容的完整 sha256，包括固定医学事实、角色固定设定、查体/检查规则、评分、媒体内容哈希与绑定、提示词或相关实现版本。以稳定字段排序、UTF-8、规范化换行形成清单；排除生成时间、审核备注等不影响运行内容的字段。跨病例共享规则以明确的规则/构建版本纳入。
- `releaseId`：便于老师反馈的可读标签，可用 `YYYYMMDD-HHmmss-摘要前12位`，时区固定 Asia/Shanghai；使用完整摘要检查冲突。同一批次还记录代码提交或构建产物指纹。时间标签不替代内容指纹。

这些为待实施的数据契约，不声称当前数据库已包含全部字段；先复用现有持久化载体。不得把新增列的建议当成已完成迁移。

### 最初定位与当前修复边界

启动时已确认版本算法只聚合`documents[].sha256`，原件未变时修订字段可能仍认成同版。2026-10-21续做已统一本地读取、导入及召回为`case-data-version.ts`的算法v2，覆盖当前固定事实、原文及召回媒体URL，旧键按原绑定恢复；已做合成独立进程验证。真实数据库导入、本地媒体字节及完整规则/量表的版本保存尚待后续接入和实测，不能将这一阶段修复当成第18节全部要求完成。进展与证据见`docs/CASE_LIBRARY_LOCAL_EVIDENCE.md`。

### 变更与回退要求

1. 任何影响学生看到的事实、结果、形象/媒体、提示词边界、规则或评分的改动必须产生新内容版本；仅改审核备注不重写患者事实。
2. 反馈记录 `caseId + caseVersion + releaseId + 环节 + materialId/factId`，附问题发生时间和必要截图，不含凭据。
3. 历史版本按既有保留规则归档；本批试用结束前不得清理仍被会话、报告或反馈引用的内容、规则及媒体。不是无限期保留所有敏感数据。
4. 回退新会话的活动版本和部署产物指向，不覆盖旧版本行、不删除成绩、不让既有会话无提示换患者。
5. 回退先核对旧版事实、规则与媒体仍可取，再验证旧会话恢复、新会话绑定、报告回看和资源权限，记录回退批次及原因。
6. 若当前运行时无法恢复旧规则/媒体，仅有数据库版本列不足以满足不变性；明确缺口并实施有边界的版本保存或兼容修复后再声称达标。

## 19. 逐环节失败与降级

降级只使用已有固定事实或已保存的模拟设定。因素材/服务故障缺失的观察，不作为学生漏查扣分；直接给出文字体征时，可以评价查体动作，不能继续按“独立听辨/阅片能力”评分。

| 故障 | 可用降级 | 必须保留的边界及验证 |
|---|---|---|
| 角色模型超时/失败 | 已有确定性事实应答 | 记录实际执行路径，不声称模型正常；身份、事实和阶段不变 |
| 听诊音频缺失/无法播放 | 固定文字体征＋音频暂不可用提示 | 不临时生成异常音作为真实证据；重试可恢复，听辨评分取消或不适用 |
| 查体视频缺失 | 原有适配静态图或固定文字结果 | 不用无关动作视频替代；动作考核受限单列 |
| 影像缺失 | 有依据的固定文字报告 | 通用示意图仅作说明，不能冒充本片；独立阅片评分受限单列 |
| 检查服务临时失败 | 可重试错误，保留已下单状态 | 不回传“检查正常/资料未提供”，重试不重复计费或记证据 |
| 原件未提供检查结果 | 明确未提供；有授权模拟补充则使用已版本化补充 | 与临时网络错误区分；无结果不能解锁对应结论 |
| 图片过小/文字模糊 | 原图缩放、转写可核实文字或清晰替代 | 不猜不清晰的数值，不靠插值放大声称增加了证据 |
| 发布端漏传材料 | 临时提示＋可用文字事实，同时补传并复验 | 不能因本地成功而标线上已验收 |

每项故障至少做一次受控模拟或真实失败验证，并核对报告中的归因和评分。

## 20. 隐私、材料使用条件及事后撤换

### 进入试用前的逐文件检查

- 姓名、家长姓名、住院/门诊/病案号、证件、电话、邮箱、具体地址、签名、二维码/条码、设备或文件元数据中的标识逐项检查。审核报告使用患儿/家长或稳定的匿名编号。
- 出生日期、检查日期等按同一患者统一做相对化或一致偏移，保留实际年龄、病程间隔和检验时序。不能逐个随意删改导致时间线错误。
- 医院、科室、医生等可识别信息按必要性泛化；不得破坏与教学有关的检查方法或专业背景。
- 处理 Word/PDF 正文、表格、页眉页脚、批注/修订、隐藏文字、附件及 PDF 可搜索层；图片 OCR 后人工看身份区和角落；视频检查关键帧、叠字及音轨；支持 DICOM 等格式时也检查元数据。
- 文字检测只输出路径、类型与计数；图片裁剪/遮盖必须作用于实际分发文件，而非可移除的页面遮罩。PDF 遮盖后复查搜索层；原件受控保存。
- 分发前检查学生页面、报告、材料响应及截图。扫描无命中不等于已脱敏，OCR失败和未审段必须明列。
- 对外部模型只传必要、已脱敏内容；不整包上传病例目录。遵守当前外部模型审核授权规则。

### 事后发现隐私或使用条件问题

1. 立即停止目标材料的继续分发并定位引用它的全部病例/版本；处理实际资源接口和派生副本，不只是移除界面链接。
2. 隐私问题优先切断可访问副本并修复。使用条件不明材料先撤换为有依据的文字结果或清楚标注的可用替代；不能凭空补新证据。
3. 检查缩略图、转码文件、导出包和服务端/CDN缓存的可达性，更新受影响绑定与缓存。已下载的副本无法承诺远程收回，应如实记录。
4. 总账补记发现时间、核查日期、结论、处理人/来源、受影响材料/版本、替代物及复验结果。使用条件不明的原件仅保留在授权范围内的受控位置。
5. 使用非秘密材料 ID/版本告诉相关老师需要停止使用哪一项及替代位置，不重复发送被撤换的隐私内容。向他人发消息仍需有相应发送授权。

这些是项目操作要求，不代替具体法律判断；不得因为“教学用途”就自动认定外部材料可复制发布。

## 21. 并发修改与常见阻断处理

### 并发修改

- 基线记录 HEAD、工作区状态、计划编辑文件及私有材料哈希。必要时使用 `codex/case-library-review-20261021` 分支或独立 worktree；分支本身不能隔离共享目录或云端修改。
- 每次覆盖文件或运行生成器之前，复查该文件与基线差异；变化来源不明则停该文件，保留双方差异后协调，不用 `reset --hard`、强制检出或全量重生成抹掉改动。
- 合并按有边界的批次完成，先 `fetch`/查看差异，再选择合并方式。不机械定期 rebase，不改写他人已共享历史，不自动 stash 全部用户修改。
- 发布时冻结本批产物清单及哈希，核对实际上传内容对应验收版本；不把审核期间不断变化的工作树直接当最终包。

### 常见阻断

| 情况 | 处理及继续范围 |
|---|---|
| 大量病例缺关键材料 | 先按根因分组修抽取/资源共用缺陷，再逐例补充；不另设“超过30%就放弃整批”阈值。剩余项明列并纳入老师反馈，不谎报完成 |
| 模型连续失败 | 记录实际失败类型、次数、耗时和降级结果；同根因连续3次后停止同类付费重试并排查，继续内容及确定性验证；这是执行预算，不是平台SLA |
| 原件疑似医学错误 | 原件保留并标明冲突；可建立独立模拟修订版本说明依据及取舍，老师试用可对照，不把疑点原文作为已确认结论 |
| 原件无法打开/OCR不可靠 | 保留失败类型、页/段范围；尝试现有工具或可验证的格式转换；未读内容不自动算已审 |
| 目标环境/真实学生访问范围不明 | 继续本地内容完善和验收；仅暂停依赖该信息的实际发布，提出目标地址与访问范围这一关键问题 |
| 现有代码无法保持旧会话事实 | 先定位绑定/指纹/恢复根因，做最小完整修复；不能靠“版本号已变”宣称解决 |

## 22. 测试分层、执行预算及可测量指标

### 分层不减全量覆盖

1. 每个条目自动或人工完成基本全链：进入、关键问答、必要查体、检查、诊断/处置、结束、报告及恢复。测试必须真实消费该例内容，不能用同一演示响应替代所有病例。
2. 每例新增的关键异常体征、媒体绑定、诊断依据、处置和评分均逐项核对。每个条目至少留一条完整运行记录。
3. 共用控件、全部边界条件和负测可选代表病例覆盖；独有媒体格式、年龄角色、复杂分支仍各自深测。深测抽样不能替代每例内容审核和基本全链。
4. 使用项目已有测试与浏览器工具。可提取批量驱动脚本，先核实已有能力，不把建议命令写成已存在工具。

### 初始执行预算（执行时根据真实环境校准并记录）

- HTTP 请求单次等待上限初始60秒；批量测试不得覆盖业务现有模型超时/重试配置。
- 浏览器单动作初始30秒，单例基本全链初始10分钟。超出先保存阶段和错误，再判断慢请求/环境故障/流程缺陷。
- 只有已确认的瞬时网络或5xx失败自动重跑1次；写操作复用业务幂等标识。内容断言、鉴权失败和数值矛盾不靠重试刷绿。
- 真实模型初始串行执行；记录请求数、模型/降级次数及耗时。批量并发需要匹配现有配额与服务能力，不能自行压测正式环境。
- 超时及失败均保留首轮证据；汇总区分首次通过、重跑通过、失败、未执行，不能只报最后一次结果。

### 量化替代模糊词

- 图像“清晰”：在390px视口可定位关键区域，缩放后应读的数字/标记能正确辨认，保留原始像素尺寸、关键区与人工判定。不能统一用800×600判所有影像、长报告和示意图。
- 病史“完整”：本例每个学习目标所需事实均有固定值、释放途径和来源；适用问题类别覆盖100%，不适用写理由。查体、检查、诊断、处置分别验收，不混称病史。
- 查体“合理”：每个本例必需体征均有至少一条可执行获取路径，方法/部位/结果100%对应；不强凑“至少3个操作”。
- AI“一致”：本例关键事实在重复、同义、诱导及恢复测试中不得矛盾；记录具体问法、事实ID及执行路径，不只报模型自评分。
- 关键材料“已接入”：实际在规定环节触发成功，且可回看；文件存在、资源总数增加不算。
