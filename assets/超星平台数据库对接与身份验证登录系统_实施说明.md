# 基于超星平台的数据库对接与身份验证登录系统实施说明

> 文档状态：开发实施基线  
> 适用项目：生物化学实验智能体及同类 Coze 全栈教学应用  
> 技术基线：Next.js + TypeScript + pnpm + Supabase + Coze  
> 核对日期：2026-08-14  
> 重要边界：本文所称“超星数据库对接”是通过超星正式授权的开放接口、微服务表单或任务流交换数据，不是直接连接超星底层数据库。

---

## 1. 前言

### 1.1 编写目的

本文说明如何让一个部署在 Coze（扣子编程）中的业务系统完成两类集成：

1. **统一身份认证**：学生和教师使用已经登录的超星/学习通账号进入业务系统，系统识别其用户、单位和角色，不再单独注册一套账号。
2. **业务数据同步**：业务系统把实验过程、AI评阅和学习报告保存在自己的事务数据库中，再将学校需要留痕的数据同步到超星授权接口、表单或任务流。

本文覆盖申请、开发、测试、部署、监控和排障全过程，并给出可直接改造的 Next.js/TypeScript 示例。

### 1.2 适用场景

- 从学习通、泛雅或超星应用入口打开校内教学应用。
- 根据 `fid` 限制只有指定学校或单位的用户可以登录。
- 根据超星角色区分学生端和教师端。
- 同步用户、课程、成绩或教学过程结果。
- 将学生文字回答、AI反馈、图片、评分和学习报告写入超星微服务表单。
- 将部署在 Coze 的高代码项目与超星开放平台连接。

### 1.3 预期读者

- 负责 Next.js/TypeScript 开发的工程人员。
- 负责 Coze 项目、工作流和环境变量的实施人员。
- 负责超星平台应用、表单和任务流配置的管理员。
- 负责接口、权限、数据一致性和安全验收的测试人员。
- 负责生产发布、监控、备份和故障处理的运维人员。

### 1.4 业务价值

- 学生不需要记忆新的账号密码，减少登录割裂。
- 系统可以稳定获得超星用户唯一标识、学工号、单位和角色。
- 学生过程数据与校内身份建立可靠映射，避免同名学生混淆。
- 业务系统负责复杂状态、版本和AI评阅，超星负责校内入口、身份依托和必要留痕。
- 同步过程可重试、可追踪，不会因为外部接口临时失败而丢失学生已完成的操作。
- 密钥、令牌和隐私数据留在服务端，降低前端泄露风险。

## 2. 先澄清“超星统一数据库”的含义

第三方应用通常不会获得超星生产数据库的地址、账号或表级权限。正确实现是：

```text
业务系统 ↔ 超星开放接口 / 微服务表单 / 已发布任务流 ↔ 超星承载的数据
```

而不是：

```text
业务系统 ↔ 直接连接超星底层 MySQL/PostgreSQL
```

因此，本文把数据能力分为三层：

| 层级 | 负责内容 | 是否由本系统直接控制 |
|---|---|---|
| 业务数据库（Supabase PostgreSQL） | 会话、实验状态、答案版本、AI评阅、报告、同步队列 | 是 |
| 超星开放接口 | 用户、课程、成绩等经学校授权的数据 | 只按权限调用 |
| 超星微服务表单/任务流 | 校内结果留痕、教师查看、统计或流程写入 | 只按已发布能力调用 |

如果学校要求“全部数据都放在超星”，仍应先确认超星是否提供完整的增删改查、附件、事务、并发和权限隔离接口。仅看到表单“新增数据”节点，不能等同于已经获得通用数据库权限。

## 3. 系统整体架构

![超星统一身份与数据同步整体架构图，展示用户、Coze业务系统、超星认证中心、开放接口、业务数据库和AI工作流之间的关系](./assets/01-system-architecture-1920x1080.png)

*图 1：超星统一身份与数据同步整体架构（1920×1080）。第三方系统通过正式授权能力交互，不直接连接超星底层数据库。*

### 3.1 架构节点说明

#### 学生与教师

- 从学习通、泛雅、超星微服务应用或业务系统入口进入。
- 如果浏览器已经处于超星 Passport 登录状态，可直接进入授权过程；否则先完成超星登录。
- 学生只能访问自己的实验、回答和报告；教师只能访问被授权课程的数据。

#### Coze 全栈业务系统

- 使用 Next.js 同时承担页面和服务端 API。
- OAuth 回调、令牌交换、用户信息请求必须在服务端执行。
- 负责实验流程、AI评分、图片处理、学习报告和权限判断。
- 通过适配器调用超星接口，避免把第三方接口细节散落在业务代码中。

#### 超星身份认证中心

- 签发一次性授权码 `code`。
- 使用 `code` 换取 `access_token`、`refresh_token`、`openid` 和有效期。
- 根据令牌返回用户唯一标识、学工号、姓名、单位和角色。

#### 业务数据库

- 保存稳定的业务用户主键，不直接把学号当数据库主键。
- 保存超星身份映射、令牌密文、实验过程、同步队列和审计日志。
- 外部同步失败时，学生业务记录仍然保留。

#### 超星开放能力

- OAuth 用户信息接口已经可以从公开文档确认。
- 课程、成绩、表单自动写入等接口必须以学校实际授权文档为准。
- 当前已验证超星智能体任务流能使用“新增数据”节点写入表单，但高代码服务端调用该任务流仍需要发布后的调用地址、鉴权和限流说明。

#### Coze AI 工作流

- 负责文字评阅、图片辅助识别和学习报告生成。
- 不持有超星 APPKEY、refresh token 或 Supabase service role key。
- AI请求使用业务用户内部ID，除非任务明确需要，否则不发送姓名和学号。

### 3.2 交互链路说明

1. 用户打开 Coze 业务应用。
2. 系统发现没有有效会话，发起超星 OAuth。
3. 超星回调业务系统，业务后端交换令牌并查询用户。
4. 后端校验单位 `fid` 和角色，将超星身份绑定到业务用户。
5. 学生操作先写业务数据库。
6. 同一数据库事务写入待同步事件 `sync_outbox`。
7. 同步 Worker 调用已授权的超星接口或任务流。
8. 成功后记录超星侧ID；失败则退避重试并告警。

## 5. 前置准备

### 5.1 账号与资质

根据超星开放平台公开对接流程，账号分为个人账号和企业/单位账号：

- 个人账号完善信息后可使用 OAuth 认证接口。
- 企业/单位账号提交审核，审核通过后可在个人中心查看单位 APP ID 和 APP KEY。
- 单校使用优先选择“自建应用”；面向多个单位的全网应用才考虑“市场应用”。

建议本项目以武汉大学校内自建应用方式实施。

### 5.2 开发者资质申请流程

1. 打开 [超星微服务开放平台](https://open.chaoxing.com)。
2. 使用有权限的账号注册或登录。
3. 选择个人账号或企业/单位账号，并完善真实资料。
4. 企业/单位账号提交审核。
5. 审核通过后进入个人中心或应用管理。
6. 创建自建应用或上传应用。
7. 填写应用名称、说明、PC/移动端地址和 HTTPS 回调地址。
8. 在应用详情中查看 APPID 和 APPKEY。
9. APPKEY 立即存入密码管理器或服务端密钥系统，不通过微信、文档或截图传播。

> 公司模板说明允许初次创建时暂用占位地址，但正式联调前必须把预览和生产回调地址完整配置好。

### 5.3 接口权限申请清单

向学校或超星申请时，不能只写“需要数据库接口”，应提交具体用途：

| 权限 | 用途 | 最小字段 |
|---|---|---|
| OAuth 授权 | 完成统一登录 | code、token、openid |
| 用户信息 | 建立学生/教师身份 | uid、学工号、姓名、fid、角色 |
| 课程查询 | 映射当前课程和班级 | course_id、course_name、term、teacher |
| 课程成员 | 判断学生选课和教师权限 | course_id、uid、role、class |
| 成绩读取 | 只在教学需求确认后使用 | task_id、student_id、score、updated_at |
| 成绩写入 | 如需回传成绩，单独申请高风险写权限 | task_id、student_id、score、request_id |
| 表单数据 | 写入过程记录和学习报告 | form_id、字段别名、附件 |
| 附件上传 | 同步学生实验图片 | file、mime、size、owner |

### 5.4 必须向超星取得的正式资料

- 生产和测试环境的接口基地址。
- 每个接口的 HTTP 方法、参数位置和字符编码。
- APPID/APPKEY 或其他应用凭证。
- 可申请的 scope 列表。
- 用户、课程、成员、成绩、表单和附件接口文档。
- 是否需要额外请求签名；如需要，提供算法、字段顺序、时间戳、nonce和样例。
- 单接口 QPS、日配额、并发数、批量上限和 429 处理规则。
- 错误码完整表。
- 数据权限边界和测试账号。
- 数据删除、修改、审计和保存期限要求。

## 6. 超星 OAuth 2.0 登录模块

### 6.1 完整流程

![超星OAuth授权码登录时序图，展示浏览器、Coze后端、超星认证中心和业务数据库之间十个步骤](./assets/02-oauth-flow-1920x1080.png)

*图 4：超星 OAuth 2.0 授权码登录全链路（1920×1080）。令牌交换和用户查询均由服务端执行。*

### 6.2 授权地址

```text
https://auth.chaoxing.com/connect/oauth2/authorize
  ?appid=<APP_ID>
  &redirect_uri=<URL_ENCODED_CALLBACK>
  &response_type=code
  &scope=snsapi_base
  &state=<FID>
```

正式代码不要手工拼接字符串，应使用 `URL` 和 `URLSearchParams` 自动编码。

### 6.3 发起登录的 Route Handler

```ts
// app/api/auth/chaoxing/login/route.ts
import { NextRequest, NextResponse } from "next/server";
import { randomBytes } from "node:crypto";

const AUTHORIZE_URL = "https://auth.chaoxing.com/connect/oauth2/authorize";

export async function GET(request: NextRequest) {
  const appid = process.env.CHAOXING_APPID;
  const redirectUri = process.env.CHAOXING_REDIRECT_URI;
  const allowedFids = (process.env.CHAOXING_FIDS ?? "")
    .split(",")
    .map((value) => value.trim())
    .filter(Boolean);

  if (!appid || !redirectUri || allowedFids.length === 0) {
    return NextResponse.json(
      { code: "OAUTH_NOT_CONFIGURED", message: "超星登录尚未配置" },
      { status: 503 },
    );
  }

  // 当前系统一次选择一个单位发起登录。
  // 官方文档把 state 用作 fid，因此这里不在 state 中塞入自定义 JSON。
  const fid = request.nextUrl.searchParams.get("fid") ?? allowedFids[0];
  if (!allowedFids.includes(fid)) {
    return NextResponse.json(
      { code: "FID_NOT_ALLOWED", message: "该单位不在允许登录范围内" },
      { status: 403 },
    );
  }

  const authorizeUrl = new URL(AUTHORIZE_URL);
  authorizeUrl.searchParams.set("appid", appid);
  authorizeUrl.searchParams.set("redirect_uri", redirectUri);
  authorizeUrl.searchParams.set("response_type", "code");
  authorizeUrl.searchParams.set("scope", "snsapi_base");
  authorizeUrl.searchParams.set("state", fid);

  // 官方把 state 固定用于 fid。额外生成一次性登录尝试 Cookie，
  // 回调时必须同时存在并与 fid 匹配，降低伪造回调风险。
  const attempt = `${fid}.${randomBytes(24).toString("base64url")}`;
  const response = NextResponse.redirect(authorizeUrl);
  response.cookies.set("cx_oauth_attempt", attempt, {
    httpOnly: true,
    secure: process.env.NODE_ENV === "production",
    sameSite: "lax",
    path: "/api/auth/callback/chaoxing",
    maxAge: 5 * 60,
  });
  return response;
}
```

### 6.4 使用授权码交换令牌

官方接口：

```text
POST https://auth.chaoxing.com/sns/oauth2/access_token/v1.0
```

```ts
// lib/chaoxing/oauth.ts
export type ChaoxingToken = {
  access_token: string;
  expires_time: string;
  refresh_token: string;
  openid: string;
  scope: string;
};

type ChaoxingError = {
  code?: number | string;
  describe?: string;
  errcode?: number | string;
  errmsg?: string;
};

export class ChaoxingOAuthError extends Error {
  constructor(
    public readonly errorCode: string,
    message: string,
    public readonly retryable = false,
  ) {
    super(message);
  }
}

export async function exchangeCodeForToken(code: string): Promise<ChaoxingToken> {
  const appid = process.env.CHAOXING_APPID;
  const secret = process.env.CHAOXING_SECRET;
  if (!appid || !secret) {
    throw new ChaoxingOAuthError("OAUTH_NOT_CONFIGURED", "缺少超星应用凭证");
  }

  const body = new URLSearchParams({
    appid,
    secret,
    code,
    grant_type: "authorization_code",
  });

  const response = await fetch(
    "https://auth.chaoxing.com/sns/oauth2/access_token/v1.0",
    {
      method: "POST",
      headers: { "content-type": "application/x-www-form-urlencoded" },
      body,
      cache: "no-store",
      signal: AbortSignal.timeout(8_000),
    },
  );

  const payload = (await response.json()) as ChaoxingToken | ChaoxingError;
  if (!response.ok || !("access_token" in payload)) {
    const code = String(
      "code" in payload ? payload.code : payload.errcode ?? "TOKEN_EXCHANGE_FAILED",
    );
    const message =
      ("describe" in payload ? payload.describe : payload.errmsg) ?? "获取令牌失败";
    throw new ChaoxingOAuthError(code, message, response.status >= 500);
  }

  return payload;
}
```

注意：

- 不要把 `secret` 放在 URL、前端包或浏览器请求中。
- 日志只记录错误码、请求ID和耗时，不能记录完整 `code`、token 或 secret。
- `code` 只能消费一次。应把 `SHA-256(code)` 写入唯一索引表，防止重复消费。
- 令牌接口超时不能盲目重试同一个 `code` 多次；先检查是否已在本地完成令牌落库。

### 6.5 刷新 access_token

官方文档说明 `refresh_token` 有效期为 30 天。接口：

```text
POST https://auth.chaoxing.com/sns/oauth2/refresh_token/v1.0
```

```ts
export async function refreshChaoxingToken(
  refreshToken: string,
): Promise<ChaoxingToken> {
  const appid = process.env.CHAOXING_APPID;
  if (!appid) {
    throw new ChaoxingOAuthError("OAUTH_NOT_CONFIGURED", "缺少 CHAOXING_APPID");
  }

  const response = await fetch(
    "https://auth.chaoxing.com/sns/oauth2/refresh_token/v1.0",
    {
      method: "POST",
      headers: { "content-type": "application/x-www-form-urlencoded" },
      body: new URLSearchParams({
        appid,
        grant_type: "refresh_token",
        refresh_token: refreshToken,
      }),
      cache: "no-store",
      signal: AbortSignal.timeout(8_000),
    },
  );

  const payload = (await response.json()) as ChaoxingToken | ChaoxingError;
  if (!response.ok || !("access_token" in payload)) {
    throw new ChaoxingOAuthError(
      String("errcode" in payload ? payload.errcode : "TOKEN_REFRESH_FAILED"),
      ("errmsg" in payload ? payload.errmsg : undefined) ?? "刷新令牌失败",
      response.status >= 500,
    );
  }
  return payload;
}
```

刷新策略：

1. 请求超星接口前检查 `expires_time`。
2. 距离过期不足 5 分钟时刷新。
3. 同一用户只允许一个刷新任务，使用数据库行锁或分布式锁。
4. 刷新成功后原子替换 access token、refresh token 和有效期。
5. 刷新失败且确认 refresh token 失效时，清除业务会话并重新授权。

### 6.6 获取用户身份信息

公开文档展示的接口地址：

```text
https://v1.chaoxing.com/backSchool/user/getUserByTokenFormMooc
```

入参为 `access_token`、`openid`、`expires_time` 和 `state`。其中 `state` 原样传入 `fid`。

```ts
export type ChaoxingUserInfo = {
  uid: string | number;
  name: string;          // 登录名，通常为学工号
  displayName: string;   // 姓名
  fid: string | number;
  orgName: string;
  role: Array<{ roleId: string | number; roleName: string }>;
  loginNames: string[];
};

export async function fetchChaoxingUserInfo(
  token: ChaoxingToken,
  fid: string,
): Promise<ChaoxingUserInfo> {
  const url = new URL(
    "https://v1.chaoxing.com/backSchool/user/getUserByTokenFormMooc",
  );
  url.searchParams.set("access_token", token.access_token);
  url.searchParams.set("openid", token.openid);
  url.searchParams.set("expires_time", token.expires_time);
  url.searchParams.set("state", fid);

  const response = await fetch(url, {
    method: "GET",
    cache: "no-store",
    signal: AbortSignal.timeout(8_000),
  });
  const payload = (await response.json()) as {
    status: boolean;
    userInfo?: ChaoxingUserInfo;
    msg?: string;
  };

  if (!response.ok || !payload.status || !payload.userInfo) {
    throw new ChaoxingOAuthError(
      "USER_INFO_FAILED",
      payload.msg ?? "获取超星用户信息失败",
      response.status >= 500,
    );
  }
  return payload.userInfo;
}
```

### 6.7 “身份信息解密”应如何理解

当前公开文档描述的用户信息响应是 JSON，没有给出需要应用方解密的加密字段算法。因此不要自行实现所谓“超星用户信息解密”。正确处理是：

- 通过 HTTPS 传输。
- 服务端携有效 token 请求。
- 校验响应结构、`fid`、角色和唯一标识。
- 将高敏令牌加密后存储。
- 不信任前端传入的学号、姓名、角色或 `fid`。

### 6.8 令牌 AES-256-GCM 加密存储

```ts
// lib/security/token-crypto.ts
import { createCipheriv, createDecipheriv, randomBytes } from "node:crypto";

function getKey(): Buffer {
  const raw = process.env.TOKEN_ENCRYPTION_KEY;
  if (!raw) throw new Error("TOKEN_ENCRYPTION_KEY 未配置");
  const key = Buffer.from(raw, "base64");
  if (key.length !== 32) throw new Error("TOKEN_ENCRYPTION_KEY 必须是32字节Base64");
  return key;
}

export function encryptToken(plainText: string): string {
  const iv = randomBytes(12);
  const cipher = createCipheriv("aes-256-gcm", getKey(), iv);
  const encrypted = Buffer.concat([
    cipher.update(plainText, "utf8"),
    cipher.final(),
  ]);
  const tag = cipher.getAuthTag();
  return [iv, tag, encrypted].map((part) => part.toString("base64url")).join(".");
}

export function decryptToken(cipherText: string): string {
  const [ivText, tagText, dataText] = cipherText.split(".");
  if (!ivText || !tagText || !dataText) throw new Error("令牌密文格式无效");
  const decipher = createDecipheriv(
    "aes-256-gcm",
    getKey(),
    Buffer.from(ivText, "base64url"),
  );
  decipher.setAuthTag(Buffer.from(tagText, "base64url"));
  return Buffer.concat([
    decipher.update(Buffer.from(dataText, "base64url")),
    decipher.final(),
  ]).toString("utf8");
}
```

### 6.9 回调全链路

```ts
// app/api/auth/callback/chaoxing/route.ts
import { createHash } from "node:crypto";
import { NextRequest, NextResponse } from "next/server";
import { exchangeCodeForToken, fetchChaoxingUserInfo } from "@/lib/chaoxing/oauth";
import { encryptToken } from "@/lib/security/token-crypto";
import { db } from "@/lib/db";
import { createSessionCookie } from "@/lib/auth/session";

export async function GET(request: NextRequest) {
  const code = request.nextUrl.searchParams.get("code");
  const state = request.nextUrl.searchParams.get("state");
  const attempt = request.cookies.get("cx_oauth_attempt")?.value;

  if (!code || !state || !attempt) {
    return NextResponse.redirect(new URL("/login-error?code=CALLBACK_INVALID", request.url));
  }

  const [attemptFid] = attempt.split(".");
  const allowedFids = (process.env.CHAOXING_FIDS ?? "").split(",");
  if (attemptFid !== state || !allowedFids.includes(state)) {
    return NextResponse.redirect(new URL("/login-error?code=FID_INVALID", request.url));
  }

  const codeHash = createHash("sha256").update(code).digest("hex");

  try {
    // 唯一索引阻止同一个 code 被重复消费。
    await db.oauthCodeConsumption.create({ data: { codeHash } });

    const token = await exchangeCodeForToken(code);
    const profile = await fetchChaoxingUserInfo(token, state);

    if (String(profile.fid) !== state) {
      throw new Error("用户信息中的 fid 与授权 state 不一致");
    }

    const result = await db.$transaction(async (tx) => {
      // provider_uid 使用 uid + fid，避免不同单位下的身份混淆。
      const identity = await tx.externalIdentity.upsert({
        where: {
          provider_providerUid_fid: {
            provider: "chaoxing",
            providerUid: String(profile.uid),
            fid: String(profile.fid),
          },
        },
        update: {
          loginName: profile.name,
          displayName: profile.displayName,
          roles: profile.role,
          lastLoginAt: new Date(),
        },
        create: {
          provider: "chaoxing",
          providerUid: String(profile.uid),
          fid: String(profile.fid),
          loginName: profile.name,
          displayName: profile.displayName,
          roles: profile.role,
          user: { create: { displayName: profile.displayName, status: "active" } },
        },
        include: { user: true },
      });

      await tx.oauthToken.upsert({
        where: { externalIdentityId: identity.id },
        update: {
          accessTokenCipher: encryptToken(token.access_token),
          refreshTokenCipher: encryptToken(token.refresh_token),
          openid: token.openid,
          expiresAt: new Date(token.expires_time),
        },
        create: {
          externalIdentityId: identity.id,
          accessTokenCipher: encryptToken(token.access_token),
          refreshTokenCipher: encryptToken(token.refresh_token),
          openid: token.openid,
          expiresAt: new Date(token.expires_time),
        },
      });
      return identity.user;
    });

    const response = NextResponse.redirect(new URL("/", request.url));
    response.cookies.delete("cx_oauth_attempt");
    await createSessionCookie(response, { userId: result.id });
    return response;
  } catch (error) {
    // 生产日志必须经过脱敏，不能直接输出 error 中可能携带的 URL 或 token。
    return NextResponse.redirect(new URL("/login-error?code=OAUTH_FAILED", request.url));
  }
}
```

### 6.10 会话维护

- 使用服务端签名会话或数据库会话。
- Cookie 设置 `HttpOnly`、`Secure`、`SameSite=Lax`。
- Cookie 中只保存随机会话ID或最小签名声明，不保存 access token。
- 会话空闲超时建议 2 小时，绝对有效期根据学校要求设置。
- 退出登录时删除本地会话；是否同时注销超星 Passport 由业务决定，不能默认影响用户其他超星页面。
- 教师权限不能只看 `roleName` 文本，应建立允许角色映射，并结合课程授权再次校验。

### 6.11 OAuth异常处理

| 场景 | 判断 | 处理 |
|---|---|---|
| 用户取消或授权失败 | 回调无 code 或带错误参数 | 显示可重试页面，不创建会话 |
| code 过期 | 官方错误 10017 或超过5分钟 | 重新发起授权，不重复使用旧code |
| code 已使用 | code哈希唯一约束冲突 | 返回幂等结果或重新登录 |
| redirect_uri 不一致 | 错误10003 | 核对开发/生产域名、路径和协议 |
| 超星账号未登录 | 错误10013 | 引导先登录泛雅/学习通再授权 |
| scope 无权限 | 10005/10012 | 停止调用并申请权限，不循环重试 |
| access token 过期 | 到达 expires_time | 使用 refresh token 刷新 |
| refresh token 失效 | 10021或超过30天 | 清理令牌，重新授权 |
| fid 不允许 | 回调state或用户fid不在白名单 | 拒绝访问，不创建业务用户会话 |
| 角色不满足 | 无学生/教师允许角色 | 显示权限不足，记录审计 |
| 超星5xx/超时 | 网络或服务异常 | 有限重试，提供request_id |

### 7.2 为什么采用 outbox

如果业务保存成功后直接同步超星，会出现两类问题：

- 超星暂时失败，学生提交也跟着失败。
- 业务已成功但请求超时，重试后在超星产生重复记录。

正确做法是在同一个本地数据库事务中：

1. 保存业务数据。
2. 保存 `sync_outbox` 事件。
3. 立即向用户返回成功。
4. 后台 Worker 异步同步。
5. 使用 `event_id/request_id` 去重。

### 7.4 请求参数与签名规范

#### 已确认的 OAuth 接口

- 使用 HTTPS。
- 令牌交换和刷新使用 POST。
- 参数按官方文档作为默认键值对发送。
- OAuth公开页面没有要求额外请求签名。
- 鉴权核心是 APPID、APPKEY、code、access token 和 refresh token。

#### 尚未确认的课程/成绩/表单接口

公开 OAuth 文档没有提供统一的 HMAC 签名算法，也没有提供统一 QPS。因此：

- 不得把网上其他超星产品线的签名算法直接套用。
- 不能假定所有接口都使用 `md5(appKey + params)`。
- 必须取得目标接口的正式文档和成功请求样例。
- 签名逻辑放在独立策略中，不能散落在业务代码。

下面代码仅展示“如果正式文档明确要求 HMAC-SHA256”的实现方式，不代表超星当前接口实际采用该算法：

```ts
// lib/chaoxing/signature.ts
import { createHmac } from "node:crypto";

export function signWithHmacSha256(
  params: Record<string, string>,
  secret: string,
): string {
  // 字段排序、空值处理、分隔符和编码方式必须以正式接口文档为准。
  const canonical = Object.entries(params)
    .filter(([, value]) => value !== "")
    .sort(([a], [b]) => a.localeCompare(b))
    .map(([key, value]) => `${key}=${encodeURIComponent(value)}`)
    .join("&");

  return createHmac("sha256", secret)
    .update(canonical, "utf8")
    .digest("hex");
}
```

在取得正式签名文档前，该策略必须保持未启用。

### 7.5 用户基础信息查询

用户信息查询使用第 6.6 节已经确认的 OAuth 用户信息接口。建议缓存：

- 登录时强制查询一次。
- `uid/fid` 作为稳定外部身份键。
- 姓名、学工号、角色缓存 15 分钟到 1 小时。
- 涉及教师权限的高风险操作再次查询或使用较短缓存。
- 角色变化后更新本地映射并记录审计。

### 7.9 缓存策略

| 数据 | 建议缓存 | 失效方式 |
|---|---:|---|
| 用户基础信息 | 15分钟～1小时 | 登录、角色敏感操作或超时刷新 |
| 课程列表 | 5～15分钟 | 定时增量同步或教师手动刷新 |
| 课程成员 | 5分钟 | 权限操作前必要时强制刷新 |
| 成绩 | 1～5分钟或不缓存 | 按教学要求和接口压力确定 |
| 表单写入结果 | 不作为读缓存 | 保存 external_record_id 和同步状态 |
| access token | 保存到服务端令牌表 | expires_time 前5分钟刷新 |

缓存键必须包含 `fid`、接口类型、用户/课程标识和接口版本，防止跨单位串数据。

### 7.10 重试机制

```ts
export async function withRetry<T>(
  operation: () => Promise<T>,
  maxAttempts = 4,
): Promise<T> {
  let lastError: unknown;
  for (let attempt = 1; attempt <= maxAttempts; attempt += 1) {
    try {
      return await operation();
    } catch (error) {
      lastError = error;
      if (attempt === maxAttempts) break;

      // 指数退避 + 随机抖动，避免所有任务同时重试。
      const base = Math.min(30_000, 500 * 2 ** (attempt - 1));
      const jitter = Math.floor(Math.random() * 300);
      await new Promise((resolve) => setTimeout(resolve, base + jitter));
    }
  }
  throw lastError;
}
```

重试原则：

- 网络超时、429、502、503、504：可重试。
- 参数错误、无权限、签名错误、fid不允许：不可自动重试。
- OAuth `code` 不能无条件重试，因为只能使用一次。
- 写请求必须带稳定幂等键。
- 达到最大次数后转 `dead_letter` 并告警，不能无限循环。

### 7.11 数据一致性

- **唯一来源**：实验状态和回答版本以业务数据库为准。
- **字段所有权**：超星拥有用户、课程和官方成绩；业务系统拥有AI评阅和实验状态。
- **冲突处理**：同步前比较 `updated_at/version`；不允许旧数据覆盖新数据。
- **幂等**：`source + event_id` 唯一，重复回调或重试返回同一结果。
- **检查点**：拉取课程/成绩保存游标或更新时间。
- **对账**：每天比较待同步数、成功数、失败数和超星侧记录ID。
- **补偿**：失败事件修复后重放，不直接修改原业务记录。

### 7.12 频率限制

当前公开 OAuth 页面能确认错误 `10007 操作太频繁了`，但未公布统一 QPS。应用必须：

- 通过环境变量配置每个接口的 QPS 和并发数。
- 按用户、单位和接口分别限速。
- 对 429/10007 执行退避。
- 优先批量、增量和缓存，避免逐学生循环调用。
- 正式上线前向超星确认峰值班级规模下的限流参数。

4. 在超星开放平台登记为开发回调。
5. 在 Coze 预览环境变量中配置同一地址。
6. 重启预览应用。
7. 测试 code、token、用户信息、fid 和角色。

### 8.4 正式环境

1. 在 Coze 点击部署并设置生产环境变量。
2. 获得或配置 `*.coze.site` 正式域名。
3. 构造正式回调地址。
4. 在超星平台增加正式回调地址。
5. 开启 `ENABLE_CHAOXING_AUTH=true`。
6. 关闭演示教师入口和测试身份。
7. 部署后从超星入口做真实端到端验证。

## 9. 安全配置

### 9.1 密钥

- APPKEY 和 token 只进入服务端环境变量或加密数据库字段。
- 不把 Secret 写进源码、Markdown示例、客户端 JavaScript、日志或截图。
- 开发、测试、生产使用不同密钥。
- 定期轮换；人员离职或泄露时立即吊销。
- Supabase RLS 不能替代服务端权限校验，service role key 不得传到浏览器。

### 9.2 通信

- 生产全部使用 HTTPS。
- 回调域名、协议、端口和路径完全匹配。
- 设置 HSTS、CSP、`X-Content-Type-Options` 和安全 Cookie。
- 服务端请求配置连接和总超时。
- 不关闭 TLS 证书校验。

### 9.3 身份和权限

- 不信任前端上报的角色。
- 业务用户与超星身份一对多建模，支持单位变更。
- 每个请求校验用户、课程、班级和资源的数据域。
- 教师查看学生数据必须同时满足角色和课程授权。
- OAuth回调记录审计，但不记录令牌明文。

### 9.4 数据保护

- 学号、姓名和成绩按最小必要原则保存。
- 学生上传图片使用私有存储和短时签名URL。
- 图片移除 EXIF；对象名不包含姓名和学号。
- 制定测试数据与正式数据分离、保存期限和删除流程。

## 10. 日志、监控与告警

### 10.1 结构化日志字段

```json
{
  "timestamp": "2026-08-14T10:00:00+08:00",
  "level": "error",
  "request_id": "req_01...",
  "event": "chaoxing_token_exchange_failed",
  "provider": "chaoxing",
  "fid": "1385",
  "http_status": 502,
  "error_code": "10006",
  "duration_ms": 1820,
  "retryable": true
}
```

禁止日志字段：完整 code、access token、refresh token、APPKEY、Cookie、完整学生回答和原始图片URL。

### 10.2 核心指标

- OAuth发起、成功、失败和取消次数。
- code交换成功率与耗时。
- token刷新成功率。
- 用户信息接口成功率。
- fid/角色拒绝次数。
- 各同步目标 pending、retry、dead_letter 数量。
- 超星接口 QPS、429、5xx 和超时率。
- 数据对账差异数。

### 10.3 告警建议

- 5分钟内 OAuth 失败率超过 10%。
- token交换连续失败 5 次。
- `sync_outbox` 最老待处理事件超过 10 分钟。
- dead_letter 出现任何新增。
- 429 持续超过 5 分钟。
- APPKEY/令牌疑似出现在日志扫描结果中。

## 11. 常见问题排查

### 11.1 回调提示 10003

原因：`redirect_uri` 域名与后台配置不一致。

排查顺序：

1. 查看浏览器实际回调地址。
2. 对比协议、域名、端口、路径和末尾斜杠。
3. 区分 `.dev.coze.site` 和 `.coze.site`。
4. 检查环境变量修改后是否重启/重新部署。

### 11.2 10013 未登录

1. 确认用户已在同一浏览器登录超星 Passport/泛雅。
2. 不要切换到丢失登录状态的浏览器或隐私窗口。
3. 重新从超星应用入口进入。

### 11.3 code 无效或过期

1. code是否超过5分钟。
2. 是否被回调处理两次。
3. 是否因页面刷新重复请求。
4. 本地 `oauth_code_consumptions` 是否已有哈希。
5. 重新发起登录，不复用旧URL。

### 11.4 token能获取但用户信息失败

1. 确认使用的是网页授权 access token，不是其他产品 token。
2. `openid`、`expires_time`、`state` 必须原样传输并正确编码。
3. 确认 state 与 fid 一致。
4. 检查令牌是否过期。
5. 比较官方“有角色/无角色/安全”接口的实际授权范围。

### 11.5 表单能手工写入但代码不能写入

这通常说明：

- 已验证的是后台任务流节点能力，不是公开 HTTP API。
- 任务流尚未发布为可外部调用的接口。
- 缺少外部调用鉴权、入参规范或文件上传接口。

处理：在任务流发布页取得真实调用地址、鉴权、请求样例和限流，再填写 `CHAOXING_FORM_WRITE_URL`。不要抓取浏览器内部请求当生产接口。

### 11.6 课程或成绩接口无法调用

1. 确认应用 scope 是否包含该权限。
2. 确认学校是否批准课程/成绩数据访问。
3. 使用对方提供的测试账号和成功样例。
4. 检查签名、时间戳和参数顺序。
5. 不要用 OAuth 用户接口文档推测课程接口地址。

### 11.7 频繁出现 429 或 10007

- 降低应用侧 QPS。
- 使用缓存和增量同步。
- 合并批量请求。
- 增加指数退避。
- 向超星确认正式配额，而不是不断重试。

## 14. 最终实施结论

本系统应采用“双层数据 + 服务端OAuth + 异步同步”方式落地：

- Next.js/Supabase 负责复杂业务事务、状态、版本和AI过程。
- 超星 OAuth 负责校内统一身份认证。
- 超星开放接口、表单或任务流负责经授权的数据读取和校内结果留痕。
- 所有外部写入通过 outbox、幂等键、退避和对账保证可靠性。
- 课程、成绩、表单调用不能在没有正式接口文档时通过猜测或抓取内部请求实现。

登录模块已经具备公开文档支撑，可以按本文直接开发；课程、成绩和表单服务端写入必须在取得学校/超星的正式接口地址、权限、签名和限流规则后完成最终联调。
