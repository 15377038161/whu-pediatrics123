# 超星身份验证登录接入技术实施手册

> 适用项目：武汉大学生物化学文字实验智能体<br>
> 运行环境：Coze 部署的 Next.js 应用<br>
> 当前技术栈：Next.js 16、React 19、TypeScript 5、Supabase、pnpm<br>
> 文档版本：2.0（2026-08-26）

---

## 0. 文档定位与执行边界

本手册用于指导开发者或通用编程 AI，在一个 Web 项目中完整接入超星/学习通身份验证，并建立本地用户、登录会话和权限控制。读者不需要查阅本项目聊天记录。

完成后应交付：

1. 唯一的“使用学习通身份进入”入口；
2. 服务端发起超星 OAuth 授权；
3. 服务端用一次性 code 换取网页授权 access_token；
4. 服务端查询、校验并归一化用户身份；
5. 超星身份与本地用户的创建或绑定；
6. 安全的本地会话；
7. 基于稳定 roleId 的学生/教师权限控制；
8. 异常处理、安全测试、构建和真实环境验收。

本文信息分四类：

| 标签 | 含义 | 能否直接用于生产 |
|---|---|---|
| **官方已确认** | 来自超星公开开发文档，并与当前实现一致 | 可以，上线前仍核对租户配置 |
| **项目已实现** | 当前仓库已有代码 | 可以，改动后需重新测试 |
| **待校方/超星确认** | 取决于学校租户、审批或未公开合同 | 不得猜测 |
| **通用示例** | 跨技术栈参考代码 | 必须按目标项目适配 |

禁止事项：

- 不抓取浏览器 Cookie、localStorage、登录态或内部请求作为生产接口；
- 不把 AppSecret、access_token、refresh_token、Supabase service role key 放进前端；
- 不根据“教师/teacher”等角色名称授予教师权限；
- 不臆造签名算法、QPS、课程接口、成绩接口或表单写入地址；
- 没有正式凭据和真实回读证据时，不宣称“生产已接通”；
- 不盲目重试可能已经被超星消费的一次性 code。

完成状态必须区分：

| 状态 | 判定条件 |
|---|---|
| 代码闭环 | mock 契约测试、类型检查、权限测试、构建通过 |
| 预览联调通过 | Coze 预览回调和超星测试账号真实登录成功 |
| 生产接通 | 正式域名、正式凭据、FID、roleId 与权限端到端通过 |

## 1. 前置准备

### 1.1 应用类型与资质

超星公开文档提供自建应用和市场应用两种方式。校内教学应用通常使用自建应用，最终由武汉大学和超星管理员确认。

实施前必须确认：

1. 开发者/单位账号已在超星微服务开放平台注册；
2. 单位或企业资质审核通过；
3. 已创建应用并取得 AppID、AppSecret/APPKEY；
4. 已配置 PC、移动端等实际运行地址；
5. 学校已批准读取姓名、学工号、单位和角色；
6. 已提供测试学生、测试教师和测试 FID；
7. 课程、成绩、通讯录、表单等权限单独申请；登录权限不等于业务数据权限。

### 1.2 必须取得的资料

| 项目 | 必填 | 用途 | 保存位置 |
|---|---:|---|---|
| AppID | 是 | 标识应用 | 服务端环境变量 |
| AppSecret/APPKEY | 是 | code 换 token | 服务端密钥管理 |
| 允许 FID | 是 | 限定机构 | 服务端白名单 |
| PC/移动端运行地址 | 是 | 学习通入口 | 超星后台 |
| OAuth 回调地址 | 是 | 接收 code/state | 超星后台和环境变量 |
| 教师 roleId | 是 | 权限映射 | 环境变量或授权表 |
| 测试账号 | 是 | 真实联调 | 校方保管，禁止入库 |
| scope | 是 | 最小权限 | 超星后台 |
| 测试/正式划分 | 建议 | 隔离数据和密钥 | 双方环境 |

### 1.3 回调域名、备案和白名单

- 生产回调使用 HTTPS；
- 协议、域名、端口、路径和末尾斜杠必须与后台逐字符一致；
- 预览域名与正式域名分别登记；
- 不把前端 hash 路由用作服务端回调；
- 是否要求 ICP 备案、域名所有权证明、IP 白名单和安全评审属于“待校方/超星确认”；
- 公网服务部署在中国大陆时，同时遵守云服务商和现行法规的备案要求。

### 1.4 最小权限

仅做身份登录时申请：

- 获取授权 code；
- 换取网页授权 access_token；
- 获取用户基本信息、FID 和角色。

按需另行申请：

- 通讯录；
- 课程、班级、成员；
- 成绩读写；
- 表单/数据源写入；
- 消息推送。

### 1.5 技术栈兼容

后端语言不限，但必须能：

- 创建服务端路由；
- 发起 HTTPS POST 表单请求；
- 安全保存服务端密钥；
- 设置安全 Cookie 或等价服务端会话；
- 持久化外部身份与本地用户绑定；
- 在服务端执行角色和资源权限检查。

推荐：Node.js 当前 LTS；或 Java 17 + Spring Boot 3.x；UTF-8；TLS 1.2+。浏览器覆盖 Chrome、Edge、Safari 当前及前两个主版本，以及学习通内置 WebView。

当前项目固定 Next.js 16、React 19、TypeScript 5、Supabase、pnpm，不得改用 npm/yarn。

### 1.6 网络访问

| 目标 | 端口 | 用途 |
|---|---:|---|
| auth.chaoxing.com | 443 | 授权和 token |
| auth.open.chaoxing.com | 443 | 官方开发文档 |
| v1.chaoxing.com | 443 | 用户信息 |
| Supabase 项目域名 | 443 | 用户和会话 |
| Coze 正式域名 | 443 入站 | 回调和业务访问 |

若超星强制固定出口 IP，而 Coze 无稳定出口，应增加校方控制的服务端网关；不得改成浏览器请求来绕过白名单。

## 2. 整体流程

### 2.1 推荐架构

~~~mermaid
flowchart LR
  U[用户浏览器/学习通 WebView] -->|点击统一登录| A[应用后端 /auth/start]
  A -->|302 授权地址| X[超星授权服务]
  X -->|code + state| C[应用后端 /auth/callback]
  C -->|POST code + Secret| T[超星 Token 接口]
  T -->|token/openid/expiry| C
  C -->|服务端查询| I[超星用户信息接口]
  I -->|uid/fid/学工号/姓名/roleId| C
  C --> B[本地身份绑定与角色映射]
  B --> S[创建本地会话]
  S -->|Secure Cookie + 302| U
  U -->|本地会话| P[学生端/教师端]
~~~

浏览器只负责顶层跳转和使用本地会话。AppSecret、超星 token 和用户信息调用全部留在服务端。

### 2.2 完整时序

~~~mermaid

  User->>FE: 点击“使用学习通身份进入”
~~~

### 2.3 前后端责任

| 节点 | 前端 | 后端 |
|---|---|---|
| 登录入口 | 按钮、禁用态、埋点 | 配置状态 |
| 发起授权 | 顶层跳转到本应用 | 拼 URL、校验 FID/next、上下文 |
| 回调 | 不解析 Secret/token | code/state 校验和换 token |
| 身份 | 不调超星接口 | 查询、校验、归一化 |

| 错误 | 重试/联系管理员 | 分类、脱敏日志、监控 |

## 3. 超星 OAuth 协议契约

### 3.1 授权地址

**官方已确认：**

~~~text
GET https://auth.chaoxing.com/connect/oauth2/authorize
~~~

| 参数 | 必填 | 值/规则 |
|---|---:|---|
| appid | 是 | 超星分配 |
| redirect_uri | 是 | URL 编码；与后台一致 |
| response_type | 是 | code |
| scope | 是 | snsapi_base 或获批范围 |
| state | 是 | 用户所属机构 FID |

通常 OAuth 的 state 是随机 CSRF nonce；超星公开文档在此流程中要求 state 传 FID，并在用户信息接口原样传回。因此应用需额外使用短时、签名、HttpOnly、SameSite=Lax 的登录上下文 Cookie，或服务端一次性事务，绑定发起和回调。

### 3.2 code

官方确认：

- 每次授权的 code 不同；
- code 只能使用一次；
- 5 分钟未使用即过期；
- 回调可能带 error/error_description。

应用还要检查：非空、trim 后长度不超过 2048、不写日志、并发只消费一次。

生产高并发建议：

~~~sql
create table oauth_code_consumptions (
  provider text not null,
  code_hash text not null,
  status text not null check (status in ('processing','succeeded','failed')),
  created_at timestamptz not null default now(),
  expires_at timestamptz not null,
  primary key (provider, code_hash)
);
~~~

仅保存 SHA-256 摘要，绝不保存 code 明文。

### 3.3 token 接口

**官方已确认：**

~~~text
POST https://auth.chaoxing.com/sns/oauth2/access_token/v1.0
Content-Type: application/x-www-form-urlencoded

appid=...
secret=...
code=...
grant_type=authorization_code
~~~

成功字段：

~~~json
{
  "access_token": "server-only",
  "expires_time": "yyyy-MM-dd HH:mm:ss",
  "refresh_token": "server-only-if-used",
  "openid": "provider-user-key",
  "scope": "snsapi_base"
}
~~~

失败通常包含 code 和 describe；解析器也应容忍 error、errorMsg、errmsg、msg 等历史字段。

### 3.4 用户信息接口

**官方已确认：**

~~~text
POST https://v1.chaoxing.com/backSchool/user/getUserByTokenFormMooc
Content-Type: application/x-www-form-urlencoded

access_token=...
openid=...
expires_time=...
state={FID}
~~~

| 超星字段 | 含义 | 本地建议字段 |
|---|---|---|
| openid | 应用范围用户标识 | provider_subject |
| uid | 超星用户 ID | provider_uid |
| name | 登录名/学工号 | student_no |
| displayName | 姓名 | display_name |
| fid | 机构 FID | institution_id |
| orgName | 单位名 | institution_name |
| role[].roleId | 稳定角色 ID | external_role_ids |
| role[].roleName | 展示角色名 | 仅展示/审计 |
| loginNames | 单位下登录名 | external_login_names |

注意：name 是学工号/登录名，displayName 才是姓名。

### 3.5 签名、解密和 token 保存

当前已确认的 OAuth token 和用户信息接口没有额外 HMAC/MD5 签名，按默认键值对提交。AppSecret 是服务端凭据，不是前端签名。

用户信息是 JSON，不需要解密，只需校验 HTTP、解析 unknown、验证 status/userInfo、收窄类型并映射。

若校方提供的其他网关要求签名/加密，只能按正式文档实现参数排序、编码、时间戳、算法和 header；放到独立 Signer/Decryptor，并用官方成功样例做契约测试。未取得契约时保持关闭。

仅用于登录时，查询身份后可不持久化超星 token。后续确需调用获批业务接口时，才在服务端加密保存并按 expires_time 刷新。浏览器永远不得得到超星 access_token/refresh_token。

### 3.6 官方授权错误码

| 码 | 含义 | 处理 |
|---:|---|---|
| 10002 | response_type 错误 | 固定 code |
| 10003 | redirect_uri 不一致 | 核对后台 |
| 10004 | 应用封禁 | 联系平台 |
| 10005 | scope 不足 | 申请权限 |
| 10006 | 稍后重试 | 有限退避 |
| 10007 | 频率过高 | 限速退避 |
| 10008 | scope 为空 | 修配置 |
| 10009 | redirect_uri 为空 | 修配置 |
| 10010 | appid 为空 | 修配置 |
| 10011 | state 为空 | 配置 FID |
| 10012 | 平台未授权 | 完成授权 |
| 10013 | 账号未登录 | 先登录学习通 |
| 10014 | secret 为空 | 修服务端密钥 |
| 10015 | secret 错误 | 核对/轮换 |
| 10016 | code 为空 | 重新授权 |
| 10017 | code 无效 | 重新授权，不复用 |
| 10018/10019 | grant_type 缺失/错误 | authorization_code |
| 10020/10021 | refresh_token 缺失/错误 | 重新授权或修刷新 |
| 10022/10023 | 参数顺序/个数错误 | 按正式文档调整 |
| 10025 | FID 为空 | 校验 state |
| 10026 | fid_token 无效 | 重新取凭证 |

## 4. 前端接入

### 4.1 唯一入口

当前项目只保留：

- 根路由 /：介绍和统一登录；
- /login：重定向到 /；
- /api/auth/chaoxing：发起授权；
- /auth/error：统一错误页。

不要创建并行的学生登录、教师登录、游客登录或第二个介绍页。

### 4.2 登录按钮与埋点

~~~tsx
"use client";
import { useState } from "react";

export function ChaoxingLoginButton({ fid }: { fid?: string }) {
  const [loading, setLoading] = useState(false);

  function login() {
    if (loading) return;
    setLoading(true);
    window.dispatchEvent(new CustomEvent("analytics", {
      detail: {
        event: "chaoxing_login_click",
        page: "login",
        institutionSelected: Boolean(fid)
      }
    }));
    const url = new URL("/api/auth/chaoxing", window.location.origin);
    if (fid) url.searchParams.set("fid", fid);
    url.searchParams.set("next", "/student");
    window.location.assign(url.toString());
  }

  return (
    <button type="button" disabled={loading} onClick={login}>
      {loading ? "正在前往学习通…" : "使用学习通身份进入"}
    </button>
  );
}
~~~

推荐事件：

| 事件 | 字段 |
|---|---|
| chaoxing_login_view | page、configured、deviceClass |
| chaoxing_login_click | page、institutionSelected |
| chaoxing_login_redirect | requestId、fidMasked |
| chaoxing_login_success | requestId、roleCategory、durationMs |
| chaoxing_login_failure | requestId、reason、stage |

禁止埋点 code、token、Secret、Cookie、完整 openid、姓名、学号。

### 4.3 跳转链接与 CORS

授权 URL 由后端拼接，前端只跳本应用路由：

~~~ts
const url = new URL("https://auth.chaoxing.com/connect/oauth2/authorize");
url.searchParams.set("appid", appid);
url.searchParams.set("redirect_uri", redirectUri);
url.searchParams.set("response_type", "code");
url.searchParams.set("scope", "snsapi_base");
url.searchParams.set("state", allowedFid);
return Response.redirect(url, 302);
~~~

前端不对超星 API 发 XHR/fetch。授权是顶层导航，token/用户信息由后端请求，因此不需要把超星接口做 CORS 放行。前后端分离时，本地 API 只允许明确 Origin；credentials=true 时不能使用通配符。

### 4.4 回调参数

推荐后端回调，前端不接触 code。处理顺序：

1. error/error_description；
2. code 是否存在；
3. state/FID 是否允许；
4. 短时登录上下文；
5. token 和身份；
6. 本地会话；
7. 302 到安全 nextPath。

若技术限制必须先进入前端回调页，页面只能立刻把 query 提交给同源后端，不写控制台、不写监控、不进本地存储。

### 4.5 本地 Token/会话存储

最佳实践：

- 超星 token：服务端内存或加密服务端存储；
- 本地会话：Secure、HttpOnly、SameSite=Lax Cookie；
- 状态修改：SameSite + CSRF token 或 Origin 校验；
- 登录/提权后轮换 sessionId；
- 不在 localStorage/sessionStorage/URL 存长期 token。

当前项目因 Supabase 浏览器 SDK 需要，Supabase 会话 Cookie 暂为 JavaScript 可读，必须配合严格 CSP 和 XSS 测试。若数据访问全部迁移到服务端 BFF，应改为 HttpOnly。

### 4.6 前端异常

| 场景 | 内部原因 | 提示与动作 |
|---|---|---|
| 用户取消 | oauth_cancelled | 已取消授权；重新登录 |
| code 超时 | oauth_failed | 登录已过期；重新进入 |
| 未登录学习通 | 10013 | 先登录学习通 |
| 机构不匹配 | institution_mismatch | 切换账号/联系教师 |
| 服务未配置 | config_missing | 登录暂未开放；联系管理员 |
| 本地会话失败 | session_failed | 稍后重试 |
| 无教师权限 | forbidden | 返回学生端 |

错误页显示 requestId、重新登录、返回首页；不得显示堆栈或原始响应。

## 5. 后端接入

### 5.1 路由

| 方法 | 路由 | 作用 |
|---|---|---|
| GET | /api/auth/chaoxing | 发起授权 |
| GET | /api/auth/callback/chaoxing | OAuth 回调 |
| GET | /api/auth/me | 当前用户和能力 |
| POST | /api/auth/logout | 退出 |

### 5.2 发起授权

1. 检查功能开关和全部必填配置；
2. next 只允许以 / 开头且不以 // 开头；
3. fid 必须在白名单；
4. 生成 10 分钟签名登录上下文；
5. 302 到超星，设置 Cache-Control: private, no-store。

### 5.3 code 校验与 token

~~~ts
function requireCode(value: string | null): string {
  const code = value?.trim() ?? "";
  if (!code || code.length > 2048) throw new Error("OAUTH_CODE_INVALID");
  return code;
}

async function exchangeCode(code: string, config: OAuthConfig) {
  const response = await fetch(
    "https://auth.chaoxing.com/sns/oauth2/access_token/v1.0",
    {
      method: "POST",
      headers: { "content-type": "application/x-www-form-urlencoded" },
      body: new URLSearchParams({
        appid: config.appid,
        secret: config.secret,
        code,
        grant_type: "authorization_code"
      }),
      cache: "no-store",
      signal: AbortSignal.timeout(10_000)
    }
  );
  const raw = await response.text();
  const payload: unknown = JSON.parse(raw);
  if (!response.ok) throw new Error("PROVIDER_HTTP_ERROR");
  return validateTokenPayload(payload);
}
~~~

不得记录请求 body、原始响应或 token。

### 5.4 重试

| 调用 | 可重试 | 建议上限 | 不可重试 |
|---|---|---:|---|
| code 换 token | 明确发生在发送前的连接错误 | 0～1 | 响应结果未知、4xx、业务错 |
| 用户信息 | 超时、429、502/503/504 | 2 | 400/401/403、status=false |
| 本地 DB | 短时连接错误 | 2 | 唯一/校验/权限错误 |

code 一次性；请求结果未知时重新开始 OAuth，不盲目重放。退避可用 300ms、600ms 加 0～250ms 随机抖动。

### 5.5 身份归一化

~~~ts
type NormalizedIdentity = {
  provider: "chaoxing";
  subject: string;
  uid: string;
  studentNo: string;
  displayName: string;
  institutionId: string;
  institutionName: string;
  roleIds: string[];
  roleNames: string[];
};
~~~

解析时：

- 所有 ID 允许数字或字符串，最终转字符串；
- uid 缺失直接失败；
- displayName 缺失时回退 name/uid；
- role 不是数组时视为空；
- roleName 仅展示；
- 不把 status=false 当成功。

### 5.6 本地绑定/创建

推荐唯一键：

~~~text
(provider=chaoxing, institution_id=fid, provider_subject=openid)
~~~

事务步骤：

1. 查询 external_identity；
2. 已绑定则更新显示名、学号、角色快照、last_login_at；
3. 未绑定则检查管理员预绑定；
4. 创建本地 user/profile；
5. 创建唯一 external_identity；
6. 唯一冲突时重新查询，避免并发重复；
7. 计算服务端 capabilities；
8. 提交后创建会话。

不得按姓名自动合并账号。

### 5.7 角色和权限

- 默认学生：studentWorkspace=true；
- 只有 roleId 在 CHAOXING_TEACHER_ROLE_IDS 或 teacher_role_grants 中才是教师；
- roleName 不参与授权；
- 未配置教师 roleId 时一律不授予教师权限；
- 教师可有 studentWorkspace、teacherWorkspace、teacherPractice；
- 学生访问教师页面/API 必须服务端返回 403；
- 还要校验教师对具体班级/课程的资源范围。

## 7. 安全与合规

### 7.1 Secret、签名与加密

- Secret 只在服务端密钥管理；
- Git、构建包、日志、截图不得出现凭据；
- 开发/测试/生产使用不同密钥；
- 支持轮换和吊销；
- 不收集超星密码；
- 不把已登录浏览器 Cookie 转交后端或 AI。

如必须持久化 provider token，使用 KMS 或 AES-256-GCM 信封加密；每条独立 nonce，保存 keyVersion/ciphertext/nonce/authTag，主密钥与数据库分离。禁止 ECB、固定 IV 或 Base64 冒充加密。

### 7.2 防 CSRF、防重放攻击与开放重定向

- state=FID 时，以签名短时 Cookie/服务端事务补充请求绑定；
- 登录上下文 10 分钟过期并在回调后清除；
- next 仅允许站内路径，拒绝 // 和完整外链；
- code 单次消费并保存哈希；
- 回调限速；
- 成功后 302 清除 URL 中 code。

其他正式接口若要求 timestamp/nonce：

1. 按合同校验时间窗口；
2. nonce 在窗口内唯一；
3. timing-safe 比较签名；
4. canonical string 与官方样例逐字一致；
5. 签名失败不重试。

### 7.3 防越权

教师接口同时要求：有效会话、teacherWorkspace 能力、目标班级/课程授权、学生归属、操作类型允许。前端隐藏不是权限控制；API 和数据库 RLS/RPC 都需校验。

### 7.4 Cookie 与浏览器

推荐 Secure、HttpOnly、SameSite=Lax、Path=/、合理 Max-Age；登录后轮换 sessionId；退出时服务端撤销。配置 CSP、nosniff、Referrer-Policy 和最小 Permissions-Policy。若学习通需要 iframe，frame-ancestors 要按实际嵌入域名配置，不能盲目 DENY。

### 7.5 个人信息保护

- 目的明确、最小必要、告知同意；
- 只保存登录和教学必需字段；
- 姓名、学号、角色和成绩分级授权；
- 不用于未告知的模型训练；
- 提供更正、删除、导出、解绑流程；
- 测试使用专用账号/脱敏数据；
- 日志仅留摘要；
- 到期删除或匿名化。

建议审计日志：

~~~json
{
  "event": "chaoxing_login_failed",
  "requestId": "req_xxx",
  "stage": "token_exchange",
  "internalReason": "oauth_failed",
  "providerCode": "10017",
  "fidHash": "sha256:...",
  "durationMs": 832,
  "retryable": false
}
~~~

禁止日志字段：code、token、Secret、Cookie、完整 openid、完整学号、姓名。

## 9. 故障排查（18 类）

统一排查顺序：浏览器实际 URL → requestId → 环境变量 → 超星后台 → 服务端网络 → 数据库。

### 9.1 点击登录无反应

根因：按钮被遮挡、disabled 未恢复、前端异常或链接错误。

1. Network 应出现 GET /api/auth/chaoxing；
2. 检查控制台错误；
3. 检查透明层/弹窗是否遮挡按钮；
4. 直接打开 /api/auth/chaoxing；
5. 登录失败后确保 loading 能恢复。

### 9.2 授权跳转失败

1. 脱敏复制实际 Location；
2. response_type 必须为 code；
3. scope 必须获批；
4. state 必须为白名单 FID；
5. 对照 10002/10005/10008/10010/10011。

### 9.3 10003 回调不一致

1. 解码实际 redirect_uri；
2. 对比协议、域名、端口、路径、斜杠；
3. 区分 dev.coze.site 与 coze.site；
4. 修改环境变量后重新部署；
5. 本地回调不能使用只登记了生产域名的应用。

### 9.4 10013 账号未登录

1. 同一浏览器/WebView 登录 Passport；
2. 不要切隐私窗口；
3. 从学习通应用入口重进；
4. 检查内置 WebView 与系统浏览器是否共享登录态。

### 9.5 回调没有 code

1. 先查 error/error_description；
2. 确认代理保留 query；
3. 回调必须允许 GET；
4. 只记录 query 键，不记录值；
5. 重新授权，不能构造 code。

### 9.6 code 无效、过期或重复

1. 授权到回调是否超过 5 分钟；
2. 是否刷新了回调页；
3. 代理是否重放；
4. code_hash 是否已存在；
5. 重新开始 OAuth。

### 9.7 token 返回非 JSON

1. 记录状态码、Content-Type、长度和 requestId；
2. 不记录正文；
3. 从服务器测试 DNS/TLS/443；
4. 确认没有误用文档域名；
5. 重新授权，不复用 code。

### 9.8 Secret/scope 错误

1. 检查 Secret 前后空格/换行；
2. AppID 与 Secret 必须同环境同应用；
3. Secret 只从服务端环境变量读取；
4. scope 是否获批；
5. 怀疑泄露立即轮换。

### 9.9 用户信息 status=false

1. token/openid/expires_time 原样传；
2. state 与授权 FID 一致；
3. 账号属于该 FID；
4. 多 FID 选择策略正确；
5. 接口版本（有角色/无角色）与权限一致。

### 9.10 用户信息解析失败

1. 只记录脱敏字段名和类型；
2. uid/roleId 的数字统一转字符串；
3. displayName 为空时回退；
4. role 为空默认学生；
5. 增加真实响应契约测试。

### 9.11 学生被识别为教师

1. 检查 app_metadata.app.role 来源；
2. 删除 roleName 模糊匹配；
3. 检查 CHAOXING_TEACHER_ROLE_IDS；
4. 检查 teacher_role_grants 的 fid+roleId；
5. 撤销受影响会话并重登。

### 9.12 教师无法进入

1. 从脱敏日志确认实际 roleId；
2. 检查环境变量分隔符/空格；
3. 授权表 active=true；
4. 授权记录 FID 一致；
5. 退出重登刷新 metadata。

### 9.13 本地用户重复

1. 检查 external_identity 唯一键；
2. openid/fid 做 trim 和类型统一；
3. 创建/绑定在事务内；
4. 唯一冲突后重新查询；
5. 不按姓名合并。

### 9.14 登录后又回到登录页

1. 检查 Set-Cookie；
2. HTTP 本地是否误开 Secure；
3. 检查 Domain/Path/SameSite；
4. 检查 X-Forwarded-Proto/Host；
5. 请求 /api/auth/me 区分 401 和前端路由错误。

### 9.15 Safari/学习通 WebView 丢 Cookie

1. 保持回调与业务 API 同源；
2. 避免跨站 Cookie；
3. 检查是否跳到系统浏览器；
4. 确认 SameSite=Lax、Secure、HTTPS；
5. 请平台确认应用打开方式。

### 9.16 Coze 仍使用旧回调

1. 区分预览/生产环境变量；
2. 确认部署对应最新 commit；
3. 重新部署；
4. 查看 302 Location；
5. 同步更新超星后台。

### 9.17 超星正常但 Supabase 失败

1. URL、anon key、service role key 属于同一项目；
2. 管理端可创建 Auth 用户；
3. migrations 已执行；
4. 虚拟邮箱唯一；
5. 错误应映射 session_failed，不误报机构问题。

### 9.18 退出后仍可访问

1. 确认调用 POST /api/auth/logout；
2. 服务端撤销会话；
3. 即使 provider token 过期也清本地 Cookie；
4. 检查页面缓存和中间件；
5. /api/auth/me 应返回 401。

### 10.1 Vue 3 前端

~~~vue
<script setup lang="ts">

const loading = ref(false);
const error = ref("");

function startLogin() {
  if (loading.value) return;
  loading.value = true;
  error.value = "";

    url.searchParams.set("next", "/student");
~~~

~~~java
@GetMapping("/api/auth/chaoxing")
public ResponseEntity<Void> start(
    @RequestParam(required = false) String fid,
    @RequestParam(defaultValue = "/") String next,
    HttpServletResponse response) {
  requireEnabled(props);
  String selectedFid = requireAllowedFid(fid, props.allowedFids());
  contexts.writeSignedCookie(response, requireSafeLocalPath(next), Duration.ofMinutes(10));
  URI target = UriComponentsBuilder
      .fromUriString("https://auth.chaoxing.com/connect/oauth2/authorize")
      .queryParam("appid", props.appId())
      .queryParam("redirect_uri", props.redirectUri())
      .queryParam("response_type", "code")
      .queryParam("scope", "snsapi_base")
      .queryParam("state", selectedFid)
      .build().encode().toUri();
  return ResponseEntity.status(HttpStatus.FOUND).location(target).build();
}

@GetMapping("/api/auth/callback/chaoxing")
public ResponseEntity<Void> callback(
    @RequestParam String code,
    @RequestParam(name = "state") String fid,
    HttpServletRequest request,
    HttpServletResponse response) {
  String safeFid = requireAllowedFid(fid, props.allowedFids());
  ChaoxingIdentity identity = chaoxing.resolve(requireCode(code), safeFid);
  LocalUser user = localUsers.bindOrCreateInTransaction(identity);
  sessions.createCookieSession(user, response);
  URI target = URI.create(contexts.readSafeNext(request).orElse("/"));
  contexts.clear(response);
  return ResponseEntity.status(HttpStatus.FOUND).location(target).build();
}
~~~

~~~java
public ChaoxingIdentity resolve(String code, String fid) {
  MultiValueMap<String, String> tokenForm = new LinkedMultiValueMap<>();
  tokenForm.add("appid", props.appId());
  tokenForm.add("secret", props.secret());
  tokenForm.add("code", code);
  tokenForm.add("grant_type", "authorization_code");

  TokenResponse token = webClient.post()
      .uri("https://auth.chaoxing.com/sns/oauth2/access_token/v1.0")
      .contentType(MediaType.APPLICATION_FORM_URLENCODED)
      .body(BodyInserters.fromFormData(tokenForm))
      .retrieve()
      .bodyToMono(TokenResponse.class)
      .timeout(Duration.ofSeconds(10))
      .block();
  requireValidToken(token);

  MultiValueMap<String, String> userForm = new LinkedMultiValueMap<>();
  userForm.add("access_token", token.accessToken());
  userForm.add("openid", token.openid());
  userForm.add("expires_time", token.expiresTime());
  userForm.add("state", fid);

  UserResponse user = webClient.post()
      .uri("https://v1.chaoxing.com/backSchool/user/getUserByTokenFormMooc")
      .contentType(MediaType.APPLICATION_FORM_URLENCODED)
      .body(BodyInserters.fromFormData(userForm))
      .retrieve()
      .bodyToMono(UserResponse.class)
      .timeout(Duration.ofSeconds(10))
      .block();
  return normalize(token.openid(), fid, user);
}
~~~

~~~ts
async function exchangeCodeOnce(code: string) {
  const response = await fetch(
    "https://auth.chaoxing.com/sns/oauth2/access_token/v1.0",
    {
      method: "POST",
      headers: { "content-type": "application/x-www-form-urlencoded" },

        appid: mustEnv("CHAOXING_APPID"),
        secret: mustEnv("CHAOXING_SECRET"),
        code,
        grant_type: "authorization_code"
~~~

## 14. 最终结论

超星身份验证必须采用“浏览器顶层授权跳转 → 服务端换 token → 服务端查询身份 → 本地会话”。前端不能保存超星 token，教师权限不能通过角色名称或前端参数判断，未知签名、接口和限流必须等待正式契约。

当前武汉大学生物化学文字实验智能体已经具备基础代码链路。后续开发者应复用第 6.1 节文件，只补齐正式配置、一次性 code 并发保护、真实 roleId 和端到端联调，不要另建平行登录体系。
