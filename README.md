## 教师病例资料工作室

教师端「病例草稿」（`/teacher/case-drafts`）现在使用中文表单，不需要填写 JSON、病例编号或版本号。

1. 选择病例文档（`.docx` 或 UTF-8 `.txt`，每份最大 10 MB），也可粘贴正文或直接填写。
2. 对照来源正文核对年龄、性别、主诉及五段临床资料；系统只按标题分段，不补造患者事实。
3. 核对脱敏情况，点击「检查资料」或「保存待审核草稿」。缺项可留空，不能将待审核当作医学审定。
4. 在「病例草稿」搜索、查看与补充；修改另存修订记录，原版本保留，保存重试不覆盖旧数据。

旧版 `.doc` 需在 Word 中另存为 `.docx`。当前不识别扫描件、图片或自动提取媒体；复杂版式未匹配的内容完整保留在来源正文中，需人工整理。草稿不进入学生训练；待审核到可训练病例的转换与发布仍需后续流程，当前不提供自动发布。

权限保持 `requireAuth('teacher')` AND 数据库 `app_is_teacher()`，学生与匿名无权读取/上传/保存。上传仅服务端提取纯文本，不渲染文档 HTML，不调用外部模型，不落公开文件目录。继续使用既有 `case_draft_imports` 和 RLS，无数据库迁移。技术契约、验收与部署说明见 [病例资料工作室](docs/CASE_STUDIO.md)。原资料缓存维护与既有病例上下架收纳在页末折叠区域。

## 登录身份字段来源与教师授权（2026-10-15）

- 超星登录可得字段上限（经官方接口契约与真实浏览器实证核对）：**姓名**（平台代理超星 OAuth 首建落库 `user_metadata.realname`）、**超星号**（`user_metadata.cxid`）、**头像**（按 `photo.chaoxing.com/p/{cxid}_80` 构造，真实加载已实证）。**手机号不可得**——超星 OAuth 与平台业务代理均不下发，界面不显示也不假造；**学号/工号**仅当应用自有超星 OAuth 服务端路径落地 `app_metadata.chaoxing.studentNo` 时可得，平台路径未下发时显示「学号未提供」，**不以超星号假填**。
- 双链身份信任语义（`src/lib/supabase-auth.ts`）：服务端身份（`app_metadata.chaoxing.*`，应用服务端写入，用户不可改）展示优先；用户资料（`user_metadata.*`，用户可经 `auth.updateUser` 自行改写）仅作展示兜底并标注来源（`nameSource`/`avatarSource`：server/user/none），**绝不作为可信身份或权限依据**。`user_metadata.cxid` 的可信绑定因此标记为外部阻塞（平台未提供不可改写的绑定证据）。
- profiles 身份同步：登录身份含可识别信息（超星号或非默认姓名）时，`/api/auth/me` 幂等调用 `sync_profile_identity` RPC（SECURITY DEFINER，仅本人行）写入 `display_name/student_no/chaoxing_uid`；教师端学情工作台/会话详情经 profiles join 展示姓名+头像+学号（缺失显示「未提供」），头像与超星号标注「用户提供」口径。
- 教师权限为应用/API/RLS 三层同源判定（`src/lib/request-auth.ts` `applyTeacherWhitelistGate`）：应用层以当前会话自身 token 调用既有 `app_is_teacher` RPC（读 `teacher_emails` 白名单，与 RLS 谓词同一函数）；邮箱所有权以服务端 `getUser()` 的 `email_confirmed_at` 为准；RPC 失败/无 token 一律不提升（fail-closed）；客户端传入的 email/uid/role 不参与判定。授权与撤销流程见 [教师权限受控管理说明](docs/teacher-access.md)（本轮未新增任何授权记录）。

## 教师单例上下架（发布状态）

教师在「病例草稿」页底部的「病例发布状态」面板可对教师病例目录的全部条目逐例上架/下架（`/api/teacher/case-publication`，双重授权同上）。目录有效性 = 存在于教师病例目录：`folder=null` 的 catalog-only 条目（缺少原始接诊资料）同样纳入管理，面板以「缺少原始接诊资料」徽章标记；未知 ID 拒绝（`CASE_NOT_FOUND`）。该放宽仅限发布管理，病例导入仍要求完整资料。

- 语义：无行 = 已发布（缺省开放）；下架写入 `case_publication.published=false`，是**可恢复停用**——不删除病例原文（`case_snapshot_*`）与历史训练记录/成绩；重新上架置 true 并保留行作审计痕迹（含操作时间与理由）。
- 生效范围：学生不能基于已下架病例新建训练（`CASE_UNPUBLISHED` 403），且该病例从学生目录（`/api/cases`）隐藏；教师不受限（可继续预览复核）；学生既有会话的恢复不受影响。病例资料的幂等初始化/导入不写本表，不会重置教师的下架决定。
- 验收脚本：`pnpm tsx scripts/verify-case53-init-publication.ts --teacher-cred-file ... --student-cred-file ...`（内容保真 53/53 + 上下架守卫闭环 10 项断言）。

### 跨平台工程复验（2026-10-26）

骨骼 manifest 通过 `.gitattributes` 固定 LF 以保持审计 SHA256。`pnpm validate` 中真实供应商语音链路需显式 `SPEECH_LIVE_TEST=1` 才执行，默认跳过并保留匿名门禁检查；跳过项不计为已验。详见 [语音验收边界](docs/SPEECH_INTEGRATION.md) 与 [骨骼审计](docs/anatomy-audit.md)。

病例版本现覆盖持久化的检查/查体媒体绑定与结果释放规则；换图、触发ID或释放阶段均换版，历史绑定不自动迁移。逐例证据与未验项见 [病例复核记录](docs/CASE_LIBRARY_REVIEW.md)。

本地原件准备链的人口学回归：`python -X utf8 -m unittest discover -s tests -p test_prepare_case_demographics.py`（需既有病例导入Python依赖），覆盖“患者/患儿/性别声明”及亲属误命中；不会读取真实病例或自动发布。

病例本地抽取现在将DOCX/PDF/PPTX内嵌图保存到忽略的`output/case-drafts/embedded-media/`，在草稿文档中登记来源哈希、定位及默认禁止绑定状态；不自动进入运行病例或公开目录。原件不变，隐私/用途核查后仍需显式受控绑定。先执行 `python -m pip install -r scripts/requirements-cases.txt`（含PDF图片提取必需的Pillow），再执行源准备与媒体回归：`python -X utf8 -m unittest discover -s tests -p "test_*case*.py"`。缺少Pillow时PDF文字提取可能正常而图片提取报错，不能把空候选当作原件无图；须检查草稿媒体错误并补依赖后重跑。

病例目录中的独立图片另登记为私有草稿`standaloneMediaCandidates`，保留每个相对定位、原图SHA/大小、实际解码结果及尺寸；损坏图片保留错误项，重复字节保留不同来源定位。它们不经过Word/PDF内嵌图计数，不能用内嵌图0张推断无图；不复制到公开目录、不自动推断检查类型或加入运行绑定，隐私、用途和实际显示仍需分别核验。

病例图片绑定与私有配置持久化见[CASE_MEDIA_BINDING.md](docs/CASE_MEDIA_BINDING.md)。上传前必须已有精确字节及用途/隐私/授权审核收据；带媒体配置的教师导入新增私有`binding_config`列前置检查，缺迁移不先写facts。检查/查体按操作释放、报告材料版本与事件关联、本地独立进程磁盘恢复已有工程验证；原图隐私/用途、真实存储与鉴权验收仍待，本地通过不代表可直接导入发布。
